# Task: Інтеграційне тестування — End-to-End сценарії

> **Статус:** Частково працює. Планується як фінальна верифікація після завершення всіх фаз.
> **Залежності:** Phase 3 (implemented), Phase 4 (in progress), CLI `generate` + `apply`, PostgREST/Supabase.
> **Ціль:** Підтвердити, що повний цикл "конфігуратор → metadata → DDL → PostgreSQL → runtime CRUD" працює end-to-end.

---

## Сценарій 1: PostgREST end-to-end

1. У конфігураторі (`apps/web`) створити:
   - Catalog `Products` з кількома атрибутами
   - Document `SalesOrder` з табличною частиною `Items`
   - Enumeration `OrderStatus`
   - AccumulationRegister `InventoryBalance` (залишковий)
2. Зберегти metadata на диск (перевірити, що forms записані serializer-ом у `forms/` підкаталозі об'єктів)
3. `pnpm simetra generate --input ./metadata --output ./output` → DDL-файли
4. Застосувати DDL на PostgreSQL + PostgREST
5. `pnpm dev:runtime` з `VITE_SIMETRA_DATA_PROVIDER=postgrest` → побачити sidebar з об'єктами by kind
6. Відкрити список Products → autogenerated list form
7. Створити новий Product → autogenerated item form
8. Зберегти → запис у БД
9. Відкрити SalesOrder → form з табличною частиною
10. Заповнити, зберегти, провести → posting functions executed
11. Перевірити: рухи з'явились у AccumulationRegister

### Критерії успіху

- [ ] Metadata зберігаються коректно (включно з forms)
- [ ] DDL генерується без помилок
- [ ] DDL застосовується на PostgreSQL без помилок
- [ ] Runtime відображає sidebar з усіма об'єктами
- [ ] CRUD операції працюють через PostgREST
- [ ] Posting/Unposting виконується через RPC
- [ ] Табличні частини рендеряться і зберігаються

## Сценарій 2: Mock provider end-to-end

1. `pnpm dev:runtime` з `VITE_SIMETRA_DATA_PROVIDER=mock` (default)
2. Відкрити список будь-якого об'єкта → порожній list
3. Створити запис → in-memory збереження
4. Перевірити, що форма рендерить усі поля відповідно до metadata
5. Перевірити, що ref-поля працюють з autocomplete (in-memory lookup)
6. Перевірити constants page

### Критерії успіху

- [ ] Runtime запускається без PostgreSQL
- [ ] CRUD працює через InMemoryDataProvider
- [ ] Autoform рендерить усі user-defined атрибути
- [ ] Стандартні реквізити показуються в header/summary зоні
- [ ] Ref-поля з autocomplete працюють
- [ ] Constants page показує і зберігає значення

---

## Сценарій 3: Configurator → Runtime round-trip

1. Створити metadata проєкт з різноманітними об'єктами в конфігураторі
2. Зберегти на диск
3. Відкрити в runtime (mock mode) — перевірити, що всі об'єкти доступні
4. Повернутися в конфігуратор, додати новий атрибут
5. Зберегти
6. Оновити runtime (F5) — перевірити, що новий атрибут з'явився у формі

### Критерії успіху

- [ ] Зміни в конфігураторі відображаються в runtime після перезавантаження
- [ ] Forms serialization/deserialization round-trip працює
- [ ] Новий атрибут автоматично з'являється в autoform
