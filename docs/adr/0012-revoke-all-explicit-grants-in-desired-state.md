# ADR-0012: Гранти й межа виконання — частина бажаного стану: `REVOKE ALL` за замовчуванням, явні гранти, ACL у каталожному гейті

Status: accepted 2026-09-26
Decided by: owner
Spec: [платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р14), §6.7

## Context

Провайдери баз налаштовують типові привілеї так, щоб нові об'єкти були
доступні ролям API без явних грантів. Якщо платформа покладається на ці
неявні дефолти, межа виконання залежить від налаштувань провайдера й дрейфує
непомітно.

## Decision

- Дефолт — `REVOKE ALL`: схема, таблиці й функції не мають жодних прав, поки їх
  не видано явно (Р14).
- Типові привілеї провайдера (`ALTER DEFAULT PRIVILEGES`) фіксуються в
  бажаному стані, а не успадковуються мовчки.
- Кожен `GRANT` і кожен `EXECUTE` явні й виводяться з виду та скоупу; об'єкти,
  які створює план, отримують права бажаного стану явними кроками.
- Каталожний гейт порівнює й ACL, а не лише структуру.
- ACL таблиці виду належить платформі: дослівний `GRANT` чи `REVOKE` на неї —
  помилка компілятора.

## Why

- Неявні дефолти провайдера — не контракт (урок simplyCMS, Р14): те, що не
  записане в бажаному стані, не можна ні перевірити, ні відтворити на іншому
  провайдері.
- Гранти в бажаному стані потрапляють у ту саму перевірку дрейфу, що й решта
  каталогу
  ([платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §6.7).

## Rejected

- Покладатися на типові привілеї провайдера — межа виконання стає залежною від
  його налаштувань.
- Дозволити дослівні `GRANT`/`REVOKE` у SQL модулів на таблиці видів — ACL
  розійшовся б із виводом з метаданих.

## Consequences

Легше: межу виконання видно у плані й гейті, а нова роль нічого не отримує
мовчки. Важче: кожна нова функція чи таблиця потребує явних грантів; забутий
`EXECUTE` дає `permission denied`, а не тихий обхід. Не «виправляти»:
відмова при забутому гранті — навмисна.
