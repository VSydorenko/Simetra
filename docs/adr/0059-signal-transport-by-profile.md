# ADR-0059: Сигнал — один формат без даних; транспорт за профілем: realtime.send у supabase, outbox і Centrifugo у postgres

Status: superseded by ADR-0083
Decided by: owner
Spec: [спека профілів провайдера](../superpowers/specs/2026-10-23-provider-profiles-design.md) §2 (ПП3); [платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р31)

## Context

Клієнт має оновлювати дані без опитування, а сигнал про зміну — бути транзакційним: відкат команди прибирає й сигнал. Профіль `supabase` вже мав вбудований Realtime, профіль `postgres` (ADR-0057) його не має.

## Decision

- Формат сигналу один для обох профілів: вид, ключі, версія; без даних. Дані перечитуються через адаптер джерела (Р31, ПП3).
- Транспорт за профілем. `supabase` — `realtime.send` з команди й політики приватних каналів на `realtime.messages`. `postgres` — рядок у outbox у транзакції команди, ретранслятор `LISTEN/NOTIFY`, сервер сигналів (перший адаптер — Centrifugo, інстанс на застосунок); канал — скоуп; підписку авторизує сервер токеном каналу за функцією множини скоупу.
- Для прийнятих таблиць, ще не переведених на команди, — тригер рівня оператора, що пише в outbox.

## Why

- Outbox робить сигнал транзакційним: відкат прибирає сигнал.
- Доставка «щонайменше раз» безпечна, бо сигнал ідемпотентний.
- Авторизація даних лишається в одному місці — у джерелі читання.

## Rejected

- Окремих відхилених варіантів початкове рішення не фіксує; принцип — авторизація даних лише в джерелі читання, тому дані в сигнал не кладуться.

## Consequences

Рішення замінено ADR-0083: один транспорт (outbox і Centrifugo) в обох профілях, Supabase Realtime не використовується. Формат сигналу без даних і правило «коректність не залежить від доставки» зберігаються. Текст цього ADR лишається як запис початкового рішення.
