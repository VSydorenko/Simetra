# ADR-0006: Джерело колекції — адаптер; типове — PostgREST + RLS

Status: superseded by ADR-0058
Decided by: owner
Spec: [платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р8), §8.2

## Context

Рушій колекцій не повинен залежати від того, звідки приходять дані. У першій
редакції платформа орієнтувалася на Supabase: браузер ходить до PostgREST
напряму під RLS. Водночас потрібні зовнішні джерела й self-host, де прямого
PostgREST немає.

## Decision

Джерело даних колекції — адаптер (Р8). Типовий адаптер — PostgREST + RLS:
браузер читає напряму, realtime іде через broadcast-тригери. Server Function —
адаптер для зовнішніх джерел і self-host. Сутність обирає адаптер у метаданих.

## Why

- Рушій колекцій уже не залежить від джерела: контракт адаптера охоплює
  читання списку, пошук, вікна, фільтри й сортування та мапінг логічних імен
  на колонки.
- Прямий PostgREST дешевий і дає realtime: браузер не проходить через власний
  сервер, а права тримає RLS.

## Rejected

- У спеці для цього рядка відхилених варіантів не зафіксовано; Server Function
  лишилась другою реалізацією контракту адаптера.

## Consequences

Адаптер лишається точкою розширення, але «типове — PostgREST» виявилося
привʼязаним до одного провайдера: на профілі без PostgREST воно не діє. Тому
рішення замінено ADR-0058, який робить типове джерело залежним від профілю
провайдера. Збережений тут принцип «джерело — адаптер» не змінився.
