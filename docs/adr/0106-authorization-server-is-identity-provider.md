# ADR-0106: сервер авторизації агента — провайдер ідентичності профілю; MCP застосунку — сервер ресурсу; токен перевіряється інтроспекцією

Status: accepted 2026-11-24
Decided by: architect
Spec: [П4-F](../superpowers/specs/2026-11-24-p4-f-agents-design.md) §5.4

## Context

Специфікація MCP (ревізія 2026-07-28, https://modelcontextprotocol.io/specification/latest/basic/authorization) вимагає від MCP-сервера ролі сервера ресурсу OAuth 2.1: метадані RFC 9728, перевірка, що токен виданий саме для цього сервера (RFC 8707), відмова іншим токенам. Реєстрація клієнта: Client ID Metadata Documents (CIMD) — SHOULD, динамічна реєстрація (DCR) — MAY і застаріла. У профілі `postgres` ідентичність дає Better Auth у host-і (спека профілю `postgres` §4). Для лінії `better-auth` 1.7 є `@better-auth/mcp` і `@better-auth/cimd` (MIT, peer `better-auth ^1.7.12`): сервер авторизації в тому самому host-і, PRM, прив'язка токена до ресурсу, інтроспекція, яка відкидає токен закінченої чи видаленої сесії. Сервер OAuth 2.1 Supabase Auth — публічна бета; його токен має `aud: "authenticated"` для всіх токенів, прив'язки до ресурсу документація не описує.

## Decision

- Сервер авторизації — провайдер ідентичності профілю; платформа власного сервера авторизації не пише.
- Профіль `postgres`: Better Auth у host-і з `@better-auth/mcp` і `@better-auth/cimd`; реєстрація клієнта — CIMD; DCR вимкнена.
- MCP-вхід застосунку — сервер ресурсу: публікує PRM, приймає лише токен, виданий для свого ресурсу.
- Токен доступу агента непрозорий (`disableJwtPlugin: true`, без плагіна `jwt()`): у `@better-auth/oauth-provider@1.7.12` токен із аудиторією за увімкненого JWT стає JWT, а JWT не відкликається на сервері. Вхід перевіряє токен інтроспекцією на кожен запит, тож відкликання діє одразу.
- Ідентичність клієнта з токена (`client_id`, інакше `azp`) стає `act.sub`; з CIMD це HTTPS-адреса документа клієнта.
- Профіль `supabase`: вхід агентів відмовляє з діагностикою, доки провайдер не дасть прив'язки токена до ресурсу.

## Why

- Один host обслуговує вхід людини й агента; дублювати провайдера ідентичності — другий механізм.
- `sessionClaimsSchema` уже приймає `act` (`packages/simetra/src/model/runtime/session.ts`); `createDataHandler`, `CommandRuntime.run` і `read` уже приймають `SessionClaims`.
- Локальна перевірка JWT не бачить відкликання до кінця строку токена (типово 1 год у `@better-auth/oauth-provider@1.7.12`); вхід агента пише дані.
- Відкрита DCR дає будь-кому зареєструвати клієнта; CIMD дає стабільну ідентичність клієнта для журналу й стелі.

## Rejected

- Власний сервер авторизації платформи — дублює провайдера ідентичності.
- JWT з локальною перевіркою — відкликання запізнюється на строк токена.
- DCR — застаріла в MCP і небезпечна відкритою.
- Профіль `supabase` у першому випуску — без прив'язки до ресурсу не виконує MUST специфікації MCP.

## Consequences

Кожен виклик агента — один запит інтроспекції до таблиць Better Auth тієї самої бази. Плагін додає таблиці Better Auth (клієнти, токени, згоди) у схему `better_auth`. Оновлення `better-auth` іде лінією разом із плагінами (lockstep-версії).
