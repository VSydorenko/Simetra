# ADR-0105: один токен агента — один тенант

Status: accepted 2026-11-24
Decided by: owner
Spec: [П4-F](../superpowers/specs/2026-11-24-p4-f-agents-design.md) §5.1, §5.5

## Context

Користувач може бути учасником кількох значень скоупу верхнього рівня (тенантів). Закріплення act-as на скоупі вже ухвалено як необов'язковий claim (Рх22, ADR-0055). Відкрито, чи закріплення завжди діє для ШІ-клієнта і хто обирає тенант.

## Decision

- У застосунку з видами скоупу токен ШІ-клієнта завжди закріплений за одним значенням скоупу верхнього рівня. Користувач обирає його на екрані згоди. Для іншого тенанта — окреме підключення.
- Застосунок без видів скоупу вибору не показує і claim закріплення не ставить.
- Закріплення — claim токена, який перетинається з функціями множини й членства на кожен запит; це не довіра до вибору на екрані.

## Why

- Закріплення — вимога першого споживача (ADR-0055).
- Помилка агента не виходить за межі одного тенанта.
- Одне правило без варіантів просто перевірити.

## Rejected

- «Усі мої тенанти» на вибір користувача — агент ризикує всіма тенантами.
- Обов'язковість закріплення як рішення проєкту в метаданих — варіанти без потреби.

## Consequences

Користувач кількох тенантів підключає клієнта кілька разів. Закріплення за тенантом, де користувач уже не учасник, нічого не відкриває: перетин порожній.
