# ADR-0055: Act-as: права ефективного користувача, стеля агента опційна, закріплення скоупу в токені

Status: accepted 2026-10-17
Decided by: owner
Spec: [спека прав](../superpowers/specs/2026-10-17-rights-design.md) §2 (Рх12, Рх22)

## Context

Агент діє від імені користувача, а токен агента не повинен розкривати більше, ніж потрібно. Перший споживач не потребує звуження прав агента, але інші застосунки можуть його потребувати; токен, виданий для одного тенанта, не має відкривати перелік інших.

## Decision

- При act-as діють права ефективного користувача (`sub`); враховується лише верхній `act` (Рх12).
- Стеля агента — необов'язковий механізм проєкту. Без оголошення агент має права користувача (Рх12).
- Якщо стеля оголошена, вона — окремий предикат, AND з правами користувача: `RESTRICTIVE`-політики `<t>_agent` (`act` відсутній або предикат стелі) і та сама умова в перевірці права ядра. `fullAccess` її не обходить (Рх12).
- Необов'язковий claim закріплення скоупу в токені act-as перетинає всі функції множини, зокрема членства: токен, виданий для одного тенанта, не бачить інших (Рх22).

## Why

- Без звуження — рішення власника для першого споживача; інші застосунки отримують механізм без перебудови (Рх12).
- Закріплення скоупу — вимога першого споживача: токен act-as одного тенанта не розкриває перелік інших (Рх22).

## Rejected

- Обов'язкова стеля агента — зайве для застосунків, яким не потрібне звуження (Рх12).
- Обхід стелі через `fullAccess` — зробив би стелю необов'язковою для найпривілейованішого (Рх12).

## Consequences

Реалізація стелі й закріплення належить частині П4 про агентів; до неї claim `act` лише передається. Стелю не слід вшивати в базові функції прав: вона — окремий шар, який вмикає проєкт.
