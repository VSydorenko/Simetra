# ADR-0024: Команда — це транзакція платформи на прямому з'єднанні, а PostgREST лише читає

Status: accepted 2026-10-01
Decided by: owner
Spec: [платформа в Postgres](../superpowers/specs/2026-10-01-platform-in-postgres-design.md) §2 (Р21), §3; [платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р21), §6.7

## Context

PostgREST дає одну транзакцію на запит. Команда з кількох кроків (нумерація, рухи, підсумки, `saveAndPost`) тому була б атомарною лише як рукописна RPC-функція. У першого споживача саме звідси неатомарні багаторядкові записи, два виклики на «зберегти й провести» і `SECURITY DEFINER`-функції з `EXECUTE` для `authenticated`, які браузер викликає повз серверну функцію. Платформі потрібен один шлях запису з тим самим контрактом RLS, що й у читання.

## Decision

Кожен запис проходить через єдиний вхід ярусу T3 `runCommand`: з'єднання з пулу, `BEGIN`, `set_config('request.jwt.claims', …, true)` з claims користувача, `SET LOCAL ROLE simetra_command`, TS-хуки «до», згенероване SQL-ядро, TS-хуки «після», `COMMIT`, побічні ефекти через outbox. PostgREST лишається лише для читання браузера й реалтайму (Р8). Запис у таблиці через API закрито грантами: ролі API (`authenticated`, `anon`) не мають `EXECUTE` на функції запису й оболонки проведення. Ролі БД: `simetra_runtime` (`LOGIN`, `NOINHERIT`, без грантів, лише з'єднання), `simetra_command` (`NOLOGIN`; DML за видом і `EXECUTE` на згенеровані функції), `authenticated` (`SELECT` і віртуальні таблиці). Вкладений `runCommand` — помилка; «голий» пул поза T3 — порушення лінт-зони з негативним тестом.

## Why

- Пряма транзакція з claims у `set_config` дає той самий контракт RLS, що й PostgREST, і одну реалізацію гардів для обох дверей ([спека](../superpowers/specs/2026-10-01-platform-in-postgres-design.md) §2, Р21).
- Діру закрито структурно, грантами, а не гардом: у `authenticated` немає `EXECUTE` на функції запису.
- Це модель 1С — платформа тримає транзакцію, обробники застосунку всередині — але без її монопольності: `psql`, імпорт і міграції лишаються можливими (див. ADR-0026).
- `simetra_runtime` без привілеїв і без успадкування: забутий `SET LOCAL ROLE` дає `permission denied`, а не тихий обхід ([спека](../superpowers/specs/2026-10-01-platform-in-postgres-design.md) §3).

## Rejected

- Запис через PostgREST/RPC — одна транзакція на запит, неатомарні багатокрокові команди, `SECURITY DEFINER`-функції, видимі браузеру.
- Роль входу з привілеями замість `NOINHERIT` без грантів — забутий `SET LOCAL ROLE` став би тихим обходом.

## Consequences

Легше: одна атомарна одиниця запису для команди, нумерації, рухів і підсумків; гарантія «запис лише командою» тримається грантами. Важче: пулер у режимі транзакцій — без стану сесії й без іменованих prepared statements, claims і роль — лише `LOCAL`. Не «виправляти»: відсутність `EXECUTE` у ролей API на функції запису навмисна. Названі винятки із запису лише командами (тригер провізії на таблиці провайдера, підписки на таблицях провайдера) — ADR-0047.
