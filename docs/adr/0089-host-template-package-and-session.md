# ADR-0089: шаблон host-а — пакет `create-simetra-app`; справжня dev-сесія; клієнт і SSR — різні транспорти; межі тіла на серверному entry

Status: accepted 2026-11-08
Decided by: architect
Spec: [П4-D](../superpowers/specs/2026-11-08-p4-d-hosts-design.md) §2 (Дх2–Дх4, Дх7–Дх9)

## Context

Шаблон host-а — застосунок TanStack Start, який споживач копіює. Він мусить
мати працездатну сесію для розробки, не мати шляху обходу автентифікації в
production-збірці й не нести тестове керування оракула. SSR-запит не повинен
ставати HTTP-ендпоінтом, а межа тіла запиту має діяти незалежно від шляху.

## Decision

- Шаблон — пакет `create-simetra-app`, поки приватний; усередині
  `template/` — окремий пакет воркспейсу, який збирається й тестується у
  воркспейсі. Тестовий хост (пакет `test-host`) лишається полігоном
  оракула з фейковим рантаймом; код шаблону від нього не залежить (Дх2).
- Профіль зрізу — лише `postgres`, сесія — Better Auth; адаптер `verifySession`
  у шаблоні (Дх3).
- Dev-сесія — та сама справжня сесія Better Auth: реєстрацію в застосунку
  вимкнено (`emailAndPassword.disableSignUp: true`); скрипт `dev:user` поза
  `src/` має власний екземпляр з дозволеною реєстрацією і заводить
  користувача на стеку розробки. Другого адаптера, dev-маршруту чи dev-cookie
  немає; production-збірка не містить скрипта — це тест (Дх4).
- Два шляхи транспорту, розділені будовою: клієнт шле конверт через одну
  Server Function даних (`dataFn`); SSR кличе обробник з `{ inProcess: true }`
  через `ssrTransport`, обгорнуту `createServerOnlyFn`, а не `createServerFn`
  (Дх7).
- Межу тіла й заголовки ставить серверний entry `src/server.ts`: тіло
  не-`GET`/`HEAD` понад межу відмовлено до розбору; `Content-Encoding`, відмінний
  від `identity`, — відмова; неасетні відповіді — `Cache-Control: no-store`,
  HTML — `private, no-store` і `Vary: Cookie` (Дх8).
- Оракул лишається в пакеті `test-host` (`test-host/oracle`); e2e шаблону
  лежать у каталозі `e2e/` пакета `create-simetra-app`; `template/` не залежить від
  `test-host`; інструментування підставляє e2e-конфіг Vite аліасом `#instrument`
  (Дх9).

## Why

- Гілка ідентичності «лише для розробки» — шлях обходу в production; відкрита
  реєстрація дала б будь-кому в інтернеті користувача з `current_user_id() ≠ NULL`;
  `disableSignUp` діє й на серверний виклик `signUpEmail`, тож дозвіл
  реєстрації живе лише в скрипті (Дх4).
- `createServerFn` у SSR-шляху став би RPC-ендпоінтом `/_serverFn/<id>`, і
  `inProcess` дістав би HTTP-запит; з двома шляхами `inProcess` неможливий на
  HTTP-шляху за побудовою (Дх7).
- Лише entry бачить сирий потік до розбору JSON; межа не спирається на
  приватну базу шляху Start і закриває маршрути Better Auth; стиснене тіло
  обійшло б лічильник (Дх8).
- Тестове керування (`ORACLE_CONTROL_TOKEN`, мутації самотесту) не мусить
  потрапити в застосунок споживача; копія правил у двох місцях розійшлася б;
  новий пакет вимагав би рішення власника (Дх9, Дх2).

## Rejected

- Dev-cookie, dev-маршрут чи другий `verifySession` — обхід автентифікації в production.
- Відкрита реєстрація в застосунку — будь-хто отримує користувача.
- `createServerFn` для SSR-транспорту — RPC-ендпоінт з HTTP-запитом.
- Межа тіла в шарі маршруту — не бачить сирий потік, не покриває маршрути Better Auth.
- Оракул у шаблоні чи новий пакет оракула — тестове керування в застосунку або без рішення власника.

## Consequences

Дерево `template/` і його `package.json` не містять посилань на `test-host`,
`frame-oracle` і `simetra/*/testing` — це тест. Не «виправляти»: dev-вхід через
звичайну форму, а не «швидкий» обхід. Копіювальник CLI й публікація — мінімальна
доставка. Хост розміщується з ADR-0074 (заголовки) і ADR-0086 (оракул).
