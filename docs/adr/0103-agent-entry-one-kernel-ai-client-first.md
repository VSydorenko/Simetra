# ADR-0103: вхід агентів — одне ядро, перший вхід — власний ШІ-клієнт користувача через віддалений MCP

Status: accepted 2026-11-24
Decided by: owner
Spec: [П4-F](../superpowers/specs/2026-11-24-p4-f-agents-design.md) §1, §3

## Context

Права агента вже ухвалено: агент діє з правами користувача (`sub`), враховується лише верхній `act`, стеля агента й закріплення скоупу необов'язкові (ADR-0055). MCP над даними є лише для бази розробника (ADR-0069). Відкрито, хто такий агент у продукті: власний ШІ-клієнт користувача (Claude, ChatGPT), що підключається до застосунку ззовні, чи агент, якого запускає сам застосунок. Від відповіді залежать транспорт і видача токена.

## Decision

- Ядро агента одне: перевірка токена агента в claims `{ sub, act }`, закріплення скоупу, стеля агента, каталог інструментів агента, `act` у журналі прав.
- Перший вхід — власний ШІ-клієнт користувача: застосунок — віддалений MCP-сервер, вхід — OAuth 2.1 за специфікацією MCP.
- Агент, вбудований у застосунок, — пізніший вхід над тим самим ядром; другого механізму прав чи журналу він не отримує.

## Why

- Застосунок на Simetra отримує агентів без власної ШІ-частини.
- Один механізм прав і журналу для обох входів; вбудований агент додається без перебудови.

## Rejected

- Спершу вбудований агент — кожен застосунок пише ШІ-частину сам.
- Лише один із входів назавжди — другий вхід тоді потребує іншого механізму.

## Consequences

Застосунок отримує сервер авторизації OAuth (ADR-0106) і стандартні екрани входу й згоди. Вбудований агент пізніше бере той самий каталог і ту саму перевірку claims; не «спрощувати» його окремим шляхом у базу.
