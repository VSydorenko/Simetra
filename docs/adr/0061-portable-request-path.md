# ADR-0061: Переносний шлях запиту: контейнер (nitro) і Vercel обов'язкові, Cloudflare Workers — пізніше; без I/O при завантаженні модуля

Status: accepted 2026-10-23
Decided by: owner
Spec: [спека профілів провайдера](../superpowers/specs/2026-10-23-provider-profiles-design.md) §2 (ПП7); [платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р33); [спека П4](../superpowers/specs/2026-10-26-p4-runtime-design.md) §5 (Рт17); [звіт спайку П0 (а)](../superpowers/specs/2026-11-04-p0-a-host-report.md)

## Context

Серверний шлях (SSR, Server Functions, `runCommand`, читання) мусить працювати там, де його розгорне споживач. Serverless-платформа може зупинити інстанс після відповіді, а Workers забороняє I/O в глобальній області й не має звичайної файлової системи. Першому споживачу потрібен контейнер.

## Decision

- Обов'язкові цілі host-а — контейнер (nitro `node-server`, еталонна ціль) і Vercel (Fluid compute). Cloudflare Workers — пізніша ціль, яку контракт T3 не закриває (Р33, ПП7, Рт17).
- T3 не виконує I/O під час завантаження модуля, не читає файлів і змінних середовища. Каталог рантайму host передає об'єктом; `createCommandRuntime` можна викликати в обробнику запиту.
- Порт `CommandDatabase` не припускає пулу на рівні модуля, тож адаптер «з'єднання на команду» додається без зміни порту.
- Дії `afterCommit` T3 передає функції `defer`, яку дає host (`waitUntil` платформи); без `defer` `run` повертає результат після цих дій.
- Довгоживучі процеси (сервер сигналів, `LISTEN`, планувальник) — окремі сервіси. `runCommand` сумісний із пулером у transaction-режимі.

## Why

- Непередана дія після відповіді губиться, коли платформа зупиняє інстанс (Рт17, ПП7).
- Vercel повторно використовує інстанс, тож пул на рівні модуля там штатний (Рт17).
- Спайк П0 (а): транзакція команди пройшла на `node-server` і на виході пресета Vercel, напряму й через пулер; у preview Vercel `waitUntil` виконав дію після відповіді (звіт спайку, таблиця критеріїв).

## Rejected

- Прив'язка до одного host-а — звужує споживачів.
- Cloudflare Workers у першій віхі — вимагає з'єднання на команду й заборони I/O на старті; відкладено.
- Пул на рівні модуля як вимога контракту — несумісний із Workers.

## Consequences

Код T3 не має I/O при імпорті, і це не слід «спрощувати» глобальним пулом чи читанням середовища на верхньому рівні. Підтримка Workers потребує нового адаптера порту, а не зміни контракту.
