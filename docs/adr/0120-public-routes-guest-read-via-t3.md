# ADR-0120: публічні маршрути — гість читає на сервері через T3 із синтетичними claims гостя, без T4, без знімка в HTML і без сигналів

Status: accepted 2026-11-25
Decided by: architect
Spec: [публічна частина застосунку](../superpowers/specs/2026-11-25-public-app-part-design.md) §5.3

## Context

Корінь маршрутів шаблону веде на вхід кожен шлях поза `PUBLIC_PATHS`, коли сесії немає (`template/src/routes/__root.tsx`). Без сесії рантайму даних немає (`establishServerSession` у `template/src/host-session.ts`), а транспорт T4 `dataFn` (`template/src/server/data-fn.ts`) завжди проходить `guardRequest` (`template/src/server/request-guard.ts`), що відмовляє запиту без claims чи з анонімною сесією. Дх11 спеки П4-D прирівнює анонімну сесію до відсутності сесії на маршрутах з даними; плагін `anonymous` Better Auth увімкнено лише заради колонки й тригера провізії, а `/sign-in/anonymous` вимкнено (`authOptions`). T3 гостю не відмовляє: `sessionKind` у `packages/simetra/src/server/runtime.ts` розпізнає анонімні claims, а `readRoleFor` обирає роль запиту гостя (`simetra_anon` у профілі `postgres`). `sessionClaimsSchema` (`model/runtime/session.ts`) вимагає непорожній `sub`. Знімок T4 у HTML (`dehydrate` у `template/src/router.tsx`) несе `subject`, версію прав і час видачі.

## Decision

1. Застосунок оголошує публічний маршрут у декларації маршруту (`staticData`). Редирект на вхід — за декларацією, а не за переліком шляхів. Публічні маршрути мають окремий макет без адмінної навігації.
2. Гостьове читання — серверна функція host-а над `CommandRuntime.read` і `readParts`. Без сесії вона передає синтетичні claims гостя: сталий `sub` і `is_anonymous: true`; роль обирає `readRoleFor`. З дійсною сесією користувача — claims цієї сесії.
3. `dataFn` і `guardRequest` не змінюються. Анонімний вхід Better Auth лишається вимкненим.
4. Публічний маршрут не кладе в HTML знімка T4 і не створює рантайму даних. Сигналів для гостя немає.
5. Серверна функція повертає результат `read`: він уже логічний (`server/read.ts` → `decodeReadRow` → `decodeRow` у `server/decode.ts`, той самий T0-декодер, що й у клієнта). На межі серверної функції за потреби — пара `readResultToWire` (`server/data-handler.ts`) і `readResultFromWire` (`model/runtime/mapping.ts`); `data/**` не змінюється.
6. Дх11 П4-D діє далі для маршрутів без декларації.

## Why

- T3 уже вміє гостя: роль запиту, порожній знімок прав, відмова каналів. Новий шлях — лише серверна функція host-а, а межу тримає RLS ролі гостя.
- Синтетичні claims не плодять рядків `better_auth.user` на кожного відвідувача і не відкривають endpoint анонімного входу.
- Знімок T4 несе тотожність сесії (ADR-0074), тож у спільний кеш він не може потрапити; без T4 немає й питання сигналів для гостя.
- Один декодер — одна форма значень у клієнта, сервера й гостьової сторінки.

## Rejected

- Анонімні сесії Better Auth для гостя — рядок облікового запису на відвідувача, cookie у відповіді, endpoint без потреби.
- Рантайм T4 для гостя — сховище й гідратація без сесії, знімок з тотожністю в спільному кеші, сигнали для `anon`.
- Пропустити гостя через `dataFn` — послабило б спільну перевірку сесії T4 і токенів сигналів.
- Копія декодера в host-і — друга форма значень.

## Consequences

- Публічна сторінка не оновлюється в реальному часі; свіжість дає кеш (ADR-0121).
- Працівник на публічному маршруті читає під своїми правами, без T4; відповідь із сесією не кешується спільно.
- Гостьовий T4 і сигнали для `anon` — окреме рішення, якщо знадобляться.
