# ADR-0030: Інструменти розробника — окремий пакет `@simetrajs/designer` з режимами, скіли споживача через `simetra init`

Status: accepted 2026-10-02
Decided by: owner
Spec: [designer](../superpowers/specs/2026-10-02-simetra-designer-design.md) §2 (Д1–Д4), §4; [платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р12)

## Context

Платформа мала пакет інструментів з назвою за транспортом (`@simetra/cli`) і скіл споживача серед скілів репо (`simetra-cli`). Назва описує транспорт, а не інструмент, а скіл для споживача в репо платформи не потрібен і заважає агентам, що розвивають саму платформу. Simetra — інструмент, яким користуються в іншому проєкті; розробник і його агент працюють з одним набором над текою `metadata/`, а спосіб виклику — лише режим.

## Decision

- Інструменти розробника — окремий пакет від рантайм-пакета `simetra` (Д1). Ім'я пакета — `@simetrajs/designer`, бінарник — `simetra`; простір npm — `@simetrajs`, назад на `@simetra` пакети не повертаються (Д2).
- Один каталог інструментів — єдине джерело правди; командний рядок, MCP і студія — тонкі режими над ним. Студія — режим `simetra studio`, а не окремий пакет (Д3, Р12). Окремих пакетів за транспортом немає.
- Скіли споживача їдуть у пакеті тієї ж версії й потрапляють у проєкт симлінками через явну ідемпотентну команду `simetra init`; `postinstall` немає (Д4).
- Репо платформи тримає лише скіли для розробки самої платформи.

## Why

- Залежності інструментів (CLI-фреймворк, MCP SDK, двигун схеми, студія) не потрапляють у залежності застосунку; так само розділено `prisma` і `@prisma/client` ([designer](../superpowers/specs/2026-10-02-simetra-designer-design.md) §2, Д1).
- Окремий пакет виправданий власним життєвим циклом — інструмент розробника, а не код застосунку (платформна спека §3.2, Р13).
- `@simetra` належить сторонньому акаунту; ім'я `designer` — за аналогією з Конфігуратором 1С: одне ядро, кілька режимів (Д2).
- Студія — ще один адаптер над тим самим каталогом (Д3).
- Без `postinstall`: pnpm 10+ блокує скрипти залежностей, а запис у проєкт має бути свідомою дією людини; симлінки дають автодискавері агентів і версію скіла, що збігається з версією пакета (Д4).
- npm-пакет у проєкті, а не плагін хоста: версія інструментів у lockfile проєкту збігається з рантаймом, є командний рядок і CI без агента, працює в будь-якому хості ([designer](../superpowers/specs/2026-10-02-simetra-designer-design.md) §4.3).

## Rejected

- Пакети `@simetra/cli`, `@simetra/mcp` за транспортом — назва вводить агентів в оману; простір `@simetra` чужий.
- Студія як окремий пакет `@simetra/studio` — зайвий життєвий цикл для ще одного адаптера.
- Розширення VS Code чи десктоп (Tauri, Electron) як основна форма студії — прив'язка до однієї екосистеми або найдорожча підтримка інсталяторів; VS Code лише як тонка оболонка пізніше.
- `postinstall` і автодискавері без `init` — pnpm 10+ блокує скрипти, запис у проєкт має бути свідомим.
- Чистий плагін хоста замість npm-пакета — глобальна версія, немає командного рядка без агента.

## Consequences

Легше: рантайм-пакет без залежностей інструментів; один канал версій; скіли тієї ж версії, що й інструменти. Важче: симлінки ламкі (Windows, ручне видалення), тому є `init --check`. Не «виправляти»: адаптер, що обчислює щось сам поза каталогом, — дефект; окремі пакети за транспортом не повертати.
