# ADR-0001: Платформа — окреме публічне репо з npm-пакетами в lockstep; один флагманський пакет з ярусами

Status: accepted 2026-09-24
Decided by: owner
Spec: [платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р1, Р13), §3.1, §3.2

## Context

Simetra мусить обслуговувати будь-який бізнес-застосунок, а не лише перший
споживач. Потрібна межа, яку неможливо порушити «по дорозі»: платформа окремо,
застосунок окремо. Досвід сусіднього репо simplyCMS показав, що надмірна
роздробленість на пакети болісна й закінчується консолідацією.

## Decision

- Платформа живе в окремому публічному репо (Apache-2.0) і постачається
  пакетами з npm (Р1). Застосунок-споживач ставить їх як звичайні залежності.
- Версія спільна для всіх пакетів (lockstep).
- Один флагманський пакет `simetra` з ярусами-теками T0…T6 під лінт-зонами
  (Р13). Окремий пакет існує лише для одиниці з власним життєвим циклом
  (інструменти `@simetrajs/designer`, шаблон host `create-simetra-app`).
- Режими інструментів (командний рядок, MCP, студія) не є окремими пакетами.

## Why

- Пакетна межа — найсильніша межа платформа/застосунок: споживач не може
  залізти у внутрішності, а платформа не знає споживача
  ([платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2, Р1).
- Ярус у теці під лінт-зоною дає ту саму межу «імпорт лише вниз» без вартості
  окремих пакетів: версіонування, публікація й крос-пакетні залежності
  множаться на кожен пакет (§3.1).
- Окремий пакет виправданий лише там, де інші залежності чи інший цикл
  релізів: інструменти не мають тягти `pg` у залежності рантайму (§3.2).

## Rejected

- Git-субмодуль платформи в застосунку — вкладені workspace-и, забутий bump,
  приватні субмодулі на хостингах.
- Vercel Microfrontends і Module Federation — повне перезавантаження між
  зонами, жодного прецеденту з TanStack Start.
- Десяток дрібних пакетів з першого дня — досвід simplyCMS: консолідація
  після болісної роздробленості.

## Consequences

Легше: одна версія для всієї платформи, один журнал змін, межа ярусів тримається
лінтом із негативним тестом. Важче: ярус не можна винести в окремий пакет без
нової причини (власний життєвий цикл). Не «виправляти»: відсутність кореневого
експорту `simetra` — споживач імпортує конкретний ярус, щоб імпорт називав
ярус, від якого залежить.
