# ADR-0045: Схема `simetra` тримає лише стан і механізми платформи

Status: accepted 2026-10-07
Decided by: owner
Spec: [системна схема й користувачі](../superpowers/specs/2026-10-07-system-schema-users-design.md) §1, §2 (С1), §3

## Context

Платформа розкладала власні таблиці й функції «десь» (marker і ledger застосованої конфігурації, лічильники нумерації, довідник міток виду, outbox, журнал DDL, функції сесії). Дані застосунку, зокрема користувачі й учасники тенантів, мають жити окремо як об'єкти метамоделі з RLS. Так само поділено в провайдерів автентифікації: закрита системна частина окремо від профілю, яким володіє застосунок.

## Decision

Схема `simetra` тримає лише стан і механізми платформи: marker і ledger застосованої конфігурації, `identities`, довідник міток виду `kind_labels`, лічильники нумерації, outbox-таблицю (коли немає `pgmq`), журнал DDL, функції сесії, а також версії прав і службові таблиці механізму прав. Даних тенанта в ній немає. Власник усіх об'єктів — роль мігратора; `REVOKE ALL` на схему від `PUBLIC`; ролі застосунку не мають грантів на її таблиці, лише `EXECUTE` на службові функції (і `USAGE` на схему); таблиці читають і пишуть лише `SECURITY DEFINER`-функції платформи з `SET search_path = ''`. PostgREST схему не експонує (невидимість тримає конфіг схем API провайдера), RLS-шаблонів у закритій схемі немає. Компілятор резервує ім'я схеми: метадані застосунку з PG-схемою `simetra` — помилка. Платформний шар схеми рендерить компілятор із довідником з роллю «користувачі» як вимикачем; marker, ledger і функцію стану рендерить рушій схеми.

## Why

- Одне місце для всього, що платформа зараз розкладає «десь», без RLS-шаблонів у закритій схемі ([спека](../superpowers/specs/2026-10-07-system-schema-users-design.md) §2, С1).
- Дані тенанта й користувачі потрібні PostgREST, RLS-шаблонам і embed, тож вони в схемах застосунку; закритою має бути лише унікальність і прив'язка (§1, §3).
- Поділ повторює провайдерів автентифікації: закрита системна частина окремо від профілю застосунку (§1).

## Rejected

- Тримати стан платформи в схемах застосунку — змішує дані застосунку зі станом механізмів.
- Гранти ролям застосунку на таблиці `simetra` — закрита схема втратила б сенс; доступ лише через `SECURITY DEFINER`-функції.
- Експонувати схему через PostgREST — ролі API не повинні читати її напряму.

## Consequences

Легше: чітка межа «стан платформи / дані застосунку»; безпека схеми однакова незалежно від наявності довідника користувачів. Важче: кожна нова службова таблиця потребує `SECURITY DEFINER`-доступу замість RLS. Не «виправляти»: скоуплені дані тенанта (дати закриття періодів, історія версій) і довідник «Користувачі» — у схемах застосунку; не додавати гранти ролям API на таблиці `simetra`.
