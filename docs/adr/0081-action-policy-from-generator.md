# ADR-0081: політику дії задає генератор — `await` типова, `predict` лише для точних передбачень

Status: accepted 2026-11-08
Decided by: architect (approved by owner)
Spec: [рішення про рушій T4](../superpowers/specs/2026-11-08-t4-engine-decision.md) §3.4; [П4-B](../superpowers/specs/2026-11-05-p4-b-client-data-design.md) §7.1 (Рд34 у §2); [платформна](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р37)

## Context

Показати результат до відповіді сервера можна лише тоді, коли клієнт передбачає
його точно. Для команд, результат яких рахує сервер (проведення, номер,
підсумки, рухи регістрів), передбачення дало б значення, яке потім зміниться.
Спайк виміряв: відповідь `run` ≈ 1 RTT, шлях «сигнал плюс перечитування» ≈
2×RTT + 50 мс ([realtime-звіт](../superpowers/specs/2026-11-08-t4-realtime-spike-report.md)).

## Decision

- `await` — значення не змінюється до відповіді, видно `pending`, результат
  з'являється одним кадром за ≈ RTT. Типова політика для команд з серверним
  обчисленням.
- `predict` — значення видно одразу. Лише для точних передбачень (атрибут з
  нормалізацією за типом, перемикач, видалення, створення з UUID клієнта) і
  лише для об'єктів без модульного обробника запису, що читає інші поля.
- Перебазування після конфлікту (до трьох спроб без розбіжності полів) і
  локальний `noop` — лише для `predict`. Решта дає `conflict` без автоповтору.
- Політику вибирає генератор з метаданих, а не автор екрана вручну.
  Редагування картки й ТЧ — чернетка форми поза ядром з базовою версією й
  ревізіями (Рд34).

## Why

- Передбачення серверного результату дає відскок значення; ≈ 10 % коду ядра
  існує лише для `predict` і там лежать усі складні гілки, тож шар обмежено
  (Рд34).
- Без чернетки поле за `await` блимнуло б старим значенням.
- Власну дію підтверджує відповідь `run` (≈ RTT), сигнал — резерв (Р37).

## Rejected

- `predict` для всього — відскок значення на серверних обчисленнях.
- Чекати realtime замість відповіді `run` — вдвічі довше й залежить від доставки.
- Вибір політики автором екрана — розбіжності між екранами.

## Consequences

Нова команда з серверною поведінкою автоматично `await`. Не «виправляти»
`await` на `predict` заради швидкості без зміни метаданих і обробника.
CAS за полями на сервері — кандидат на заміну перебазування, окреме рішення
разом з T3.
