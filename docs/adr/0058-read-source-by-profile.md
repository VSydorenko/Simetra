# ADR-0058: Читання за профілем: PostgREST плюс RLS у supabase, Server Function під RLS у postgres

Status: accepted 2026-10-23
Supersedes: ADR-0006
Decided by: owner
Spec: [спека профілів провайдера](../superpowers/specs/2026-10-23-provider-profiles-design.md) §2 (ПП2); [платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р8, Р30); [спека П4](../superpowers/specs/2026-10-26-p4-runtime-design.md) §5 (Рт13); [спека профілю postgres](../superpowers/specs/2026-11-08-postgres-profile-design.md) §9 (ПГ12)

## Context

ADR-0006 зробив типовим джерелом колекції PostgREST. У профілі `postgres` (ADR-0057) PostgREST немає, а на довгоживучому процесі поруч із базою серверне читання не дає зайвого стрибка мережі. Одна модель прав має діяти і на читання, і на запис.

## Decision

- Джерело даних колекції лишається адаптером, але типове — за профілем (Р8, ПП2): PostgREST плюс RLS у `supabase`, Server Function під RLS у `postgres`. Контракт адаптера не змінюється.
- Серверне читання — пряме з'єднання в транзакції з контрактом сесії `runCommand`: claims через `set_config('request.jwt.claims', …, true)` і `SET LOCAL ROLE` ролі запиту; RLS лишається первинною (Р30, ПП2).
- Серверне читання — запит T0 другої форми у транзакції `READ ONLY` з `statement_timeout`; той самий будівник дає `ctx.read` хуків, MCP і адаптер Server Function (Рт13).
- Embed виражається оператором, згенерованим із метаданих, у тій самій транзакції; це не обов'язково `JOIN`.
- Перехідного PostgREST у `postgres` немає (ПГ12).

## Why

- На довгоживучому процесі поруч із базою серверне читання не додає стрибка, а форма запиту — контракт T0 між клієнтом і Server Function, а не стабільне API для сторонніх клієнтів (ПП2, Р30).
- PostgREST ставить роль і claims лише з JWT, підписаного секретом бази: у `postgres` це другий шлях автентифікації поруч із сесією провайдера ідентичності й другий секрет без виграшу (ПГ12).
- Агент MCP мусить знати версію рядка, щоб змінити його; один будівник служить серверному читанню, хукам, MCP і адаптеру (Рт13).

## Rejected

- PostgREST як типове джерело в усіх профілях (ADR-0006) — у `postgres` його немає, а прямий PostgREST вигідний лише там, де браузер іде до провайдера.
- Перехідний PostgREST у `postgres` — вимагав би JWT для бази (ПГ12).

## Consequences

Адаптер PostgREST лишається кодом T4 для профілю `supabase` і для прийнятих баз. Форму запиту до Server Function не слід публікувати як стабільне зовнішнє API.
