# ADR-0114: мова даних у сховищі T4 — вимір значення поля в рядку, сховище одне на об'єкт

Status: accepted 2026-11-25
Decided by: architect (М5c) разом з архітекторкою ядра синхронізації (М4)
Spec: [мультимовні дані](../superpowers/specs/2026-11-24-multilingual-data-design.md) §5.6

## Context

T4 тримає один `ObjectStore` на об'єкт (`data/store/core.ts`); `mergeVersioned` зливає поля за іменем при рівній версії (`data/store/object-store.ts`), а позначки `known` будуються з того самого сховища. Ідентичність форми читання — `specKey` (`data/store/forms.ts`). Рядок, прочитаний мовою L і основною мовою при тій самій версії, має різні значення мультимовних полів з тим самим іменем. Межі безпеки сховища — purge за правами, `hide`, надгробки, горизонт, бар'єри — зараз діють за ключем рядка одного сховища; ядро синхронізації М4 зводить їх в одне місце.

## Decision

1. Мова даних читання — параметр, який задає host (SSR — на запит); типово основна мова; мова входить в ідентичність форми читання й знімка SSR.
2. Сховище рядків лишається одним на об'єкт. Мова — вимір значення мультимовного поля: рядок тримає значення за парою (поле, мова); `mergeVersioned` зливає за цією парою.
3. Версія, надгробки, горизонт, purge, `hide` і бар'єри лишаються за ключем рядка й накривають значення всіх мов.
4. `known` мовою L — за правилом лінивих полів П4-B: ключ іде в `known`, лише коли рядок тримає значення мови L для всіх мультимовних полів форми з тією самою версією.
5. Вигляд читає значення своєї мови під логічним іменем поля; сигнал зміни рядка не розводиться.
6. Стан мов даних — службова ціль ядра синхронізації «мови даних» (рядок таблиці правила розширення ядра, без власного таймера) і вимога «мови не підтверджено» на `command.invalid` за мовою. Кожна резолюція цілі без L серед `published` кличе операцію області запису `Writer.dropLanguage(L, e)` зі свіжою епохою `e`: вона завжди ставить бар'єр і видаляє значення (поле, L), їхній `$status` і знімки мови L, коли вони є; бар'єр судить лише слоти (поле, L) сховища рядків і знімки читань мовою L, а частина «переклади» — запис наявного сховища частин (як ТЧ) — його не кличе; накладка журналу мутацій після бар'єра не показує передбачених значень L; вид «мову L поховано з `e`» родини «поховано з початку читання» відкидає значення L з відповідей, що стартували раніше `e`.

## Why

- З окремим сховищем на мову кожна межа безпеки (purge, бар'єр, надгробок, горизонт) стала б циклом по мовних сховищах — новий клас пропуску, той самий, що ядро синхронізації зараз прибирає.
- Сигнал за UUID рядка вже накриває всі мови; розводити його по сховищах не треба.
- Часткова присутність мов у рядку — той самий випадок, що ліниві поля, які П4-B уже розв'язує для `known` і злиття.

## Rejected

- Сховище на пару (об'єкт, мова) — кожна межа безпеки й сигнал стають циклом по мовних сховищах.
- Мова лише в `specKey` при значенні поля за іменем — читання двох мов затирають одне одного й дають хибні `$known`.
- Мультимовні поля під іменами з суфіксом мови в API вигляду (`name@pl`) — форма рядка для екранів і фільтрів залежала б від даних (кількості мов).

## Consequences

- Зміна шару `data/store`, який блоки ядра синхронізації М4 змінюють строго послідовно; блок цієї ADR стартує після закриття М4; API сховища, що змінює SK-5 (`heldStrongly`, лічильники рядків каналу), враховує це рішення.
- Родина «поховано з початку читання» (спека ядра §5.11) отримує вид «мову поховано» — узгодити з планом SK-5. `Writer.hide` для мови не годиться: він лише ставить позначку, яку знімає наступне читання, а злиття зберігає відсутні у відповіді поля.
- Пам'ять рядка росте з кількістю мов, які читає вкладка; типово вкладка читає одну мову.
