# ADR-0054: RLS-шаблон: тенант RESTRICTIVE, права PERMISSIVE за обсягом; запис — політики плюс ядро з тими самими предикатами

Status: accepted 2026-10-17
Decided by: architect
Spec: [спека прав](../superpowers/specs/2026-10-17-rights-design.md) §2 (Рх11), §5.2, §5.3, §5.4

## Context

База має лишатися остаточним бар'єром доступу, зокрема для хуків, які пишуть більше, ніж перевірило ядро команди. Водночас команда мусить відмовляти рано й з кодованою помилкою, а не лише політикою. Предикати прав обчислюються на кожен запит, тож їхня форма впливає на продуктивність.

## Decision

- Читання: межа тенанта — `RESTRICTIVE`-політика; права — `PERMISSIVE`-політики, по одній на кожен обсяг, який підтримує об'єкт (незалежно від того, які обсяги дають архетипи, бо кастомна дельта може дати будь-який) (Рх11).
- Запис: команди під `simetra_command` проходять політики `INSERT` / `UPDATE` / `DELETE` (`USING` — рядок до зміни, `WITH CHECK` — після) і `SELECT` за `read`.
- Ядро команди — рання перевірка тими самими предикатами, що й політики, з кодованою помилкою; обидві сторони рендерить один будівник предикатів (ADR-0067).
- Політика складається з умов `колонка = ANY(множина)`, де не більше однієї множини залежить від гранту; множини обчислюються раз на запит (`InitPlan`), без `SubPlan` на рядок (спека прав §5.4).

## Why

- База — остаточний бар'єр і для хуків (Рх11).
- Один будівник предикатів не дає розсинхрону ядра й політик (Рх11).
- Некорельована форма виміряна на реальній базі першого споживача: різниця між корельованою й некорельованою формою — порядки величини, з квадратичним зростанням корельованої на обмежених ролях (спека прав §5.4); перевірка для актора з багатьма скоупами над парою (дія, об'єкт) на порядки дешевша за перевірку над повними правами.
- Правило «не більше однієї множини від гранту» не дає декартового добутку умов (спека прав §5.4).

## Rejected

- Перевірка права лише в ядрі без політик — база не була б остаточним бар'єром для хуків (Рх11).
- Корельовані підзапити на рядок — на порядки повільніші (спека прав §5.4).
- Підзапит `parent_id IN (SELECT …)` для ТЧ — хешований `SubPlan` матеріалізує всі видимі id власника на кожен запит (спека прав §5.2).

## Consequences

Форму предиката тримає гейт планів: тест на даних помітного обсягу під роллю запиту, без вузла `SubPlan` і з індексом зі скоупом першим. Нову форму умови не можна додавати в обхід цього правила. Дві множини, що обидві залежать від гранту, можливі лише через ключі доступу (поза поточним обсягом).
