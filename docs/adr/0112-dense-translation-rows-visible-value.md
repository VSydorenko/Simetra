# ADR-0112: таблиця перекладів щільна — рядок на кожну не основну мову (повний для опублікованої), колонка тримає видиме значення

Status: proposed 2026-11-24 (стає accepted після DB-доказу блоку B1)
Decided by: architect
Spec: [мультимовні дані](../superpowers/specs/2026-11-24-multilingual-data-design.md) §5.1, §5.3, §5.4 (брама публікації, заповнення)

## Context

Список мовою L має сортуватися й шукати за тим, що бачить читач: перекладом, а без нього — значенням основною мовою (fallback). Вираз `coalesce(переклад, джерело)` охоплює дві таблиці, тож його не обслуговує жоден індекс; під RLS він ще й не буває умовою індексу: `CoalesceExpr` не входить до leak-safe вузлів `contain_leaked_vars_walker` (postgres `REL_17_STABLE`, `src/backend/optimizer/util/clauses.c`). Leakproof у Postgres 17.12: `texteq`, `text_lt/le/gt/ge`, `bttextcmp`, `starts_with`, `uuid_eq/lt/gt/cmp`; не leakproof: `lower`, `left`, `textlike` (запит до `pg_proc.proleakproof` на стеку `postgres`). Без рішення keyset-сортування (П4-B Рд43) і `startsWith` (ADR-0097) мовою L неможливі.

## Decision

1. Мова в стані `published` має рядок у таблиці перекладів для кожного рядка об'єкта з мультимовними реквізитами. Для мов `draft` і `disabled` рядки є там, куди їх уже вставили тригер вставки шапки чи заповнення.
2. Мультимовна колонка рядка мови L тримає **видиме значення**: переклад, а без нього — копію значення основною мовою. Ключ реквізиту в `source_hashes` позначає переклад (хеш джерела на мить перекладу); без ключа колонка дорівнює колонці шапки.
3. Інваріанти тримають тригери бази (ADR-0026), чинні й у режимі `import`; тіла — платформні функції `SECURITY DEFINER`, що пишуть лише копії значень основною мовою:
   - `AFTER INSERT` шапки — рядки всіх не основних мов з копіями;
   - `AFTER UPDATE OF` мультимовних колонок шапки — нове значення в рядках без ключа;
   - `BEFORE INSERT OR UPDATE` рядка перекладу (не з іншого тригера) — кожна колонка без ключа отримує значення шапки; прибрати переклад — зняти ключ.
4. **Брама публікації.** Перехід не основної мови в `published` — тригер: попередня перевірка без замків → `LOCK TABLE … IN SHARE MODE` на мультимовні таблиці шапки в сталому порядку під `lock_timeout` опції функції → та сама перевірка під замками; бракує рядка мови — відмова `language-incomplete`.
5. **Заповнення** — ідемпотентний копіювальник порціями (`INSERT … SELECT … FOR NO KEY UPDATE`, `ON CONFLICT (parent_id, language_id) DO NOTHING`) у всіх тенантах; повноту доводить брама. Це єдиний санкціонований запис платформи через межу тенантів; мову не видаляють.
6. Індекси таблиці перекладів спільні для всіх мов: keyset `(language_id, [скоуп], колонка, parent_id)`, префіксний пошук `(language_id, префікс)`; `unique` — частковий `UNIQUE (language_id, [скоуп], колонка) WHERE source_hashes ? '<ім'я>'` між справжніми перекладами, копії поза ним.

## Why

- Умови над збереженою колонкою (`=`, `<`, `starts_with`, `uuid_eq`) leakproof, тож індекс працює під RLS; нова мова не дає DDL.
- Одна форма зберігання й один шлях коду для всіх об'єктів.
- Порядок і фільтр сервера збігаються з видимим значенням, яке T4 порівнює локально для форм `window`/`full` (`data/store/forms.ts`).
- `unique` між справжніми перекладами не залежить від повноти заповнення: копії поза індексом, тож заповнення ніколи не впирається в `unique`, і переклад в одному тенанті не зупиняє мову для всіх.
- Щільність потрібна лише мові, яку читають. Перевірка в мить публікації стандартним табличним замком (як `CREATE INDEX` без `CONCURRENTLY`) замінює безперервне онлайн-підтримання повноти під час заповнення: без прапорця, позначки й advisory-замка на кожній вставці шапки.
- Рядки мови `draft` з'являються одразу з тригером вставки й заповненням, тож переклад готують до публікації.

## Rejected

- Розріджені рядки (рядок лише для перекладеного) з читанням `coalesce` — без індексу мовою L; сортування й фільтр — перегляд скоупу під `statement_timeout`.
- Гібрид (щільні лише для об'єктів із `indexed` чи пошуковим мультимовним реквізитом) — дві форми зберігання й дві гілки коду.
- `unique` над видимим значенням (переклади й копії в одному індексі) — заповнення впирається в переклад, рівний ще не скопійованому значенню; охорона від цього коштує перегляду скоупу на кожен запис і бар'єра при створенні мови, а адреси сторінок з історією однаково веде застосунок.
- Окрема колонка `<col>_effective` поруч із перекладом — дублює текст перекладених полів; ознака перекладу в `source_hashes` дає те саме однією колонкою.
- Безперервна повнота під час заповнення (прапорець `filled`, транзакційна позначка, спільний advisory-замок у кожній вставці шапки й бар'єр) — чотири кола аудиту знаходили в ній нові дефекти безпеки й доступності.

## Consequences

- Запис множиться: зміна значення основною мовою оновлює до P−1 рядків; створення рядка вставляє P−1 рядків; обсяг — рядки × (P−1). Прийнятно для бізнес-застосунку з кількома мовами.
- Збіг перекладу одного рядка з копією основної мови іншого рядка мовою L не ловиться; застосунок, якому потрібна унікальність видимого значення (адреси сторінок), веде власний реєстр.
- Публікація мови блокує запис у мультимовні таблиці шапки щонайбільше на N × `lock_timeout` плюс перевірку; неповна мова відмовляється попередньою перевіркою без замків; публікацію запускає адміністратор, і вона рідкісна.
- Писати мовою можна лише в рядок, який уже є; рядка ще немає — `language-incomplete`.
- **Фальсифікатор:** блок B1 доводить на базі, що складені індекси з провідним `language_id = $n` є умовою індексу під чотирма формами політики (пряма, членство з підзапитом, `<t>_public_read` з фільтром опублікованих мов, `OR` з `<t>_edit_read`). ADR-0097 відкинув складений ключ (скоуп, нормалізована) саме під політикою членства, але там провідна колонка — умова політики, а тут — константа запиту. **Запасний шлях**, якщо доказ не пройде: одноколонковий префіксний індекс і keyset-індекс без `language_id`, умова мови — фільтром над результатом індексу.
