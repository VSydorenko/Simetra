# ADR-0007: Одне поле `kind`; кожна гілка за видом читає реєстр видів

Status: accepted 2026-09-24
Decided by: owner
Spec: [платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md) §2 (Р9), §4; [спека П2](../superpowers/specs/2026-09-28-p2-metamodel-compiler-design.md) §2 (М11), §5

## Context

Знання про вид об'єкта потрібне в багатьох місцях: стандартні колонки й
тригери, словник дій прав, UI за замовчуванням. У прототипі це знання було
розмазане між генератором і UI, і класифікаторів було більше одного.

## Decision

- Об'єкт має одне поле `kind`; воно задає стандартні колонки й тригери, словник
  дій прав і UI за замовчуванням (Р9).
- Код, що поводиться по-різному залежно від виду, бере факт із запису реєстру
  видів, а не перемикається за назвою виду. Новий вид — це новий запис реєстру
  плюс тести (М11).
- Кожна схема виду несе літерал `kind`.

## Why

- Не два паралельні класифікатори: один реєстр замість знань, розмазаних між
  генератором і UI (Р9, М11).
- Реєстр — єдине джерело виведення стандартних реквізитів, тож додати вид
  означає додати запис, а не пройтися по всіх `switch`
  ([спека П2](../superpowers/specs/2026-09-28-p2-metamodel-compiler-design.md) §5).

## Rejected

- Окремий класифікатор для UI поряд із видом метамоделі — дублює знання й
  розходиться з ним.
- Перемикання за назвою виду в генераторах — новий вид вимагає правок усюди.

## Consequences

Легше: новий вид — запис реєстру й тести. Важче: будь-яка різниця поведінки між
видами мусить стати полем запису реєстру. Не «виправляти»: `switch` за назвою
виду в коді, що читає метадані, — це дефект, а не скорочення.
