# ADR-0132: варіанти списку бувають стандартні, особисті й спільні

Status: accepted 2026-11-26
Decided by: owner
Spec: [модель інтерфейсу](../superpowers/specs/2026-11-26-ui-model-design.md) §5.5; [налаштування інтерфейсу](../superpowers/specs/2026-11-26-ui-settings-design.md) §5.7

## Context

Користувач повертається до тих самих наборів колонок, фільтрів і сортування. Відділу потрібні спільні набори без нової версії застосунку.

## Decision

- Варіант списку тримає колонки, фільтр, сортування, групування й вид списку.
- Стандартний варіант дає застосунок у метаданих; змінити його не можна, можна скопіювати.
- Особистий варіант зберігає користувач.
- Спільний варіант публікує користувач з правом публікувати — для ролі або для скоупу.
- Ширини колонок і останній варіант — стан інтерфейсу; незбережені зміни живуть лише в адресі сторінки.

## Why

- Одна схема запису з полем поширення покриває три види; додати поширення пізніше означало б зміну схеми даних.
- Запит списку має одного власника — адресу сторінки (спека §5.5); варіант дає лише початкове значення.

## Rejected

- Стандартні й особисті — спільний набір з'являвся б лише з новою версією застосунку.
- Лише стандартні й запам'ятований стан — іменованих наборів немає.

## Consequences

Потрібне право публікувати з адресатом. Рішення архітекторки після аудиту: спільний варіант створює, змінює й видаляє лише той, хто має право публікувати на момент запису; авторство права запису не дає. Поширення задається при створенні й не змінюється: особистий варіант стає спільним лише як новий рядок.
