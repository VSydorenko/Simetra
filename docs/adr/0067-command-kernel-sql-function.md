# ADR-0067: Ядро команди — SQL-функція SECURITY INVOKER з перевіркою права тими самими предикатами; окремої authorize немає; нуль рядків розрізняє замок

Status: accepted 2026-10-27
Decided by: architect
Spec: [спека П4](../superpowers/specs/2026-10-26-p4-runtime-design.md) §5 (Рт2, Рт3, Рт4)

## Context

Команда записує рядок, перевіряє право актора й відрізняє конфлікт версії від відмови в праві. Спека прав початково передбачала окрему функцію `simetra.authorize`. Умови `own`, виміру й контейнера мають окрему форму носіїв, яку RLS-предикат не повторив би.

## Decision

- Ядро команди — згенерована SQL-функція на таблицю й дію, `SECURITY INVOKER` під `simetra_command`, `EXECUTE` лише `simetra_command`: `<t>_save(p_item jsonb, p_expected_version bigint)` (створення при `NULL`, інакше зміна) і `<t>_mark_deletion(p_id uuid, p_expected_version bigint, p_mark boolean)`; повертає рядок після запису текстом `jsonb` (Рт2).
- Перевірка права — частина ядра: воно рендерить ті самі `rightsPredicates`, що й політики запису, над змінними рядка «до» і «після». Окремої функції `authorize` немає (Рт3).
- Зміна й позначка спершу беруть `SELECT … FOR NO KEY UPDATE` за id під контекстом команди (видалення призначення — `FOR UPDATE`): відсутній і чужий рядок дають ту саму відмову `no-right`, інша версія — конфлікт; після DML нуль рядків — `no-right` (Рт4). Створення спершу читає рядок за id: видно — конфлікт `exists`, не видно — `INSERT`.

## Why

- `INVOKER` лишає RLS остаточним бар'єром (Рт2, ADR-0054).
- Еквівалентність із RLS тримає побудова — один будівник предикатів, а не друга реалізація формули (Рт3).
- Замок рядка застосовує й політики `UPDATE USING` за будь-якої сили; у `READ COMMITTED` відкликання права між замком і `UPDATE` може відфільтрувати рядок, тож нуль рядків після DML лишається відмовою, а не конфліктом (Рт4).
- `NO KEY UPDATE`, бо `FOR UPDATE` конфліктує з `FOR KEY SHARE` RI-перевірок, і дві команди з взаємно новими посиланнями дали б `40P01`; ключа команда не змінює (Рт4).

## Rejected

- `SECURITY DEFINER` для ядра — обійшов би RLS (Рт2).
- Окрема функція `simetra.authorize` — друга реалізація формули, що розійшлася б із політиками (Рт3).
- Повторна перевірка права для розрізнення нуля рядків — не відрізняє конфлікт від відмови надійно (Рт4).

## Consequences

Відсутній і чужий рядок свідомо неможливо розрізнити з боку клієнта — це не слід «уточнювати» кодом помилки. Для `DELETE` лишається `FOR UPDATE`, бо видалення конфліктує з `KEY SHARE` за природою. Форму `<t>_save` змінює лише разом із `kernelHash` (ADR-0066).
