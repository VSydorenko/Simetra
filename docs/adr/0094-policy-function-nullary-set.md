# ADR-0094: Функція політики — множина без параметрів; решта definer-хелперів політик — клас ремонту

Status: accepted 2026-11-18
Decided by: architect (напрям погодив власник)
Spec: [декларації функцій](../superpowers/specs/2026-11-18-sql-function-declarations-design.md) §5.8; [промоція](../superpowers/specs/2026-10-06-promotion-design.md) §9, §9.4

## Context

Правило #173: definer-функція SQL застосунку з `EXECUTE` для ролі API без
декларації — помилка в будь-якій одиниці, борг включно. Власник: споживачів
ще немає, поступок сумісності немає. Прийнята база першого споживача має
понад два десятки definer-хелперів, які кличуть її дослівні політики:
булеві предикати членства, права й ролі, множини видимості з аргументом
тенанта, множини тенантів. Частина з них приймає id іншого користувача, тож
працює як оракул чужих прав. `EXECUTE` видається ролі, а не місцю виклику: функцію,
яку кличе політика, роль запиту може викликати і як RPC. Експозицію схеми
API компілятор не бачить, тож безпека має триматися на нешкідливості
прямого виклику, а не на його недосяжності. Спека промоції §9 уже називає
шлях: «корельовані хелпери → функції множини (C)».

## Decision

1. **Функція політики** — форма платформи: функція множини без параметрів
   (`LANGUAGE sql STABLE SECURITY DEFINER SET search_path = ''`, один
   `SELECT`, `RETURNS SETOF uuid`, суддя голів Правила 3) з результатом,
   прив'язаним до актора. Політика, що її кличе, — лише атоми
   `<колонка> IN (SELECT f())` чи `= ANY(ARRAY(SELECT f()))`, один чи
   з'єднані `OR`, без `AND` і `NOT`, і `TO` лише ролей призначень `user`, `service` чи
   `command`. Компілятор розпізнає її за графом викликів, без декларації;
   декларація на неї — помилка; форма платформи, що вже є функцією множини
   скоупу чи функцією значень виміру, функцією політики не буває. `EXECUTE`
   виводить платформа з ролей `TO` політик-викликачів, ролі без сесії —
   ніколи; дослівний грант — `sql.generated-grant`. Вона в закритій
   оболонці, тож боргом не є; борг — політики, що її кличуть. Вона звільнена
   від `sql.definer-caller-unchecked`; вихід — промоція (вид скоупу з
   прийнятим джерелом) або видалення з останньою політикою.
2. **Актор у кожній голові** — лише функція ідентичності провайдера (claims
   JWT) чи `simetra.current_user_id()`, транзитивно; `current_setting` у
   кожній голові — лише з літеральною назвою налаштування, яке спека прав
   §5.3 захищає від запису SQL застосунку (`PROTECTED_SESSION_SETTINGS`: `request.jwt.claims`,
   `request.jwt.claim.<поле>`, префікс `simetra.`), зокрема в наявних
   функціях множини скоупу й функціях значень виміру.
3. **Решта definer-функцій, які кличе дослівна політика** (параметризовані, корельовані, `plpgsql`, `VOLATILE`, з параметром актора,
   з результатом без прив'язки до актора, у політиці з `AND`, `NOT`, сторонньою умовою чи `TO PUBLIC`), — клас ремонту
   (`sql.policy-helper-correlated`) з підказкою й `explain`, що пропонують
   переписати функцію на множину без параметрів, а виклики в політиках — на
   `<колонка> IN (SELECT f())`. Зміну застосовує звичайний план.
4. Промоція: функція політики стає функцією множини виду скоупу або зникає
   разом з політикою.

## Why

- Прямий виклик функції політики нешкідливий: без параметрів, з
  результатом, прив'язаним до актора з claims точною формою рівності й
  зв'язністю з'єднань, і з політикою — `OR` атомів без інших умов — RPC
  повертає підмножину того, що політика дає цьому актору.
  Оракул чужих прав формою неможливий.
- Форма та сама, що й функція множини скоупу: той самий суддя голів,
  некорельований `InitPlan`, той самий шлях промоції. Нового механізму немає —
  клас ремонту вже є (спека декларацій §5.1).
- Канон не отримує повільних корельованих предикатів (спека промоції §2.1:
  корельована політика — сотні мілісекунд, некорельований шаблон —
  мілісекунди).
- Налаштування поза `PROTECTED_SESSION_SETTINGS` задає клієнт запиту
  (заголовки, cookies, шлях) чи будь-який SQL застосунку (`set_config`), а не
  сесія: голова, що читає їх, віддала б права значенню від клієнта. Запис
  `request.jwt.*` з боргового SQL — лише попередження (спека прав §5.3): той
  самий залишковий ризик несе й функція ідентичності провайдера.

## Rejected

- Декларація в боргу без перевірки — та сама definer-функція з `EXECUTE` для
  ролі API без доказу безпеки, тобто виняток із правила #173.
- Параметризована форма з доказом «немає параметра актора» через FK —
  доказ умовний: тип параметра й FK не гарантують, що функція не відповідає
  про іншого користувача.
- Опора на неекспоновану схему — експозицію API компілятор не бачить, а
  `EXECUTE` діє для будь-якого шляху виклику.
- Переписування хелперів вручну до прийому — прийом мусить описати базу як
  є, а ремонт — окремий крок під контролем компілятора й плану.

## Consequences

- Прийом бази з корельованими хелперами дає помилки класу ремонту, а не
  тихий прийнятий стан; мутації designer працюють у режимі `repair`.
- Обмеження `current_setting` діє й на наявні функції множини скоупу й
  функції значень виміру.
- Політика боргу `TO PUBLIC`, що кличе предикат, потребує ремонту: вона діє
  й на роль без сесії, якій `EXECUTE` не видається.
- Функція політики, що лишилася без політики-викликача, судиться як звичайна
  definer-функція: її `EXECUTE` більше ніхто не виводить.
