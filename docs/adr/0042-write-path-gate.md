# ADR-0042: Гейт шляху запису — об'єкт, у який застосунок пише напряму, не промотується

Status: accepted 2026-10-07
Decided by: owner
Spec: [промоція](../superpowers/specs/2026-10-06-promotion-design.md) §3 (Пр21), §8, §16

## Context

Після промоції запис у вид іде лише командами платформи (ADR-0024), а ролі API мають лише читання. Якщо застосунок пише в прийняту таблицю напряму (гранти запису ролям API чи політики запису), промоція зламала б його запис, поки шару команд немає.

## Decision

Промоція об'єкта, у який застосунок пише напряму, — відмова, доки не вирішено етап шляху запису. Умова: на прийнятій таблиці є гранти запису ролям API (явні, колонкові чи через типові привілеї схеми) або політики запису; гейт повторюється проти живої цілі під час побудови плану й охоплює типові привілеї ролі, що застосовує, і для схеми одиниці, і глобальні. Повідомлення гейта називає відкрите питання «Шлях запису після промоції». Платформна провізія користувачів тригером на таблиці провайдера (ADR-0047) — не шлях запису застосунку й гейт не вмикає. Вид не дає сервісній ролі привілеїв; привілеї, які промоція в неї забирає, план показує окремо під `access:<таблиця>`, а скіл конверсії до промоції перевіряє, чи серверний код читає чи пише таблицю сервісним ключем.

## Why

- Після промоції запис у вид — лише командами платформи (Р21), а ролі API мають лише читання; без шару команд промоція зламала б запис застосунку ([промоція](../superpowers/specs/2026-10-06-promotion-design.md) §3, Пр21; §8).
- Відмова з названим питанням чесніша за мовчазну поломку: питання «Шлях запису після промоції» зачіпає кеш, ядро T4, читання на сервері й шар даних і відкладене до етапу рантайму даних (§16).

## Rejected

- Промотувати об'єкт і лишити застосунку прямий запис — суперечить Р21 і ADR-0024.
- Мовчки знімати гранти запису ролям API — ламає застосунок без попередження.

## Consequences

Легше: промоція не ламає запис застосунку несподівано. Важче: об'єкти з прямим записом чекають на шлях запису, поки застосунок не перейде на команди. Не «виправляти»: не послаблювати гейт, поки шлях запису не вирішено окремим рішенням; тригер провізії користувачів гейт не вмикає.
