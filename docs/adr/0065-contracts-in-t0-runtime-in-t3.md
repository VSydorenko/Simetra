# ADR-0065: Контракти — у T0, рантайм — у T3 через порт CommandDatabase; T4 і T5 не імпортують сервер; помилка — значення в конверті, форма передачі фізична

Status: accepted 2026-10-26
Decided by: architect
Spec: [спека П4](../superpowers/specs/2026-10-26-p4-runtime-design.md) §5 (Рт1, Рт15); [спека П4-B](../superpowers/specs/2026-11-05-p4-b-client-data-design.md) §2 (Рд4, Рд17)

## Context

Клієнт (T4, T5) і сервер (T3) говорять одним контрактом, але серверний код не повинен потрапити в клієнтську збірку, а production-код `simetra` не імпортує драйвера `pg`. Server Function серіалізує відповідь, і виняток губить поля помилки. Перейменування об'єкта без DDL (ADR-0003) не повинно ламати стару вкладку.

## Decision

- Форма операції, результату, набору змін, помилок (з класом `CommandFailure`), запиту читання, каталогу рантайму й хуків — у `simetra/model` (T0); `simetra/server` (T3) — лише сервер (Рт15). T4 і T5 не імпортують `simetra/server`: лінт-зона з негативним тестом, за однією декларацією серверних входів пакета.
- T3 не імпортує драйвера: він оголошує порт `CommandDatabase` (`connect()` → клієнт із `query(text, params)` і `release(destroy?)`) і дає адаптер `fromPgPool(pool)`, що читає `pg.Pool` структурно (Рт1). Параметри — лише `string | null`; рядки повертаються одним текстовим стовпцем JSON, де `numeric` і `bigint` подані рядками; помилка — об'єкт `{ code, message, detail, hint, constraint, table, column, connectionLost }`.
- Host прив'язує одну Server Function до `createDataHandler(runtime)`; відповідь — значення `{ ok, value } | { ok: false, error }`, а не виняток (Рд4).
- Форма передачі між T4 і T3 — фізична (Рд17): об'єкт — UUID каталогу, реквізити — фізичні колонки, рядки — сирі. Сервер приймає лише колонки свого каталогу; T4 мапить логічне й фізичне сам. Логічна форма T0 — для API в процесі (хуки, MCP, серверний код host-а).

## Why

- Без заборони серверний код потрапив би в клієнт транзитивно через T5 → T4; правило реалізує «межа клієнт/сервер — одна декларація» (Рт15).
- Порт зберігає межу «production-код не імпортує `pg`»; власні парсери типів host-а не змінюють результату T3; `numeric` не губить точності (Рт1).
- Помилка як значення переживає серіалізацію Server Function без втрати полів (Рд4).
- Перейменування без DDL безпечне і на читанні, і на записі; логічних імен старої вкладки сервер із новим каталогом не впізнав би (Рд17).

## Rejected

- Прямий `pg.Pool` у T3 — порушує межу драйвера (Рт1).
- Виняток як форма помилки відповіді — губить поля при серіалізації (Рд4).
- Логічні імена у формі передачі — ламаються при перейменуванні без DDL (Рд17).

## Consequences

Нова серверна можливість додається за портом і контрактом T0, а не імпортом сервера в клієнт. Фізична форма передачі свідомо неудобна для читання людиною; логічну форму слід лишати лише для API в процесі.
