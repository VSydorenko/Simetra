# ADR-0106: сервер авторизації агента — `oidc-provider` у host-і поряд із Better Auth; MCP застосунку — сервер ресурсу; токени непрозорі

Status: accepted 2026-11-24
Decided by: architect
Spec: [П4-F](../superpowers/specs/2026-11-24-p4-f-agents-design.md) §5.4

## Context

Специфікація MCP (ревізія 2026-07-28, https://modelcontextprotocol.io/specification/latest/basic/authorization) вимагає від MCP-сервера ролі сервера ресурсу OAuth 2.1: метадані RFC 9728, перевірка, що токен виданий саме для нього (RFC 8707), відмова іншим токенам; реєстрація клієнта — Client ID Metadata Documents (CIMD) як SHOULD, динамічна реєстрація (DCR) — MAY і застаріла. У профілі `postgres` людський вхід дає Better Auth у host-і (спека профілю `postgres` §4).

Вимоги П4-F до сервера авторизації: лише публічні клієнти (ChatGPT оголошує в документі CIMD `private_key_jwt`, а `/token` викликає без `client_assertion` — заміри `munin-mcp`); токен оновлення без запиту `offline_access`; грант не залежить від браузерної сесії; повторне вживання токена оновлення відкликає лише свій грант (клієнт, користувач, тенант); тенант прив'язаний до одного запиту авторизації; згода на кожному `/authorize`; список і відкликання грантів.

`@better-auth/oauth-provider` (перевірено код 1.7.12, 1.7.28, 1.8.0-beta.11) цих вимог не виконує: до методів автентифікації завжди додає конфіденційні; токен оновлення видає лише з `offline_access`; токени прив'язані до браузерної сесії й відкликаються з виходом; сімейство токенів відкликає за (клієнт, користувач) в 1.7; тенант згоди читає з сесії в момент згоди; списку грантів з активністю немає. Issue better-auth#10660 про методи автентифікації CIMD відкритий.

`oidc-provider` 9.12.2 (MIT, Filip Skokan; сертифікований OpenID для профілів OIDC) виконує їх налаштуванням і адаптерами: `clientAuthMethods: ["none"]`, `issueRefreshToken`, `expiresWithSession`, повторне вживання токена оновлення відкликає грант (`lib/actions/grants/refresh_token.js`), взаємодія на кожен запит (`uid`), `extraTokenClaims`, `accessTokenFormat: "opaque"`, `revocation`, `resourceIndicators`, CIMD — експериментальна функція `features.clientIdMetadataDocument`. Сусідній проєкт `munin-mcp` використовує його як сервер авторизації для MCP і заміряв вхід Claude Code, claude.ai і ChatGPT через CIMD.

## Decision

- Сервер авторизації агента — `oidc-provider` у host-і, версія закріплена точно. Людський вхід лишається за Better Auth; на сторінці взаємодії сервер авторизації бере користувача з сесії Better Auth.
- Клієнти — лише публічні, реєстрація — CIMD з нормалізацією документа (`none`, без `jwks_uri`); DCR вимкнена; документ завантажує власний транспорт із захистом від SSRF.
- Токени доступу непрозорі; MCP-вхід перевіряє токен у сховищі сервера авторизації в тому самому процесі на кожен запит, тож відкликання діє одразу.
- Грант — (клієнт, користувач, тенант); не залежить від браузерної сесії; відкликається повторним вживанням свого токена оновлення, екраном підключених клієнтів або `/revoke` токена оновлення (`/revoke` токена доступу знімає лише цей токен).
- Ідентичність клієнта (`client_id`, адреса документа CIMD) стає `act.sub`.
- Профіль `supabase`: вхід агентів відмовляє з діагностикою, доки його вхід не матиме сервера авторизації з тими самими властивостями.
- Спосіб монтування `oidc-provider` (обробник Koa/Node) у сервері шаблону встановлює прототип F0.

## Why

- `oidc-provider` виконує кожну вимогу налаштуванням або невеликим адаптером; Better Auth потребує змін у бібліотеці, на які не можна покластися.
- Інтероперабельність із трьома клієнтами заміряна на тій самій бібліотеці в `munin-mcp`.
- Локальна перевірка JWT не бачить відкликання до кінця строку токена; вхід агента пише дані.
- Відкрита DCR дає будь-кому зареєструвати клієнта; CIMD дає стабільну ідентичність клієнта для журналу й стелі.

## Rejected

- `@better-auth/oauth-provider` з `@better-auth/mcp` — не виконує вимог публічних клієнтів, оновлення без `offline_access`, незалежності від сесії, гранту на тенант.
- Власний сервер авторизації платформи — повторює зрілу бібліотеку.
- JWT з локальною перевіркою — відкликання запізнюється на строк токена.
- DCR — застаріла в MCP і небезпечна відкритою.

## Consequences

У host-і дві бібліотеки ідентичності: Better Auth для людей і `oidc-provider` для агентів, кожна зі своїми ключами й таблицями. CIMD в `oidc-provider` експериментальний: оновлення версії — окрема зміна з тестами. Бібліотека вживає токен оновлення до перевірки ресурсу: перевірки на `/token` ідуть до вживання. Монтування обробника Node у сервері шаблону перевіряє F0.
