# ADR-0113: мови даних — системний довідник «Мови»; основна мова одна на базу й незмінна

Status: accepted 2026-11-24
Decided by: owner
Spec: [мультимовні дані](../superpowers/specs/2026-11-24-multilingual-data-design.md) §5.2

## Context

Набір мов даних визначає, якими мовами зберігаються мультимовні реквізити (ADR-0111). Мову застосунок додає під час роботи, без деплою. Метадані вже мають мітки `LocalizedString` з ключами `uk`/`en` (`model/schemas/localized-string.ts`) — це мова інтерфейсу, інший вимір. Платформні довідники з особливою роллю вже є: «Користувачі» й довідники прав (`CATALOG_ROLES`, `model/kinds/catalog.ts`).

## Decision

1. Мови даних — рядки системного довідника «Мови» з роллю `languages`: код BCP 47 незмінний; стан `draft → published → disabled` (повний набір переходів — спека §5.2); рівно одна основна мова, лише `published`.
2. Основна мова одна на базу даних. Її задає конфіг при створенні застосунку (передвизначений елемент); надалі вона не змінюється.
3. Розгортання з різними основними мовами для незв'язаних власників — окремі бази, а не тенанти однієї бази.

## Why

- Мову додають з адмінки без деплою й без DDL (ADR-0112).
- Той самий шлях, що «Користувачі» й довідники прав: права, команди, екрани довідника виводяться як для будь-якого довідника.
- Незмінна основна мова робить колонку шапки однозначною (ADR-0111); власник виключив кілька застосунків незв'язаних власників в одній базі.

## Rejected

- Список мов у метаданих проєкту — нова мова вимагала б деплою.
- Основна мова на тенанта — колонка шапки тримала б різні мови в різних рядках; `unique` і сортування між тенантами втратили б сенс.

## Consequences

- Зміна основної мови — окремий майбутній інструмент масового перенесення, не операція довідника.
- Мова інтерфейсу користувача не залежить від набору мов даних.
