# Glossary

Одне слово — одне значення. Специ, плани, назви в коді й повідомлення власнику вживають слова цього глосарія; якщо слово має друге значення, воно має власний термін. Новий термін додається, коли вперше з'являється в обговоренні чи спеці (скіл `spec`).

## Платформа і споживач

**Simetra** — платформа бізнес-застосунків, описаних метаданими, у дусі 1С:Підприємство; з метаданих виводить схему БД, права, команди, дані клієнта й стандартні екрани.
*Avoid:* «продукт», «фреймворк»
*See:* ADR-0001, ADR-0011, [платформна спека](superpowers/specs/2026-09-24-simetra-platform-design.md) §3

**Застосунок-споживач** — проєкт, що ставить пакети Simetra і тримає лише свої декларації, правила й нестандартні екрани.
*Avoid:* «продукт», «клієнт» (у значенні застосунку)
*See:* ADR-0011

**Перший споживач** — перший застосунок-споживач; його досвід доповнює концепцію, але не звужує її. У спеках — без імені.
*Avoid:* назва застосунку в спеках і ADR
*See:* ADR-0011, ADR-0014

**Конфігурація** — повний опис застосунку у файлах `metadata/` у git.
*Avoid:* «застосована конфігурація» (для стану в БД)

**Застосований стан** — стан, що застосований до бази й записаний у marker; відрізняється від конфігурації у файлах.
*Avoid:* «конфігурація» (для стану в БД)

**Модуль** — пакет об'єктів, поведінки й екранів; пише лише у власні об'єкти.
*Avoid:* «модуль» для TS-файлу одного об'єкта
*See:* ADR-0009

**Модуль об'єкта** — TS-файл поведінки одного об'єкта метаданих: хуки, правила, власні запити.
*Avoid:* «модуль» без уточнення

**Ярус** — тека флагманського пакета `simetra` під лінт-зоною: T0 `model`, T1 `compiler`, T2 `schema`, T3 `server`, T4 `data`, T5 `ui`, T6 `shell`; імпорт лише вниз.
*Avoid:* «тір», «шар» (для ярусу)
*See:* ADR-0001, ADR-0010

## Метамодель

**Об'єкт метаданих** — одна бізнес-сутність конфігурації з `id`, `kind`, `name`, `physicalName`.
*Avoid:* «сутність», «метаоб'єкт»

**Вид** — рід об'єкта метаданих (`kind`); один запис реєстру видів задає схему, стандартні реквізити, патерн запису, словник дій і стандартний UI.
*Avoid:* «тип об'єкта», «kind» в українському тексті
*See:* ADR-0007

**Реєстр видів** — єдине джерело фактів про види в T0 (`packages/simetra/src/model/kinds/`); код, що поводиться по-різному за видом, читає його.
*See:* ADR-0007

**Вид 1С** — вид із семантикою 1С (довідник, документ, перерахування, регістри, константа); склад стандартних реквізитів задають вид і його налаштування.
*See:* ADR-0015

**CustomTable** — вид без семантики 1С: точний фізичний опис таблиці; для прийнятих таблиць до промоції й постійних технічних таблиць.
*Avoid:* «довільна таблиця», «adopted table»
*See:* ADR-0015

**Реквізит** — поле об'єкта з `id`, `name`, `physicalName` і типом.
*Avoid:* «атрибут» (у прозі), «поле» (для метаданих)

**Стандартні реквізити** — службові реквізити, які виводить вид із налаштувань (код, найменування, дата, номер, позначка видалення, `version`, `predefined_name`…); у файлах не зберігаються.
*See:* ADR-0015

**Налаштування виду** — параметри, що керують складом стандартних реквізитів (довжина коду 0 — коду немає).
*See:* ADR-0015

**Таблична частина (ТЧ)** — рядки, що належать об'єкту; фізично окрема таблиця, успадковує скоуп; ТЧ не вкладаються.
*Avoid:* «табличка», «tabular section» в українському тексті

**Довідник** — вид для умовно-постійної інформації (код, найменування, ієрархія, власник).

**Документ** — вид для події в момент часу: номер, дата, ТЧ, проведення.

**Перерахування** — вид із фіксованим набором значень; у БД — `text` + `CHECK` з мітками значень.
*Avoid:* «енам» (для виду)
*See:* ADR-0020

**PgEnum** — запис наявного енам-типу Postgres у `CustomTable`; не вид 1С.
*See:* ADR-0020

**Регістр відомостей** — вид для даних у розрізі ключа, з періодом або без.

**Регістр накопичення** — вид для рухів документів-реєстраторів; два види: залишків і оборотів.
*See:* ADR-0023

**Виміри, ресурси, реквізити регістру** — ролі полів регістру: ключ, значення, додаткова інформація.

**Константа** — вид з одним значенням на застосунок.

**EventSubscription** — вид без сховища: підписка на подію запису; тригер генерує платформа.
*Avoid:* «підписка» без уточнення
*See:* ADR-0033

**Посилання (`Ref`)** — реквізит, значенням якого є інший об'єкт; поліморфне посилання — `allowedTypes`, пара `<ім'я>_type` + `<ім'я>_id` без FK.
*Avoid:* «лінк», «зв'язок»

**MetadataRef** — єдина форма посилання у файлах: `{ kind, name }`; компілятор резолвить її в UUID.
*See:* ADR-0003

**Логічне ім'я** — ім'я елемента в метаданих; стиль імен реквізитів — `naming.attributeCase` проєкту.
*See:* ADR-0003

**`physicalName`** — ім'я в БД; призначається раз, перейменування його не змінює; єдиний виняток — промоція.
*Avoid:* «ім'я колонки», «ім'я в базі»
*See:* ADR-0003, ADR-0039

**Ідентичність елемента** — UUID іменованого елемента метаданих; ніколи не перевикористовується.
*Avoid:* «ідентичність» без уточнення
*See:* ADR-0003

**Призначене раз** — поле, яке компілятор не дає змінити при тому ж `id` відносно baseline git (`identity.assigned-once-changed`).
*See:* ADR-0003

**Фізична мітка** — значення, призначене раз, що живе в даних: мітка значення перерахування, `predefined_name`, мітка виду.
*Avoid:* «label», «маркер»

**Мітка виду** — читабельне слово, призначене раз і незмінне навіть промоцією; дискримінатор поліморфних пар, ключ прав і нумерації.
*Avoid:* «код типу», «kind label» в українському тексті
*See:* ADR-0044

**Предвизначений елемент** — рядок довідника з міткою `predefined_name`; мітку ставить лише платформа, `id` свій у кожній базі.
*See:* ADR-0015

**Скоуп** — розділювач даних і межа ізоляції тенанта, не модель доступу; застосунок оголошує 0..n видів скоупу.
*Avoid:* «тенант» (для механізму), «компанія», «простір», «scope» в українському тексті
*See:* ADR-0008

**Вид скоупу** — оголошення в `project.meta.json`: UUID, ім'я скоуп-колонки, корінь, функція множини.
*See:* ADR-0008

**Корінь скоупу** — об'єкт з одноколонковим uuid-ключем, ключ якого і є значенням скоупу.
*Avoid:* «кореневий рядок» (це інше: рядок, який пише команда)

**Носій скоупу** — колонка, що несе значення скоупу в рядку.

**Складений FK** — посилання всередині скоупу `(scope, ref) → (scope, id)`; міжскоупне — лише з `crossScope`.
*See:* ADR-0008

**Членство** — декларативна властивість `membership` скоупленого довідника: учасник тенанта; не вид.
*Avoid:* «вид "членство"», «member» в українському тексті
*See:* ADR-0046

**Порожнє значення** — `NULL`; обов'язковість — правило за видом.
*Avoid:* «службове порожнє», «заглушка»
*See:* ADR-0025

**Патерн запису** — властивість виду: оптимістичний (id від клієнта) чи серверний (`gen_random_uuid()`).

**Проведення** — дія, що фіксує вплив документа на облік рухами регістрів, атомарно на сервері.
*Avoid:* «posting» в українському тексті
*See:* ADR-0017

**Оболонка проведення** — згенерована платформою функція `<doc>_save/_post/_unpost`: блокування, статус, права, обов'язковість, рухи, контроль залишків.
*Avoid:* «оболонка» без уточнення, «shell»
*See:* ADR-0017

**Рух** — рядок регістру від документа-реєстратора.

**Реєстратор** — документ, що пише рухи; поліморфна пара `recorder_type` + `recorder_id`.

**Запит рухів** — повний SQL рухів у блоці `-- @movements`; **конструктор рухів** — мала граматика `posting.movements[]`.
*Avoid:* «posting DSL»
*See:* ADR-0017

**Підсумки регістру** — `<reg>_turnovers_month` і `<reg>_totals`, які веде тригер рівня оператора.
*See:* ADR-0023

**Віртуальна таблиця регістру** — SQL-функція залишків, оборотів чи зрізів на межі «момент + реєстратор».
*See:* ADR-0023

**Нумерація** — номер чи код першим записом із лічильника в тій самій транзакції.
*See:* ADR-0017

**Версія рядка** — стандартний реквізит `version` довідника й документа; береться з послідовності, не зменшується.
*Avoid:* «версія даних», `row_ver` у прозі
*See:* ADR-0082

**Позначка видалення** — стандартний реквізит; видалення в 1С-моделі — позначка й контроль посилань, не каскад.
*See:* ADR-0037

**Подання** — декларація списку, картки, фільтрів і віджетів об'єкта.
*See:* ADR-0009

**Рівні кастомізації** — параметри → слоти → внески модулів → кастомна сторінка.
*See:* ADR-0009

## Компілятор і designer

**Компілятор** — чиста функція `files → знімок + хеш + діагностика`; єдині двері для всіх поверхонь.
*See:* ADR-0002

**Стадії компілятора** — 1 файл, 2 ідентичність, 3 модель, 4 цілісність, 5 зв'язок із модулями; 6 (план БД) — T2.

**Скомпільований знімок** — детермінована модель з UUID, фізичний знімок і SQL-одиниці.
*Avoid:* «знімок» без уточнення
*See:* ADR-0002

**Хеш знімка** — sha256 від канонічної серіалізації скомпільованого знімка.

**Baseline git** — стан метаданих у `HEAD` git, проти якого компілятор перевіряє поля «призначене раз».
*Avoid:* «baseline» без уточнення

**Baseline схеми** — знімок схеми, з якого розгортається нова інсталяція; не baseline git.
*Avoid:* «baseline» без уточнення

**Діагностика** — повідомлення компілятора у формі LSP: файл, JSON-pointer, код правила, серйозність.

**Синтетичний домен** — публічні метадані `examples/reference/metadata/`, що повторюють форму схеми споживача, не імена.
*See:* ADR-0014

**`@simetrajs/designer`** — окремий пакет інструментів розробника, бінарник `simetra`.
*Avoid:* «CLI-пакет», `@simetra/cli`
*See:* ADR-0030

**Режим designer** — тонкий адаптер над одним каталогом інструментів: командний рядок, MCP, студія.
*Avoid:* «поверхня» (для режиму)
*See:* ADR-0030

**Студія** — режим `simetra studio`: локальний конфігуратор на TanStack Start.
*Avoid:* «конфігуратор» (як назва частини), «web configurator»
*See:* ADR-0030

**Каталог інструментів** — перелік інструментів designer з осями доступу `files` і `database`.
*See:* ADR-0032

**Скіл споживача** — скіл, що їде в пакеті тієї самої версії; `simetra init` кладе симлінки.
*See:* ADR-0030

**Зворотна генерація** — `simetra introspect`: з каталогу БД — метадані `CustomTable`, `PgEnum` і дослівний SQL.
*Avoid:* «introspect» у прозі

**Round-trip** — extract → зворотна генерація → компіляція → рендер → порожній план; критерій повноти опису.

## Схема БД, прийом і промоція

**Рушій схеми** — ярус T2: рендер бажаного стану, порт `SchemaEngine`, тінь, планувальник намірів.
*Avoid:* «рушій» без уточнення

**Двигун** — зовнішній каталожний diff-двигун (pg-delta) за портом `SchemaEngine`; адаптер — у designer.
*Avoid:* «рушій» (для pg-delta)
*See:* ADR-0004, ADR-0031

**Бажаний стан** — DDL, RLS, тригери й гранти, зрендерені зі знімка.

**Тінь** — чиста БД, у яку розгортається бажаний стан, щоб двигун побудував план «жива БД → тінь».
*Avoid:* «тіньова БД», «shadow»
*See:* ADR-0004

**Копія доказу** — копія цілі з даними, на якій план репетирується перед робочою базою.
*Avoid:* «тінь» (для копії), «co-located тінь»
*See:* ADR-0036

**Планувальник намірів** — шар над двигуном: перейменування за UUID, фази, кроки даних, класифікація змін.

**План схеми** — незмінний артефакт `<from>-<to>.plan.json` з класифікованими кроками.
*Avoid:* «план» без уточнення
*See:* ADR-0036

**Крок даних** — крок плану, що пише чи переписує дані.

**Послаблення** — крок, що розширює доступ або знімає інваріант; вимагає дозволу.

**Дозвіл** — явний дозвіл на послаблення чи видалення, прив'язаний до хешу плану.
*Avoid:* «permit», «права» (для дозволу)
*See:* ADR-0036

**Marker** — рядок поточного застосованого стану в схемі `simetra`: хеш знімка, відбиток каталогу, версія платформи.
*Avoid:* «маркер» (кирилицею), «мітка»

**Ledger** — журнал застосувань у схемі `simetra`, разом із записами промоції.
*Avoid:* «журнал» без уточнення

**Схема `simetra`** — закрита PG-схема платформи: лише стан і механізми, без даних тенанта.
*Avoid:* «системна схема» — допустимо як пояснення
*See:* ADR-0045

**Гейт прийому** — перевірка, що план «база ↔ тінь» після прийому порожній; без неї прийом не завершено.
*See:* ADR-0040

**Гейт дрейфу** — порівняння живої БД зі станом у marker.
*See:* ADR-0012

**Каталожний гейт** — порівняння каталогу, зокрема ACL, з бажаним станом.
*See:* ADR-0012

**Прийом** — операція: наявна схема описується як `CustomTable`, план «база ↔ тінь» порожній.
*Avoid:* «adoption», «прийнята форма»
*See:* ADR-0040

**Рукописна форма** — SQL синтетичного домену, написаний вручну як зразок прийнятої схеми.
*Avoid:* «прийнята форма»

**Прийнята таблиця** — таблиця наявної бази, описана як `CustomTable` після прийому.
*Avoid:* «прийнята форма», «таблиця боргу»

**Борг SQL** — дослівний SQL прийнятих таблиць поза закритими формами; ратчет дозволяє лише зменшувати.
*Avoid:* «борг» без уточнення, «sql-debt» у прозі
*See:* ADR-0033

**Закрита оболонка функції** — дозволена форма дослівної функції: мова, волатильність, `search_path`, без динамічного SQL.
*Avoid:* «оболонка» без уточнення

**Декларація функції** — запис у `<основа>.functions.json` поруч із SQL: хто викликає функцію застосунку (викликачі) і яку перевірку прав вона застосовує.
*Avoid:* «TS-декларація», «декларація сигнатури»
*See:* ADR-0092

**Викликачі** — призначення ролей у декларації функції; з них платформа виводить `EXECUTE` функції.
*Avoid:* «роль виклику»

**Названа перевірка** — поле `check` декларації функції: дія контракту прав над об'єктом — на рядку чи в скоупі, чий UUID дає параметр функції, або без цілі для об'єкта без носіїв.
*See:* ADR-0093

**Запобіжник виклику** — оператор `PERFORM` функції запобіжника першим у зовнішньому блоці тіла definer-функції; його виняток зупиняє виклик без права.
*Avoid:* «guard», «перевірка» без уточнення
*See:* ADR-0093

**Функція запобіжника** — згенерована `simetra.rights_require` чи `simetra.rights_require_scope`, яку кличе запобіжник виклику: умова RLS дії над рядком чи право з обсягом `any` у скоупі; відмова `42501`.
*See:* ADR-0093

**Промоція** — канонізація прийнятої `CustomTable` у вид 1С: мутація `promote` і план у БД однією операцією.
*Avoid:* «канонізація» (як назва операції), «конверсія»
*See:* ADR-0035, ADR-0039

**Мапінг промоції** — разовий вхід промоції «було → стало»; не метадані.
*Avoid:* «мапінг» без уточнення
*See:* ADR-0034

**Запис промоції** — файл `plans/<objectId>.promotion.json`, прив'язаний до хешів знімків.

**Клас конверсії** — клас кожного видалення в плані промоції; некласифіковане видалення — відмова.
*See:* ADR-0040

**Виключний перелік** — закритий перелік конструкцій класів A/B/C/D, які платформа приймає.
*Avoid:* «рамка» — допустимо як назва принципу
*See:* ADR-0033

**Одиниця промоції** — довідник чи документ без рухів з ТЧ або зв'язна група «документи ↔ регістри».
*See:* ADR-0038

**Гейт шляху запису** — відмова промоції об'єкта, у який застосунок пише напряму.
*See:* ADR-0042

**Крок міграції** — один сумісний крок розкладання зміни схеми («розширити» чи «звузити»).
*Avoid:* «фаза» (для кроку міграції)

**Розширити → звузити** — розкладання зміни схеми на сумісні кроки; звуження — коли старих клієнтів немає.
*Avoid:* «expand/contract», «фази»
*See:* ADR-0005

**Облік версій клієнтів** — мінімальна підтримувана версія клієнта, перезавантаження вкладки, `command.stale-client`.
*See:* ADR-0005

**Режим імпорту** — `write_mode = 'import'`: вимикає поведінку, не інваріанти.
*See:* ADR-0026

**Платформні служби** — регламентні завдання, надійні побічні дії, сповіщення, масові дії, сервіси БСП у базі.
*Avoid:* «сервіси БСП» — допустимо як пояснення
*See:* ADR-0029, ADR-0078

## Права

**Контракт прав** — згенерований із метаданих словник дій, граф вимог, набори прав і ролі; одна семантика для бази, команд і UI.
*Avoid:* «модель прав» (як синонім), «permissions»
*See:* ADR-0050

**Привілеї Postgres** — `GRANT`/`REVOKE` на об'єкти бази; не контракт прав.
*Avoid:* «права», «дозволи» (для `GRANT`)
*See:* ADR-0012

**Доступ інструмента** — вісь `files`/`database` у каталозі інструментів designer: що інструмент читає чи пише.
*Avoid:* «права», «дозвіл» (для доступу інструмента)

**Дія** — слово словника виду (`read`, `create`, `post`…) або UUID кастомної дії.
*Avoid:* «action» у прозі, «операція»

**Граф вимог** — `post ⇒ update`, `create/update/delete ⇒ read`, `X@any ⇒ X@own`; замикається fail-closed.

**Обсяг** — значення гранту: `any`, `own` чи вимір доступу.
*Avoid:* «скоуп права», «extent»
*See:* ADR-0052

**Вимір доступу** — обсяг за значенням поля; носій може бути шляхом посилань.
*See:* ADR-0052

**Роль** — набір грантів контракту прав: системний архетип у метаданих або кастомна роль-рядок.
*Avoid:* «роль» для ролей Postgres — там **роль БД**
*See:* ADR-0051

**Кастомна роль** — рядок «Ролей»: архетип + дельта `allow`/`deny`.
*See:* ADR-0051

**Набір прав** — іменована багаторазова група грантів (`include`).

**`fullAccess`** — єдиний обхід перевірок прав рівня ролі; не обходить межу тенанта й стелю агента.
*Avoid:* «адміністратор» (це звичайна роль)
*See:* ADR-0052

**Рівень призначення** — `everyUser`, глобальний, скоуп або контейнер.
*See:* ADR-0053

**Контейнер** — об'єкт, на який призначається контейнерна роль.

**`rootCreator`** — позначка ролі скоупу: створення кореня призначає її творцю в тій самій транзакції.
*See:* ADR-0053, ADR-0070

**Запобіжник** — платформна перевірка адміністрування прав (⊆, `last-full-access`, `role-in-use`) на COMMIT.
*Avoid:* «guard», «ескалація» (це клас відмови)
*See:* ADR-0056

**Проєкція прав** — згенеровані функції бази, з яких читають RLS і ядро команди.
*Avoid:* «таблиця прав»
*See:* ADR-0050

**Версія прав** — лічильник на скоуп; сигнал інвалідації клієнтського кешу, не умова безпеки.
*See:* ADR-0050

**RLS-шаблон** — межа тенанта `RESTRICTIVE` + по одній `PERMISSIVE` політиці на обсяг; запис — політики й ядро з тими самими предикатами.
*See:* ADR-0054

**Act-as** — токен, що діє від імені користувача: `sub` — користувач, claim `act` — агент.
*See:* ADR-0055

**Стеля агента** — опційний AND-предикат до прав користувача для агента.
*See:* ADR-0055

**Аналіз прав** — «що може / хто може / чому видно» над тими самими функціями.

**Режим обслуговування** — привілейований шлях адміністрування прав (`rights-maintenance`, лише CLI) з журналом.

**Користувачі** — системний довідник платформи без скоупу, один на проєкт; корінь виду скоупу `user`.
*Avoid:* «таблиця користувачів» (це таблиця провайдера), «учасник» (це членство)
*See:* ADR-0046

**Прив'язка облікового запису** — рядок `simetra.identities` «провайдер + subject → користувач».
*Avoid:* «ідентичність» без уточнення
*See:* ADR-0046

**Провізія** — створення користувача однією ідемпотентною `simetra.provision_user`; тригером або JIT.
*See:* ADR-0047

**Недійсний користувач** — `invalid`: вхід заборонено, посилання живі; видалення облікового запису робить користувача недійсним.
*See:* ADR-0048

**Контракт сесії** — `request.jwt.claims` + `simetra.current_user_id()`, однаковий в обох профілях.
*Avoid:* `auth.uid()` у контракті платформи
*See:* ADR-0049

## Сервер і команди

**Команда** — запис через `runCommand`: згенерована (create, update, post…) або явна.
*Avoid:* «мутація» (це клієнтська сторона), «RPC»
*See:* ADR-0024

**Команда CLI** — підкоманда бінарника `simetra` (`compile`, `introspect`, `init`).
*Avoid:* «команда» без уточнення (це запис через `runCommand`)

**Операція** — вхід T0 з полем `action` (`create`, `update`, `markDeletion`).

**`runCommand`** — єдиний вхід T3 на запис: claims → `SET LOCAL ROLE simetra_command` → фази → COMMIT.
*See:* ADR-0024

**Ядро команди** — згенерована SQL-функція `SECURITY INVOKER` (`<t>_save`…), що перевіряє право тими самими предикатами, що й RLS.
*Avoid:* «ядро» без уточнення, «kernel/core» у прозі
*See:* ADR-0067

**Фаза команди** — один виклик ядра зі своїм контекстом `simetra.command`; пакет — кілька фаз однієї транзакції.
*Avoid:* «фаза» без уточнення

**Хук** — функція модуля об'єкта `beforeWrite` чи `onWrite` у транзакції команди; без сирого SQL і зовнішнього I/O.
*Avoid:* «тригер» (для хука), «обробник» без уточнення
*See:* ADR-0071

**Каталог рантайму** — артефакт `runtime-catalog.json` з `compile --out`; звіряється хешем з marker.
*See:* ADR-0066

**Рантайм команд** — серверний `CommandRuntime` з пулом `simetra_runtime`.
*Avoid:* «рантайм» без уточнення

**Роль БД** — роль Postgres: `simetra_runtime` (вхід), `simetra_command` (запис), роль запиту провайдера.
*Avoid:* «роль» без уточнення
*See:* ADR-0068, ADR-0087

**Роль запиту** — роль провайдера для серверного читання під RLS (`authenticated` у supabase, `simetra_user`/`simetra_anon` у postgres).

**Домен довіри пулу** — код host-а, що володіє пулом `simetra_runtime`; межа — довіра, не база.
*See:* ADR-0068

**Серверне читання** — читання з прямого з'єднання під роллю запиту в `READ ONLY` тим самим будівником запитів.
*See:* ADR-0058

**Квитанція** — рядок схеми `simetra` з `mutationId`, хешем пакета й результатом без значень; дає ідемпотентність `run`.
*See:* ADR-0082

**Конверт** — відповідь Server Function `{ok, value} | {ok: false, error}`: помилка як значення.
*See:* ADR-0065

**Форма передачі** — фізична форма даних між T4 і T3 (UUID об'єкта, фізичні колонки); логічна — лише в процесі.
*Avoid:* «wire form», «дріт»
*See:* ADR-0065

## Дані клієнта (T4)

**Ядро даних T4** — власний рушій клієнтських даних: сесія, сховища, реєстр підмножин, журнал мутацій.
*Avoid:* «рушій даних», «рушій колекцій», «фасад», «ядро» без уточнення
*See:* ADR-0079

**Рантайм даних** — `createDataRuntime`: одна сесія ядра на сесію користувача.
*Avoid:* «рантайм» без уточнення, «тримач»
*See:* ADR-0074

**Сесія ядра** — `subject`, епоха й сигнал скасування; `dispose()` робить недійсними всі токени.
*Avoid:* «сесія» без уточнення (це й сесія автентифікації)

**Область запису** — `commit(fn, token)`: єдина точка змін сховищ ядра.
*Avoid:* «Scope», «скоуп» (для області запису)

**Сигнал скасування** — `AbortSignal` сесії ядра; скасовує запити сесії.
*Avoid:* «сигнал» (для `AbortSignal`)

**Токен покоління** — токен сесії, підмножини чи спроби; захищає від старого покоління запиту.

**Епоха сесії** — монотонний лічильник сесії ядра; «читання після позначки» = `readEpoch ≥ markEpoch`.
*Avoid:* «епоха» без уточнення

**Історію втрачено** — стан каналу сигналів, коли сервер сигналів не пам'ятає пропущених повідомлень; клієнт перечитує дані.
*Avoid:* «нова епоха» (для сервера сигналів)
*See:* ADR-0083

**Епоха версій** — відбиток бази й послідовності, у межах якого порівнюються версії рядків.
*Avoid:* «епоха» без уточнення
*See:* ADR-0082

**Надгробок** — позначка ключа з епохою читання після видалення чи `purge`; пізня відповідь не воскрешає видалене.
*Avoid:* «tombstone»

**Сховище об'єкта** — `ObjectStore`: рядки шапки за ключем для будь-якого відбору.
*Avoid:* «колекція на зріз»
*See:* ADR-0079

**Сховище ТЧ** — `SectionStore`: рядки ТЧ на (власник, ТЧ) з `ownerVersion`.
*See:* ADR-0076

**Підмножина** — одиниця читання й власності рядків: форми `keys`, `card`, `section`, `full`, `window`.
*Avoid:* «колекція», «зріз»

**Вигляд** — опис вибірки `view(spec)` над підмножинами, як його бачить UI.
*Avoid:* «хендл», «вид» (для вибірки)

**Стратегія списку** — `full` чи `window` за метаданими `residency`.
*Avoid:* «residency» у прозі
*See:* ADR-0075

**Власність рядка** — рядок живе, поки його тримає вигляд, журнал мутацій чи етап `include`.
*Avoid:* «refs», «утримання» — допустимо як пояснення
*See:* ADR-0079

**Журнал мутацій** — журнал власних незавершених змін користувача з індексом за ключем.
*Avoid:* «overlay»

**Мутація** — одна зміна користувача = один виклик `run` = одна транзакція; спроба несе `mutationId`.

**Політика дії** — `await` (значення змінюється після відповіді) чи `predict` (точне передбачення одразу); задає генератор.
*See:* ADR-0081

**Стан рядка** — `synced`, `pending`, `failed`, `conflict`, `unknown`, `stale`, `removed`.
*See:* ADR-0080

**Стан вибірки** — `loading`, `ready`, `refreshing`, `hasNewRows`, `needsRefresh`, `error`, `purged`.
*See:* ADR-0080

**Правило стабільності** — сигнал і перечитування не змінюють склад і порядок видимого списку; лише дія користувача.
*Avoid:* «без мерехтіння» як назва правила
*See:* ADR-0080

**Виняток безпеки** — втрата доступу прибирає дані негайно (`purge`), окремо від правила стабільності.
*See:* ADR-0080

**Заборонений кадр** — кадр, який не має побачити користувач: скелет після даних, спалах, відкат значення, перестановка, стрибок.
*Avoid:* «мерехтіння» (як термін)

**Оракул** — браузерний тест заборонених кадрів і мережевих бюджетів у Chromium і WebKit.
*Avoid:* «оракул» для серверної перевірки наявності
*See:* ADR-0086

**Модельний тест ядра** — property-based тест ядра даних T4 на переплетеннях подій.
*See:* ADR-0086

**Умовне читання** — запит з `known` (епоха, ключі, версії): незмінний рядок приходить позицією, без тіла.
*Avoid:* «маркер»
*See:* ADR-0085

**Лінивий реквізит** — `load: lazy`: не віддається списочною формою, дочитується при показі.
*See:* ADR-0085

**`include`** — етап вигляду: цілі посилань стають підмножиною `keys`.

**Клієнтський каталог** — проєкція каталогу рантайму + контракт прав + ознака `signal`.

**`kernelHash`** — хеш форми ядра команди; несумісність — `command.stale-client`.
*See:* ADR-0066

**Застарілий клієнт** — збірка клієнта, несумісна з базою: `isStale`, банер, запис вимкнено.
*Avoid:* «stale» (для клієнта)
*See:* ADR-0066

**Кеш прав клієнта** — знімок власних фактів + обчислювач контракту; відповіді `true`/`false`/`unknown`.
*See:* ADR-0073

**Сигнал** — realtime-повідомлення без даних: `change`, `invalidate`, `rights`.
*Avoid:* «подія», «broadcast», «poke»
*See:* ADR-0072, ADR-0083

**Сигнальний об'єкт** — об'єкт, зміни якого шлють сигнали.

**Канал** — пара (скоуп, UUID об'єкта); авторизує `simetra.signal_topic_allowed`.
*Avoid:* «топік»
*See:* ADR-0072

**Outbox** — `simetra.signal_outbox`: рядок сигналу в транзакції команди; споживач Centrifugo публікує після COMMIT.
*See:* ADR-0083

**Приймач сигналів** — частина ядра, що збирає сигнали пачками й вирішує, що перечитати.

**Збіжність** — гарантія, що показ наздоганяє базу перечитуванням без гарантії доставки сигналів.
*See:* ADR-0083

**Чернетка форми** — редагування картки з базовою версією й ревізіями; поза ядром даних.

**Знімок показу** — зафіксований стан ядра, за яким клієнт показує дані, поки не прийшла відповідь; ключ — `subject`, `catalogHash`, `rightsVersion`.
*Avoid:* «знімок» без уточнення

**SSR-знімок** — знімок ядра в HTML з тотожністю `subject`, `catalogHash`, `rightsVersion`.
*See:* ADR-0074

**Адаптер джерела** — порт T0 `SourceAdapter`: Server Function або PostgREST.
*See:* ADR-0058

## Інтерфейс і host

**Host** — застосунок на TanStack Start, що збирає модулі й тримає Server Function, пули, сесію і SSR.
*Avoid:* «хост» (кирилицею, для застосунку), «host-фреймворк»
*See:* ADR-0010, ADR-0089

**Шаблон host-а** — працездатний застосунок у пакеті шаблону застосунку.
*See:* ADR-0089

**Хост сторінки** — компонент T5 без власного стилю (`ListHost`, `CardHost`, пікер, діалог); завжди з уточненням.
*Avoid:* «хост» без уточнення

**Маршрут з одного рядка** — `entityListRoute` / `entityCardRoute` T6: сторінка як один рядок з параметрами.

**Адаптер навігації** — інтерфейс T5 `NavigationAdapter`; реалізація на TanStack Router — у T6.
*See:* ADR-0010

**Тонкий зріз** — вертикаль «браузер → Server Function → T3 → Postgres → ядро T4 → хост сторінки → маршрут» зі SSR, без візуальної мови.
*Avoid:* «зріз» без уточнення
*See:* ADR-0077

**Візуальна мова** — токени, метрики, композиції й рух T5.
*Avoid:* «вигляд», «дизайн», «тема» (для всієї мови)
*See:* ADR-0064

**Токен оформлення** — змінна CSS `--color-<група>-<роль>`, `--spacing-*`, `--radius-*`; компоненти читають лише токени.
*Avoid:* «токен» без уточнення (це й токен покоління, токен каналу)
*See:* ADR-0064

**Шар тем** — база платформи → тема модуля → бренд тенанта → режим користувача.
*See:* ADR-0064

**Візуальний референс** — зовнішній зразок, який база візуальної мови повторює майже повністю без копіювання коду.
*See:* ADR-0064

**Правила екстраполяції** — правила вигляду для поверхонь без аналога в референсі; чекають ухвали власника.

## Профілі провайдера

**Профіль провайдера** — набір механізмів поза ядром Postgres: `supabase` або `postgres`; поле `database.provider`.
*Avoid:* «профіль» без уточнення, «провайдер» (для профілю)
*See:* ADR-0057, ADR-0084

**Профіль користувача** — рядок довідника «Користувачі» з даними людини; не профіль провайдера.
*Avoid:* «профіль» без уточнення

**Профіль інтеграції pg-delta** — набір правил двигуна, які вирізають об'єкти провайдера з плану.
*Avoid:* «профіль» без уточнення

**Обов'язкова база Postgres** — мінімум, що платформа вимагає від бази в будь-якому профілі: Postgres 17 і contrib.
*Avoid:* «ядро платформи»
*See:* ADR-0028

**Пресет провайдера** — фіксований опис схем і ролей провайдера; задає межу гейта й засів тіні.

**Провайдер ідентичності** — сервіс автентифікації (Supabase Auth, Better Auth, Clerk).
*Avoid:* «провайдер» без уточнення
*See:* ADR-0062

**Пресет ідентичності** — запис T0 `PROVIDER_IDENTITY_SOURCES`: таблиця облікових записів, ключ, ознаки анонімності.
*See:* ADR-0062

**Сервер сигналів** — зовнішній сервер доставки сигналів; перший адаптер — Centrifugo.
*See:* ADR-0083, ADR-0088

**Сховище файлів** — порт `FileStore` для байтів файлу; файл — рядок об'єкта під RLS.
*Avoid:* «Storage» (це Supabase Storage)
*See:* ADR-0060

**Прибирання файлів** — фонове `reconcileFiles`: видаляє байти без рядка.
*Avoid:* «звірка файлів»

**Роль-власник** — `simetra_owner` з `BYPASSRLS`, роль застосування плану в профілі postgres.
*See:* ADR-0087

**Кластер на застосунок** — у профілі postgres прод-кластер тримає одну базу застосунку.
*See:* ADR-0087

**Гість** — анонімна сесія: читає як `simetra_anon` лише `publicRead: anon`, команд не має.
*Avoid:* «анонім» — допустимо як пояснення
*See:* ADR-0087

**Стек розробки** — локальний стек профілю (docker compose `postgres` або Supabase CLI), що запускається лише `pnpm db:*`.
*See:* ADR-0063

**Тег прогону** — мітка DB-прогону в іменах об'єктів і `application_name`; за ним guard прибирає своє.

## Процес розробки

**Знімок прав** — відбиток контракту прав, який клієнт кешує разом із `rightsVersion`.
*Avoid:* «знімок» без уточнення

**Перший випуск** — набір підпроєктів П0…П6, що складає перший випуск платформи; не віха.
*Avoid:* «перша віха»
*See:* ADR-0090

**Віха** — результат із критерієм «що показати»; GitHub milestone; закривається.
*Avoid:* «фаза», «етап», «перша віха» (для першого випуску)
*See:* ADR-0090

**Частина системи** — область платформи як мітка GitHub; не закривається.
*Avoid:* «підпроєкт», «модуль»
*See:* ADR-0090

**Спека** — дизайн-документ блоку роботи в `docs/superpowers/specs/`; issue GitHub.
*Avoid:* «специфікація», «дизайн-док»
*See:* ADR-0090

**Блок** — одиниця реалізації спеки: sub-issue спеки, свій план і PR.
*Avoid:* «блок» для ярусу («блок чистоти»), «частина» (для блоку)
*See:* ADR-0090

**Підпроєкт П0…П6** — історична назва групи спек (П0 спайки … П6 конфігуратор); не одиниця статусу.
*Avoid:* «фаза», «етап»; статус за П-номером
*See:* ADR-0090

**Частина П4-A…F** — історична назва підспеки П4 (A запис, B дані клієнта, C документ, D host, E модулі, F агенти).

**Спайк** — одноразова проба з хартією і бінарним критерієм на гілці `spike/*`, що не зливається в `main`.
*See:* ADR-0013

**План реалізації** — самодостатній план одного блоку для виконавця.
*Avoid:* «план» без уточнення

**Архітектор задачі** — сесія, яку власник назвав архітектором блоку; ухвалює технічні рішення замість власника.
*Avoid:* «головна архітекторка» як роль у спеках — допустимо як ім'я ролі

**Звірка першого споживача** — приватна перевірка платформи на схемі першого споживача поза репо.
*Avoid:* «звірка» без уточнення

**Технічний борг** — відкладена робота проєкту з реєстром у документі боргу.
*Avoid:* «борг» без уточнення

**Гейт** — обов'язкова перевірка, що блокує злиття чи застосування; вживається лише з назвою: гейт прийому, дрейфу, каталожний, шляху запису.
*Avoid:* «гейт» без уточнення

**Гейти CI** — перевірки `format:check`, `lint`, `typecheck`, `test` і `metadata:check`, які CI запускає перед злиттям.
*Avoid:* «гейт» для окремого гейта платформи

**Межа гейта** — набір схем і ролей, який гейт порівнює; задає пресет провайдера.
*Avoid:* «скоуп гейта»
