# Шлях метаданих: від файлів до бази

Механізми й рішення — [спека П2](../superpowers/specs/2026-09-28-p2-metamodel-compiler-design.md)
§3 (ідентичність, файли), §8 (компілятор), §9 (інтроспекція каталогу) і
[платформна спека](../superpowers/specs/2026-09-24-simetra-platform-design.md)
§3.4, §5, §6. Тут — як частини з'єднані в коді зараз.

```
metadata/*.meta.json, *.sql, *.module.ts
        │  читання диска — лише в @simetra/designer (src/io)
        ▼
T1 compile(files)  ──►  діагностика (file:line:col, коди правил)
        │  без помилок
        ▼
CompiledModel: логічна модель з UUID, фізичний знімок, SQL-одиниці,
               посилання, контракти, хеш
        │
        ├─► T1 операції (fix, create, add, rename, delete): нова мапа файлів
        │      → повторна компіляція результату → запис лише при ok
        ├─► T1 кодоген і JSON Schema
        └─► T2 рендер бажаного стану → DDL
                 │
                 ▼
         T2 порт SchemaEngine  ◄── адаптер pg-delta (@simetra/designer)
                 │  extract бази, план між базою й тінню
                 ▼
         T2 звірка бажаного стану з базою
                 │  модель каталогу
                 ▼
         T2 зворотна генерація → мапа файлів CustomTable, PgEnum, *.sql
                 → компіляція результату (round-trip §9)
```

## 1. Файли

Тека `metadata/` проєкту — єдине джерело правди: JSON-файли об'єктів за
теками видів, дослівні `*.sql` і модулі поведінки. Ідентичність — UUID, а не
ім'я; `physicalName` призначається один раз і не змінюється (спека П2 §3).
Канонічний вигляд файлу дає власний форматер компілятора, а `$schema` вказує
на JSON Schema встановленого пакета `simetra` через `node_modules/simetra`.

## 2. Компілятор (T1)

`compile()` — чиста функція над мапою «шлях → текст» (`packages/simetra/src/compiler/compile.ts`).
Стадії 1–5 (файл, ідентичність, модель, цілісність, зв'язок із модулями)
описано в спеці П2 §8.2; код — `compiler/stages/` і `compiler/pipeline.ts`.
Правило «без напівмоделі»: модель повертається лише без помилок, інакше —
діагностика з місцем у файлі.

Окремий результат стадії 2 — **індекс посилань**: кожне посилання за іменем
(значення, ключ, токен у виразі, маркер у `.sql`) з точним місцем у файлі. На
ньому стоять перейменування з каскадом і перевірка залежностей при видаленні.

## 3. Операції над метаданими (T1)

`compiler/operations/` — `fixFiles`, `createObject`, `addElement`,
`renameElement`, `deleteElement`: чисті функції «мапа файлів → зміни +
діагностика результату». Мутації вимагають чистої компіляції входу, а `ok` —
це чиста компіляція **результату**; лише тоді обгортка пише зміни. Входи — Zod-
схеми в `compiler/operations/inputs.ts`; їх же використовує каталог
інструментів designer, тож вхід однаковий у CLI, MCP і тестах.

## 4. Рендер і двигун схеми (T2)

- **Рендер** (`schema/render/`) перетворює фізичний знімок і SQL-одиниці на
  DDL бажаного стану. Бази не потребує.
- **Порт `SchemaEngine`** (`schema/engine/port.ts`) — контракт двигуна:
  extract бази в модель каталогу Simetra, план між двома станами, тінь.
- **Адаптер** порту на pg-delta і читачі бази живуть у
  `@simetra/designer` (`packages/designer/src/schema-engine/`) і передаються
  в порт ззовні: рантайм застосунку двигуна не тягне.
- **Звірка** (`compareWithDesired`) розгортає бажаний стан у тінь і порівнює
  extract тіні з extract бази; межа керування — профіль провайдера
  (`schema/engine/provider/`).

## 5. Зворотна генерація (T2)

`reverseGenerate` (`schema/reverse/`) — чиста функція над моделлю каталогу
порту й наявною текою: без бази й диска. Вихід — підсумкова мапа теки після
злиття, зміни відносно наявної й діагностика; змін немає за будь-якої
помилки. Інваріанти (типи, ключі ідентичності, розкладка одиниць) — спека П2
§9. Підключення до бази, тінь і запис файлів складає `@simetra/designer`.
Повноту ланцюжка «extract → зворотна генерація → компіляція → рендер → тінь»
тримає DB-тест round-trip з незалежним читачем `pg_catalog`
(`packages/designer/src/schema-engine/__tests__/round-trip.db.test.ts`).

План БД і застосування до бази — П3 ([ROADMAP](../ROADMAP.md)).
