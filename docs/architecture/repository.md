# Мапа репо

## Пакети workspace

Перелік — `pnpm -r ls --depth -1` або `packages/*/package.json`.

### `simetra` — рантайм і ядро (`packages/simetra`)

Флагманський пакет, який застосунок споживача ставить як залежність. Код
розкладено за ярусами, імпорт іде лише вниз (платформна спека §3.1):

| Ярус | Тека `src/` | Що тримає зараз |
| --- | --- | --- |
| T0 | `model` | Zod-схеми метаданих, реєстр видів, фізичний знімок і правило фізичних імен; єдина runtime-залежність — `zod` |
| T1 | `compiler` | компілятор над мапою файлів (стадії, діагностика, знімок і хеш, кодоген, JSON Schema) і чисті операції над метаданими (`operations/`); без Node API |
| T2 | `schema` | рендер бажаного стану в DDL, порт `SchemaEngine`, модель каталогу, звірка бажаного стану з базою, профіль провайдера |
| T3–T6 | `server`, `data`, `ui`, `shell` | заготовки ярусів; наповнюються з П4 |

Межі ярусів і фреймворку тримає `packages/simetra/eslint.tier-zones.js` з
негативним тестом `packages/simetra/test/tier-boundary.test.ts`. Там само
правило: продакшн-вихідники `simetra` не імпортують `pg` і
pg-delta — двигун схеми не входить у рантайм застосунку
([спека designer](../superpowers/specs/2026-10-02-simetra-designer-design.md),
Д5).

Згенеровані JSON Schema метаданих — `packages/simetra/schemas/`; файли
метаданих посилаються на них через `$schema`.

### `@simetra/designer` — інструменти розробника (`packages/designer`)

Окремий пакет з бінарником `simetra`: інструменти над текою метаданих і
адаптер двигуна схеми. У застосунок він не потрапляє — споживач ставить його як
dev-залежність. Устрій — [designer.md](designer.md).

## Поза пакетами

| Місце | Що це |
| --- | --- |
| `examples/reference/` | синтетичний референсний домен: метадані (`metadata/`), очікувані результати прийому (`accepted/`); на ньому стоять тести компілятора, рендера, звірки й скіла |
| `legacy/` | заморожений прототип: читати можна, збирати, тестувати й імпортувати — ні (`AGENTS.md`, «Target architecture vs. the prototype») |
| `supabase/` | локальний стек Postgres для `pnpm test:db` (запуск лише через `pnpm db:*`) |
| `scripts/` | службові скрипти репо, зокрема гард якорів документації |
| `docs/` | BRD, ROADMAP, спеки й плани (`superpowers/`), дослідження (`research/`), ця тека |
| `.agents/skills/`, `.claude/` | харнес агентів **розробки платформи**; скілів для споживачів тут немає |

## Гейти

Команди й правила — `AGENTS.md`, «Commands and gates». Коротко про те, що
тримає архітектуру:

- `pnpm lint` — лінт-зони ярусів і фреймворку (зокрема зона студії в
  `packages/designer/eslint.zones.js`);
- `pnpm test` — юніт-тести обох пакетів, разом із тестом прикладів скіла
  споживача;
- `pnpm test:db` — тести проти локального Postgres: рендер і розгортання
  (`simetra`), адаптер двигуна схеми й звірка на корпусі (`@simetra/designer`);
- `pnpm metadata:check` — `simetra compile --all` над кожною текою метаданих
  репо; pre-commit запускає його з `--staged` (компілюється вміст індексу Git),
  CI — без нього.
