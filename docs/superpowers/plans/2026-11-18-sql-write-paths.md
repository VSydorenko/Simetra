## Мета, архітектура, спека

**Мета.** SQL застосунку (кожен `.sql` проєкту, борг включно) не пише таблиці
виду, таблиці джерела ідентичностей провайдера й відношення схеми `simetra`
(Правило 1) жодним шляхом і не виконує текст SQL через жодне посилання на
функцію. Обидва приклади issue — помилки з кодом: подання без
`security_invoker` над такою таблицею з записом для ролі API; агрегат, чия
складова виконує текст SQL. Спека прав отримує таблицю шляхів, а кожен її
рядок — тест, що червоніє без правила.

**Архітектура.** Два судді, кожен — одна функція над усіма формами.
(1) **Шляхи запису.** `compiler/sql/write-paths.ts` отримує один перелічувач
`writePaths`: для кожної одиниці — шляхи запису (форма, ціль, ролі, що
можуть ним писати). Форми — у Р1. Правило 1, гейт шляху запису промоції й
`rights.snapshot-exempt-writer` стають фільтрами цього переліку за своєю
множиною цілей і ролей; другого обходу немає. (2) **Посилання на функцію.**
Кожне посилання на функцію в одиниці поза тілом функції чи процедури —
виклик, `EXECUTE FUNCTION` тригера, складова агрегату, `DEFAULT`/`CHECK`
домену, умова `WHEN` — судить дозвільний перелік виразів
(`expressionCallProblem`); тіло — перелік тіла (`callsSqlText`), де
кваліфіковане невідоме ім'я теж fail-closed. Форми, які могли б дати шлях
повз ці два судді (`CREATE RULE`, членство ролей, оператори, приведення,
`ALTER … OWNER`), відмовляє закритий перелік класів `classify()`; блок
закріплює це таблицею тестів.

**Спека.** Спека прав §6.1 (Правило 1, таблиця шляхів — задача 0), §5.3
(одиниці-вирази), §7 (`rights.snapshot-exempt-writer`); платформна §6.7
(гранти, подання без `security_invoker`); спека промоції §8 (гейт шляху
запису).

## Глобальні обмеження

- Без поступок сумісності (рішення власника 2026-11-18): прийнятий борг
  судиться тим самим правилом, помилкою; ні винятків для `sql-debt.json`, ні
  попереджень замість помилок.
- Наявні тести лишаються зеленими без послаблення очікувань. Тест, що
  червоніє через нове правило, змінюється лише так, щоб фікстура пройшла
  правило (кваліфікація імені, `security_invoker`), і це названо в звіті
  задачі. Послаблення оракула — розвилка до архітекторки.
- Повідомлення діагностик — англійською в `compiler/messages.ts`, код — у
  переліку `compiler/diagnostics.ts`. Тести перевіряють коди й параметри, не
  текст.
- Нові тести — за скілом `writing-tests`: таблиці випадків, спільні
  будівельники фікстур, рівень unit, крім задачі 5.
- Кожна нова гілка суддів — fail-closed: невідоме значення опції, ім'я без
  схеми, ціль поза знімком — як найгірший випадок.

## Рішення

| # | Рішення | Вплив на спеку |
| --- | --- | --- |
| Р1 | **Один перелічувач шляхів запису** `writePaths(units, ctx)` у `write-paths.ts`: `{ unit, form, target, roles }`, форми `functionBody`, `view`, `grant`, `defaultPrivileges`, `policy`, `trigger`. Правило 1 (`checkKindTableVerbatim` і `debtPredicate`), гейти промоції (`writePathProblems`, `debtWritesProblems`) і `snapshotExemptWriters` фільтрують його. Наявні `bodyKindTable`, `kindTableOf`, `viewWrittenTable`, `writeGrantPaths` стають його частинами або видаляються, без обгорток. Наслідок: гейт промоції бачить і запис крізь подання (зараз не бачить). | спека прав §6.1 (таблиця шляхів), спека промоції §8 — рядок про подання (задача 0) |
| Р2 | **Хто «може писати» крізь подання чи грант.** `PUBLIC` — лише явним грантом (у таблиць, на відміну від функцій, `PUBLIC` типових привілеїв не має). Роль API (`user`, `anonymous`, `service` з `PROVIDER_API_ROLES`) — без явного відкликання запису: типові привілеї провайдера не моделюються (Supabase дає ролям API `ALL` на таблиці `public`), fail-closed як у класі Р30. Роль команд і будь-яка інша названа роль — явним грантом. Крім того, ADP застосунку `IN SCHEMA s` з записом на `TABLES` (дозволене лише ролям API, Р4) робить їх письменниками кожного подання схеми — незалежно від порядку операторів (рушій ставить ADP перед вузлами схеми, `defaultPrivilegeEdges`). Власник не рахується. Одна функція привілеїв для `select`, `execute` і запису: `privilegedRoles` переноситься з `definer-reads.ts` (після Д1) і отримує вид привілею «запис» (`insert`/`update`/`delete`/`truncate`/`trigger`/`all`, зокрема поколонковий; `TRIGGER` — бо його власник створює тригер `BEFORE`, що змінює `NEW` чужого запису). | спека прав §6.1 |
| Р3 | **Запис крізь подання** — шлях, коли подання моделі (а) автооновлюване за деревом (одне відношення у `FROM`; без `WITH`, `DISTINCT`, `GROUP BY`, `HAVING`, `LIMIT`/`OFFSET`, операцій множин, агрегатів, віконних і множинних функцій у списку вибору — правила Postgres), (б) без `security_invoker` (невідоме значення — без нього, `securityInvoker`), (в) з роллю за Р2. Ціль — `writtenKindTable` (рекурсія крізь вкладені подання без перевірки їхньої оновлюваності — fail-closed). Подання з `security_invoker` шляхом не є: Postgres перевіряє гранти й RLS базового відношення у викликача. Вкладене подання без `security_invoker` під ним судиться як окремий вхід. Підказка виправлення: `security_invoker = true` або відкликання запису. Подання, що не є автооновлюваним, шляхом не є: `CREATE RULE` відмовлено, а тіло тригера `INSTEAD OF` судить форма `functionBody`. | спека прав §6.1; платформна §6.7 — посилання на §6.1 (задача 0) |
| Р4 | **ACL того, що створює платформа, належить платформі (модельна зміна, на затвердження).** Три раунди аудиту знаходили той самий клас: привілей застосунку досягає об'єкта, який платформа створює пізніше чи відкликає лише в `PUBLIC` і ролей API (`tableGrants`, `executeGrants`, `sequenceRevokes`). Одне правило: (а) **глобальне ADP** (без `IN SCHEMA`) у SQL застосунку — помилка за будь-якого класу об'єктів (`TABLES`, `FUNCTIONS`/`ROUTINES`, `SEQUENCES`, `TYPES`, `SCHEMAS`) і будь-якого отримувача: воно досягає й `simetra` (`simetra.identities` без RLS, функції `simetra.provision_user`…); (б) **ADP `IN SCHEMA s`** може називати лише ролі API — кожен об'єкт, що його платформа створює в схемі застосунку, відкликає всі привілеї в ролей API (задача 1 доводить тестом для таблиць виду всіх ролей таблиць, згенерованих функцій і послідовностей); `PUBLIC`, роль команд чи інша роль — помилка; `FOR ROLE` не звужує (fail-closed); (в) **явний грант** на ціль Правила 1 (таблиця виду, джерело ідентичностей, послідовність, яку створює платформа) з привілеєм запису за Р2 — помилка будь-якій ролі; ціль — за `kindTableNamed` (некваліфіковане fail-closed); одиниця з `sql.generated-grant` другої діагностики не отримує. Форма — `defaultPrivileges` / `grant`. Для промоції й винятків знімка форми лишаються, як зараз. Інваріант: ролі, крім ролей API, отримують привілеї на об'єкти платформи лише від генератора. | спека прав §6.1; платформна §6.7 — рядок «ACL об'єктів платформи» (задача 0) |
| Р4б | **Зміна послідовності платформи з тіла.** `setval`/`nextval` у тілі дозволені (`isBuiltin` охоплює клас виключень), тож тіло, зокрема тригерна `SECURITY DEFINER`, змінює послідовність `simetra` чи таблиці виду від власника. Форма Правила 1 `sequence`: виклик `setval`/`nextval` з літералом, що називає послідовність у `simetra` чи послідовність, яку створює платформа, — помилка; нелітеральний аргумент — помилка (fail-closed). | спека прав §6.1 |
| Р4а | **Тригер і політика на джерелі ідентичностей.** `kindTableOf` судить тригери й політики лише над таблицями виду, тож тригер `BEFORE` на `auth.users` (чи `better_auth.user`), що змінює `NEW`, пише джерело без DML. Над таблицею джерела ідентичностей дозволено лише тригер `AFTER` (форма підписок платформи); `BEFORE`, `INSTEAD OF` і будь-яка дослівна політика — `sql.kind-table-verbatim`, форми `trigger` / `policy`. | спека прав §6.1 |
| Р5 | **Один код Правила 1.** Нові форми — значення `form` наявної `sql.kind-table-verbatim` (`view`, `grant`); параметри `table`, `roles`, `line`. Помилка в будь-якому файлі, борг включно; `debtPredicate` виключає одиницю з помилкою Правила 1 через той самий перелічувач, тож ратчет не рахує її боргом. | немає |
| Р6 | **Посилання на функцію поза тілом — дозвільний перелік виразів.** `EXPRESSION_CLASSES` = подання, матеріалізоване подання, політика, **агрегат, тригер, домен** (у домені — лише `DEFAULT`: `CHECK` домену судить суворіше правило голів `checkDomainChecks`, друга діагностика була б шумом). `unitCalls` уже повертає `FuncCall`, `EXECUTE FUNCTION` тригера й складові агрегату; виконавець перевіряє, що й `WHEN` тригера та `DEFAULT` домену (задача 3). `scope.models` включає агрегати моделі (агрегат тепер судиться сам). Код — наявний `sql.expression-call-not-allowed`, помилка скрізь, борг включно. Окремий шлях `aggregateWrite` і `AGGREGATE_FUNCTION_OPTIONS` у `command-context.ts` видаляються; `judgedElsewhere` (`closed-forms.ts`, після Д1) відносить форми виклику всіх класів-виразів до цього судді. Перелік опцій-складових агрегату — одна константа (`dependencies.ts`), її читає й `definerComponent` (`definer-reads.ts`, після Д1). | спека прав §5.3 — перелік одиниць-виразів (задача 0) |
| Р7 | **Тіло: кваліфіковане невідоме ім'я — виконання тексту SQL.** `sqlTextCall` зараз судить кваліфікований виклик лише в схемі провайдера, тож функція розширення в схемі застосунку (боргове `CREATE EXTENSION dblink` без `SCHEMA`) у тілі не судиться. Нове: кваліфікований виклик, що не є вбудованою `pg_catalog`, функцією, процедурою чи агрегатом моделі, згенерованою функцією, функцією платформи (її судить `sql.platform-function-call`) чи поіменною функцією провайдера, — `dynamicText`. Множини — ті самі, що в `ExpressionScope`: один збирач області для обох суддів. | спека прав §5.3 — одне речення (задача 0) |
| Р7а | **Розширення лише в схемах провайдера — помилка, не попередження. На затвердження архітекторки.** Postgres обирає перевантаження за аргументами, тож збіг імені з функцією моделі не робить виклик безпечним (`command-context.ts`, коментар `sqlTextCall`): боргове `CREATE EXTENSION dblink` без `SCHEMA` ставить `public.dblink_exec(text, text)`, і виклик `public.dblink_exec('…', '…')` поруч із моделевою `public.dblink_exec(int)` дістанеться розширення. Сигнатур компілятор не розв'язує. Тому `sql.debt-extension-schema` стає помилкою: розширення поза схемами провайдера (у схемі застосунку чи без `SCHEMA`) не приймається; виправлення — `ALTER EXTENSION … SET SCHEMA <схема провайдера>` у базі. Тоді в схемах застосунку функцій розширень немає, і збіг з моделлю за `схема.ім'я` для Р6/Р7 надійний. Альтернатива (не рекомендовано): у схемах `extensionSchemas` збіг з моделлю не рятує — кожен виклик функції моделі там стає помилкою. | спека прав §5.3 — речення про `sql.debt-extension-schema` (задача 0) |
| Р7б | **Збіг з функцією моделі рятує лише в схемі застосунку.** Модель може мати функцію в схемі провайдера (`extensions.dblink_exec(int)`), а виклик `extensions.dblink_exec('…', '…')` дістанеться розширення. `scope.models` (обидва судді) не містить функцій у схемах провайдера й `pg_catalog`: там виклик судить лише позитивний перелік провайдера. Задача 0 перевіряє, що розширення, наявне в базі, але відсутнє в одиницях, — дрейф каталожного гейта (§6.2); якщо ні — розвилка. | спека прав §5.3 |
| Р8 | **Некваліфіковане посилання в DDL** (`SFUNC = f`, `EXECUTE FUNCTION f()`) — fail-closed, як виклик у виразі: дозволена лише вбудована. Postgres зв'язує ім'я за `search_path` сесії застосування, якого компілятор не фіксує, тож ім'я може потрапити в схему провайдера. Виправлення — кваліфікувати. **На затвердження архітекторки:** ламає некваліфіковані тригерні функції в борговому SQL. | спека прав §5.3 |
| Р9 | **Закриті форми лишаються закритими.** `classify()` (`sql/units.ts`) відмовляє `sql.statement-not-allowed` усе поза переліком класів: `CREATE RULE`, `GRANT <роль> TO <роль>`, `ALTER GROUP … ADD USER`, `CREATE`/`ALTER ROLE`, `CREATE OPERATOR`/`CAST`/`TYPE`/`CONVERSION`/`TRANSFORM`/`LANGUAGE`, `CREATE EVENT TRIGGER`, `CREATE INDEX`/`TABLE`, `ALTER TABLE` поза правилом рядка й `REPLICA IDENTITY`, `ALTER VIEW`, `ALTER … OWNER TO`, `REASSIGN OWNED`, `DO`, DML і `COPY` верхнього рівня. Блок не додає класів; таблиця тестів закріплює кожну форму. Ролі й членство дає лише платформа — рядок спеки. | спека прав §6.1 — рядок «ролі й членство» (задача 0) |
| Р10 | **`ALTER FUNCTION` на функцію, якої застосунок не створив** (згенерована функція запису, функція платформи): задача 0 перевіряє, чи її вже відмовлено. Якщо ні — розвилка до архітекторки з пропозицією: `functionSettings`, чия ціль не є функцією моделі, — помилка (форму функції платформи тримає платформа). | за розвилкою |

  (`unit-target.ts`); `grantFacts` (`definer-reads.ts`, після Д1);
  `PROVIDER_API_ROLES`, `PLATFORM_ROLES` (T0).
