# #271 Д4 «Інструменти designer»: декларації SQL-функцій у каталозі інструментів — план

**Статус:** аудит. Приймає архітекторка М4 (сесія `m4-simetra-milestone`); після приймання виконує автор (simetra-ea) чи свіжа сесія за брифом.
**Якорі:** `main` 3a6e091 (Д1, Д2, Д3 злито). Паралельно пишеться план Д5 (функції політик, спека §5.8): спільні файли — `compiler/diagnostics.ts` (`REPAIR_CLASS`), `compiler/messages.ts`, `compiler/operations/fix.ts`, `compiler/operations/platform-forms.ts`, `designer/src/schema-engine/__tests__/round-trip.support.ts`; хто зливається другим, той зливає `main` у свою гілку й проганяє `run-tests unit --changed` (правило семантичного конфлікту).
**Заборони:** стеки postgres і supabase спільні — лише таргетовані `run-tests`; повні рівні (`unit`, `db`, `db-supabase`, `packaging`) — CI на draft PR. Локально наприкінці блоку — нічого понад таргетоване (рівнів поза CI профіль для цих пакетів не має).

## Мета

Агент чи людина доводить прийняту теку з помилками класу ремонту до 0 помилок інструментами каталогу: оголошує декларацію SQL-функції (`declare-function`), а `fix` механічно вставляє запобіжник виклику, призначає `id`, вирізає дослівні гранти й ADP на функції та прибирає декларацію функції, що стала формою платформи. `explain` пояснює задекларовану функцію. Компілятор судить кожен задекларований `check` definer-функції, хоч би які викликачі. Результат блоку — тест каталогу «прийом з нуля» через MCP: база з функцією множини скоупу й definer-RPC без запобіжника → `introspect` → `add` виду скоупу → `declare-function` з `check` → `fix` → 0 помилок, після застосування план порожній.

## Архітектура

- **T1, операції** (`packages/simetra/src/compiler/operations/`):
  - нова операція `declareFunction` (модуль поруч з `add.ts`; вхід у `inputs.ts`) за формою `addElement`: `compileInput(files, {repair: true})` → правка `.functions.json` → `toPlatformForms` → `completeAndCompile(…, accepted)`. Файл декларації — `<основа>.functions.json` поруч із `.sql`, що тримає `CREATE FUNCTION` (одиницю знаходить за `tupleKey(schema, name)` серед одиниць скомпільованої моделі; `schema` за відсутності — `defaultSchema`). Запис — `formatSqlFunctionsFile` (порядок масиву — правило схеми T0). Новий запис отримує `id` з `completion.newId`; наявний зберігає свій `id`;
  - `fixFiles` (`fix.ts`) отримує режим ремонту (Р2) і нові кроки: (а) `id` записам `.functions.json` без нього; (в) вставка запобіжника (Р3); (г) `toPlatformForms` (той самий, що в мутаціях); (д) вирізання дослівного `ALTER DEFAULT PRIVILEGES … ON FUNCTIONS|ROUTINES` за діагностикою `sql.default-privileges-execute` тим самим механізмом позицій інструкцій, що (б) `withoutGeneratedGrants`.
- **T1, судження** (`compiler/sql/guard-of.ts`): `checkDeclaredGuards` судить кожну декларацію з `check` на `SECURITY DEFINER`-функції (Р4); `check-not-applied` вказує на рядок тіла (Р5).
- **T1, пояснення:** `explainFunction(model, {schema, name})` поруч з `explainObject` — викликачі, ролі з `EXECUTE` профілю (через `grantRole`), перевірка словами (дія, об'єкт, ціль), стан застосування (запобіжник доведено `guardOf` / причина).
- **Designer** (`packages/designer/src/tools/`): інструмент `declare-function` (вісь `files: "write"`, як `addTool` у `mutations.ts`); `explain` приймає ще й `{ function: { schema?, name } }`; `fix` — без нового входу. Реєстрація: `catalog.ts` (`TOOLS`), `types.ts` (`TOOL_NAMES`); MCP і CLI беруть каталог самі (`mcp/tools.ts`, `cli/command.ts`).
- **Скіли споживача:** `packages/designer/skills/simetra-adoption/SKILL.md` (крок «декларації й запобіжник» прийому з нуля; рядок «`fix` лише прибирає застарілі записи» стає неправдою), `simetra-metadata/SKILL.md` (інструмент `declare-function`). Англійською.

## Спека

- Декларації функцій (`docs/superpowers/specs/2026-11-18-sql-function-declarations-design.md`), у PR плану: §3 — рядки Д4 і Д5 (Р8); §5.6 — режим ремонту `fix` (Р2) і крок (д) вирізання ADP на функції (уже обіцяний §5.1 «виправлення — прибрати ADP, Д4»). У задачі 0: §5.2 — задекларований `check` definer-функції судиться завжди (Р4, на затвердження).
- Платформна спека — без змін.

## Глобальні обмеження

- Без поступок сумісності (правило власника): старих шляхів не лишати — вихід `refusedRoundTrip` для фікстур з `definers` видаляється, а не обходиться.
- `fix` ніколи не вигадує право: запобіжник вставляється лише з `check` декларації й лише у формі, яку доводить `guardOf`; підсумок перевіряє компіляція.
- Повідомлення й описи інструментів — англійською; коментарі — українською, «чому».
- Ідентичність функції — кортеж `tupleKey(schema, name)`, ніколи склеєний рядок (`compiler/sql/identity.ts`).
- Ослаблення оракула чи очікування тесту — розвилка архітекторці.

## Рішення

| # | Рішення | Вплив на спеку |

| Р1 | `declare-function`: вхід `{ function: { schema?, name }, callers, check? }`; створює чи замінює запис цієї функції (повна заміна `callers` і `check`, `id` зберігається). Неможливе — та сама діагностика, що в компілятора (`sql.declaration-target-missing`, `sql.declaration-overload`, `sql.declaration-duplicate`), і відмова без запису. Мутація приймає теку з помилками класу ремонту й відмовляє, якщо додає нову за кортежем `code, schema, name` (правило `acceptsRepair`). Після правки — `toPlatformForms`: декларація функції, що вже форма платформи, прибирається, а `declaration-platform-form-widens` — як у мутацій Д1. | немає (§5.6 це вже описує) |
| Р2 | `fix` у режимі ремонту, як мутації: пише, коли підсумок не додає нових помилок класу ремонту (за кортежем `code, schema, name`), прибирає хоча б одну й не має помилок поза класом; чистий підсумок пише, як і тепер; інакше — нічого. Затверджено архітекторкою. Причина: на базі з кількома RPC `fix` однієї функції інакше нічого не пише, поки решта не задекларовані. | §5.6: одне речення (у PR плану) |
| Р3 | Вставка запобіжника (`fix` (в)): лише коли декларація має `check`, функція `SECURITY DEFINER`, мова `plpgsql`, тіло без `DECLARE` і без `EXCEPTION` у зовнішньому блоці, а `check-not-applied` має причину `firstStatement` (запобіжника першим оператором немає). Вставляється рівно `PERFORM simetra.rights_require[_scope]('<дія контракту>', '<мітка виду>', <параметр або NULL>);` першим оператором зовнішнього блоку (після `BEGIN`), аргументи — з контракту прав (`action` для назви дії, `kindLabel`), функція запобіжника — за `guardFunctionOf`. Інші причини (`language`, `declareSection`, `exceptionBlock`, `arguments` — наявний запобіжник з іншими аргументами) `fix` не чіпає: правка змінила б семантику тіла. Текст правиться нульовою вставкою `applyEdits` у межах `$$…$$` тіла (`functionBodyText`). | немає |
| Р4 | `checkDeclaredGuards` судить кожну декларацію з `check` на `SECURITY DEFINER`-функції — зокрема з `callers: []` і лише `service` (залишок Д3): задекларована перевірка, якої тіло не застосовує, — `sql.declaration-check-not-applied`. Обов'язковість `check` (лише для `user`/`command`) не змінюється. `withoutFirstGuard` (виняток `sql.platform-function-call`) після цього спирається на доведений `guardOf` для всіх. **На затвердження.** | §5.2: одне речення |
| Р5 | `sql.declaration-check-not-applied` вказує на `.sql` функції й рядок першого оператора тіла (чи `CREATE FUNCTION`, коли операторів немає), параметри `schema`, `name`, `function`, `reason` — без змін. Інші `sql.declaration-*` уже вказують на файл `.functions.json` і JSON-pointer запису. | немає (§5.6 це вже вимагає) |
| Р6 | `explain` функції: вхід — об'єкт (як тепер) або `{ function: { schema?, name } }` (union у схемі входу). Вихід — `callers`, ролі профілю з виведеним `EXECUTE` (`grantRole` за провайдером), `check` словами («action `post` of Document `Order` on row `p_order`»), стан: `applied` / `not-applied (<reason>)` / `none`. Потребує моделі (`explain` за чистої компіляції — як тепер; у режимі ремонту — так само, як `compile` з `repair`). | немає |
| Р7 | `fix` (д): вирізає дослівний `ALTER DEFAULT PRIVILEGES … ON FUNCTIONS` / `ON ROUTINES` за `sql.default-privileges-execute`; ADP на інші класи об'єктів у тій самій інструкції — інструкція лишається (як `ownsWholeGrant` для грантів). | §5.6: крок (д) |
| Р8 | Корпус round-trip: Д4 видаляє вихід `refusedRoundTrip`/`definerRefusals`/`expectRefusedDefiners` — фікстура з `Loss.definers` без ланцюжка — помилка тесту, не очікувана відмова; ланцюжок `deployedRoundTrip` лишається єдиним шляхом. Прибрати `unscoped()` з корпусу прийому з нуля й довести фікстури з функціями множини, які кличуть дослівні політики (функції політик, ADR-0094), — done-when Д5. Затверджено архітекторкою. | §3: рядки Д4, Д5 (у PR плану) |
