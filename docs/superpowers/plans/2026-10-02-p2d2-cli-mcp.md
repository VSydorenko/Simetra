# П2, план D2 — CLI, MCP-операції, єдині двері: план імплементації

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Мета:** дати компілятору двері: `@simetra/cli` з `compile`/`explain`/`fix`,
`simetra mcp` з операціями над метаданими й `simetra compile` у pre-commit і CI
над кожною текою метаданих репо.

**Архітектура:** уся логіка — чисті функції ярусу T1 над мапою файлів
(`files → { changes, diagnostics }`), без диска й Node API; CLI і MCP-сервер у
новому пакеті `packages/cli` лише читають диск, викликають T1/T2 і пишуть
результат (спека §8.6: «тонкі обгортки над API компілятора»). Мутація
пишеться лише тоді, коли компіляція результату не має помилок.

**Технології:** TypeScript 7, Vitest 5, citty **0.2.2**,
`@modelcontextprotocol/server` **2.2.0**, tsx (запуск TS-вихідників без
збірки), husky **9.1.7**.

**Спека:** [спека П2](../specs/2026-09-28-p2-metamodel-compiler-design.md)
§3 (ідентичність, `physicalName`, перейменування, форма файлу), §8.4
(діагностика), §8.5 (`$schema`), §8.6 (CLI, MCP, єдині двері), §8.7, М12;
[платформна спека](../specs/2026-09-24-simetra-platform-design.md) §3.2, §5,
Р18, Р19.

**Передумова:** E1 приземлено. Перед стартом — `orient --plan` цього файлу.

**Серія:** F → E1 → **D2** (цей) → E2 (порт `SchemaEngine` з pg-delta, окремі
тіні, зворотна генерація, round-trip, приватна звірка).

## Рішення плану

1. **Операції — у T1** (`packages/simetra/src/compiler/operations/`), чисті й
   асинхронні над `ReadonlyMap<string, string>` (шлях відносно `metadata/` →
   текст). Результат — `OperationResult` з перелічених змін файлів і
   діагностики компіляції **результату**. `ok` — компіляція результату без
   помилок; лише тоді обгортка пише зміни. CLI `fix`, MCP і згодом студія (П6)
   — обгортки над цими функціями.
2. **Мутації (create, add, rename, delete) вимагають чистої компіляції
   входу** — інакше `operation.input-invalid` з діагностикою входу; це
   продовження правила «без напівмоделі» (`compile` без помилок не віддає
   модель), а каскад перейменування спирається на індекс посилань чистої
   моделі. `fix` — виняток: його справа — лагодити саме вхід, тож він працює
   над JSON без чистої компіляції. `explain` теж вимагає чистої компіляції.
3. **Адресація елемента — ланцюжок логічних імен** від об'єкта:
   `{ kind, name, element?: string[] }` (`["services", "amount"]` — реквізит
   ТЧ, `["Uah"]` — предвизначений, `["org"]` у `Project` — вид скоупу).
   Неоднозначність — `operation.element-ambiguous`, відсутність —
   `operation.target-not-found`.
4. **Правило `physicalName` у `fix`** (спека §3, «факт моделі»; прототип —
   `legacy/generator-pg/src/column-naming.ts`) — `toSnakeCase` логічного
   імені, плюс: одиночний `Ref` не на перерахування — суфікс `_id`;
   поліморфний `Ref` — основа без суфікса (компілятор сам дає `_type`/`_id`);
   табличну частину префіксує `physicalName` власника (`<власник>_<тч>`);
   вид скоупу — суфікс `_id`. SQL-зарезервоване слово чи зайняте ім'я —
   суфікс `_` (повторно, доки ім'я не стане вільним і не зарезервованим).
   Правило живе в T0 (`model/physical/assign.ts`), бо це факт моделі, а не
   CLI. Доказ правила — синтетичний домен: зняті `physicalName` відновлюються
   дослівно.
5. **`$schema`** проставляє `fix` відносним шляхом від файлу до файлу схеми
   встановленого пакета `simetra` (`schemas/<тека виду>.schema.json`,
   `project.schema.json`); T1 отримує резолвер шляху від CLI, бо розташування
   пакета на диску знає лише CLI.
6. **Вихід `simetra compile`:** діагностика й код виходу (0 — без помилок,
   попередження дозволені; 1 — є помилки; 2 — помилка використання чи
   введення-виведення). Артефакти — лише з `--out <dir>`: `snapshot.json`
   (`canonicalSnapshot`), `desired-state.sql` (`renderDesiredState(...).sql`),
   `entities.d.ts` (`emitEntityTypes`). Без `--out` CLI нічого не пише.
7. **Запуск CLI без збірки:** `bin/simetra.mjs` реєструє `tsx` (`tsx/esm/api`
   `register()`) і імпортує `src/main.ts`; вихідники `simetra` мають
   відносні імпорти без розширень, тож вбудоване стирання типів Node їх не
   виконає. Збірка (tsdown) — разом із доставкою пакета (П0 (а)), не в D2.
8. **MCP-сервер read-only за замовчуванням:** інструменти мутацій
   реєструються лише з `simetra mcp --allow-write`; кожна мутація має
   `dryRun`; `delete` вимагає `confirm: true`; до бази сервер не звертається.
9. **Єдині двері:** `pnpm metadata:check` знаходить кожну теку метаданих за
   `git ls-files '**/metadata/project.meta.json'` і проганяє `simetra compile`
   над кожною; його викликають `.husky/pre-commit` і CI.
10. **Борг F — `scopeColumn` за іменем на стадії 4** закривається першою
    задачею: стадія 4 бере колонку з індексу посилань
    (`customTable.scopeColumn` → id колонки), а не повторним пошуком за
    іменем; інакше каскад перейменування колонки мав би дві точки правди.
    Та сама задача кладе в індекс `defaultValue` перерахування (логічне ім'я
    значення, яке зараз звіряється повз індекс) і додає охоронця повноти
    індексу — каскад задачі 5 мусить бачити кожне посилання за іменем.

## Global Constraints

- T0 — без runtime-залежностей, крім `zod`; T1 — без `node:*` і Node API
  (лінт-зони `packages/simetra/eslint.tier-zones.js`); `crypto.randomUUID` —
  Web API (`globalThis.crypto`), дозволений.
- Пакет CLI — `packages/cli`, ім'я `@simetra/cli`, `bin: { "simetra": "bin/simetra.mjs" }`,
  `private: true`; залежить від `simetra` (`workspace:*`). Логіки стадій,
  рендера чи операцій у ньому немає (спека §8.6).
- Точні піни без каретки: `citty` `0.2.2`, `@modelcontextprotocol/server`
  `2.2.0`, `husky` `9.1.7`; `tsx` — точна версія, актуальну перевірити
  (`npm view tsx version`). Ліцензію перевіряти за файлом `LICENSE`
  джерела, не за npm (`@modelcontextprotocol/server`: Apache-2.0 + MIT —
  обидві дозволені `CONTRIBUTING.md`).
- MCP SDK — v2 (`@modelcontextprotocol/server`, не `@modelcontextprotocol/sdk`
  1.x); `inputSchema` — `z.object(...)` (Zod 4); stdio-транспорт; API
  перевіряти через context7 / типи пакета, не з пам'яті.
- Тексти CLI, MCP і нових діагностик — англійською (`AGENTS.md`); нові коди
  правил — у `COMPILER_RULES` і `MESSAGES` з `en`, `uk` і `hint`.
- Файли пишуться лише власним форматером (`formatMetaFile`,
  `formatProjectFile`); жоден шлях запису не обходить компіляцію результату.
- Id — UUID v4, ніколи не перевикористовується; `physicalName` наявного
  елемента ніколи не змінюється (перейменування — без DDL, спека §3, Р5).
- Коміти — Conventional Commits, опис українською, без трейлерів.
- Гейти в кожній задачі: scoped-тести, `pnpm --filter <pkg> typecheck`,
  `lint`, `pnpm format:check`; перед фінальним рев'ю — повні кореневі гейти
  разом із `pnpm test:db`; після правки доків — `python3 scripts/check-doc-anchors.py`.

## Review Focus

1. **Каскад перейменування пропускає роль.** Перейменування реквізиту
   регістра, на який посилаються ключ `fields` конструктора, вираз у рядку
   конструктора (`span`), `balanceControl` і маркер `-- @movements`, лишає
   модель зеленою й без жодного старого імені. Тест — задача 5.
2. **Перейменування об'єкта переносить теку й усі файли об'єкта**
   (`.meta.json`, `.sql`, `.module.ts`) і не змінює `physicalName` та хеш
   фізики. Тест — задача 5.
3. **`fix` ідемпотентний і не чіпає наявних id чи `physicalName`:**
   повторний прогін дає нуль змін; домен після `fix` компілюється з тим самим
   хешем. Тест — задача 3.
4. **Мутація на зламаному вході не пише нічого** (CLI і MCP), а dry-run не
   пише навіть на чистому. Тест — задачі 4 і 7.
5. **Видалення об'єкта, на який посилаються,** відмовляє з переліком місць
   посилання (файл і pointer), а без `confirm` MCP не видаляє навіть
   непосилане. Тест — задачі 6 і 7.
