# П4-A5 «MCP над даними» — план реалізації

> **Для агентів-виконавців:** ОБОВ'ЯЗКОВИЙ СКІЛ: `superpowers:subagent-driven-development`
> (рекомендовано) або `superpowers:executing-plans`. Кроки — чекбокси (`- [ ]`).
> Процедура блоку — `.claude/commands/виконай-задачу.md`; перед кожним кроком
> тестів — `.agents/skills/writing-tests/SKILL.md`.

**Мета:** агент у репо споживача читає й змінює дані бази розробника тими
самими API T3 (`runtime.read`, `runtime.run`), що й сервер застосунку, з
правами користувача `--as` — через два входи каталогу інструментів designer
(MCP і CLI).

**Архітектура:** нова вісь каталогу `data: "none" | "read" | "write"` поруч
із `files` і `database`; `invoke` вирішує її вичерпним `switch`. Два нові
інструменти: `data-read` і `data-command`. Кожен виклик компілює теку
метаданих, будує каталог рантайму, перевіряє запобіжники бази розробника,
відкриває пул ролі входу рантайму, створює `createCommandRuntime` (звірка
хешу) і закриває пул. Відмови, які не потребують бази (вісь, прапорці, об'єкт
із модулем, довідники прав), — до першого з'єднання.

**Стек:** TypeScript, Zod 4, citty, `@modelcontextprotocol/server`, `pg`
8.23.1 (уже залежність designer), Vitest.

**Спека:** `docs/superpowers/specs/2026-10-26-p4-runtime-design.md` §6.14
(повністю), §6.3, §6.4, §6.5, §6.10, §6.11, §6.15–§6.16, §7.2, §8 (рядок A5),
Рт14, Рт21; `docs/superpowers/specs/2026-10-02-simetra-designer-design.md`
§3.1–§3.2; спека прав Рх12 (без стелі агента до П4-F).

## Global Constraints

- Мова: коментарі коду — українською й про **чому**; опис інструментів,
  підказки, тексти відмов, CLI, скіл споживача — англійською; коміти —
  Conventional Commits з українським описом, **без трейлерів**.
- Рядок підключення — **лише із середовища**; ім'я змінної фіксується при
  запуску (`--data-url-env <NAME>`), значення ніколи не з'являється у
  виводі, структурованому результаті, діагностиці чи помилці (спека designer
  §3.2, «Читання бази»).
- Права агента = права користувача `--as`; `act` = `{ "sub": "<uuid агента>" }`
  (RFC 8693); `current_user_id()` `act` не читає (§6.14).
- Запобіжники — **не межа безпеки** (§6.14): межа — облікові дані
  `simetra_runtime`.
- `simetra/server` нічого не дізнається про designer: жодних правок
  `packages/simetra/src/server/` у цьому блоці (контракт T3 уже має `act` у
  `SessionClaims`, `packages/simetra/src/model/runtime/session.ts`).
- Кожна гілка за видом читає реєстр видів (`KIND_REGISTRY`), не ім'я виду
  (`AGENTS.md` § «Metamodel rules»).
- Версій пакетів і `PLATFORM_VERSION` не чіпати; історію не переписувати.
- Репо публічне: фікстури синтетичні.
- 🔴 Без `--` перед шаблоном vitest у `pnpm --filter`.
- Гейти під час роботи — лише scoped: `pnpm --filter @simetrajs/designer test <pattern>`,
  `pnpm --filter @simetrajs/designer typecheck`, `pnpm --filter @simetrajs/designer lint`,
  scoped DB (`pnpm --filter @simetrajs/designer test:db <pattern>`). Повний
  `pnpm test:db` — рівно один раз на блок (Задача 8), після «можна»
  архітекторки.
- Стек один на машину: лише `pnpm db:*`; не зупиняти й не перезапускати;
  перед DB-прогоном — `uptime`. `pnpm db:dev-env` до спільного стеку **не
  застосовувати** (застосує архітекторка після мерджу).
- DB-мутації — лише на закоміченому дереві.

## Відкриті питання для виконання

- Третя копія `seedActor` — у `catalog-command-concurrency.db.test.ts`; перенести й її на `seedRuntimeActor`, якщо дешево.
- `describeConnection` показує unix-сокет (`postgresql:///x?host=/tmp`) як `:5432/x` — не витік, але неточний `describe` в `instructions`; виправити разом із ресурсом даних або лишити кандидатом.
- Порядок рядків таблиці рішень (Р-A5-16 після Р-A5-19) — косметика.
- Попередження компіляції про об'єкт операції (наприклад, застарілий реквізит) мали б бути видні агентові й на успіху `data-read`/`data-command` — зараз не зроблено, кандидат (беклог §8).

## Review Focus

1. **Запис без `--allow-data-write` через MCP** — будь-яка комбінація
   прапорців, що веде до `run`, мусить бути у вичерпній матриці (Задача 1).
2. **Рядок підключення у виводі** — помилка `pg` (автентифікація, мережа)
   несе ім'я користувача; вихід інструмента бере лише `describeConnection`
   і код (Задача 4, тест з невірним паролем — DB-кейс у Задачі 5).
3. **`options=-c simetra.environment=development`** у рядку підключення —
   перевірка не проходить (Задача 5).
4. **Зміна моделі між викликами** — наступний виклик бачить нову модель і
   отримує `command.model-mismatch`, доки її не застосовано (Задача 5).
5. **Пакет, де лише одна фаза — на об'єкті з модулем чи довіднику прав** —
   відмова всього пакета до бази (Задача 3).
