# П4-D. Тонкий зріз: шаблон host-а, список і картка довідника — план імплементації

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Мета:** перший екран Simetra на справжній базі — шаблон host-а на TanStack
Start з однією Server Function даних над `createDataHandler`, SSR і сесією
Better Auth профілю `postgres`; список і картка довідника `Client` з
маршрутів в один рядок; редагування атрибутів шапки через чернетку форми;
оракул заборонених кадрів і мережеві бюджети як гейт.

**Архітектура:** хости T5 (`simetra/ui`) стоять на публічному API T4
(`simetra/data/react`) і інтерфейсі навігації; маршрути з одного рядка й
адаптер навігації на TanStack Router — T6 (`simetra/shell`). Шаблон —
приватний пакет `packages/create-simetra-app` з працездатним застосунком у
`template/`: зв'язування рантайму з пулом `simetra_runtime`, Server Function
даних (HTTP-шлях) і прямий виклик обробника з `{ inProcess: true }` для SSR
(Дх7), серверний entry з межею тіла й заголовками (Дх8). Оракул B3-6
переїжджає в спільний приватний пакет `packages/frame-oracle` (Дх9).

**Стек:** TypeScript, React 19, TanStack Start і Router (піни B3-6 і тесту
пакування), TanStack Virtual (пін B3-3), TanStack Form (новий точний пін),
Better Auth (пін спеки профілю `postgres`), Playwright (пін B3-6), Vite,
Vitest, Postgres 17 стеку `postgres`.

**Спека:** [П4-D](../specs/2026-11-08-p4-d-hosts-design.md) — усі розділи
зрізу; [П4-B](../specs/2026-11-05-p4-b-client-data-design.md) §4.5
(«Вимоги до host-а»), §6.4–§6.6, §7.1, §12; [профіль
`postgres`](../specs/2026-11-08-postgres-profile-design.md) §4.4; звіти
[П0 (а)](../specs/2026-11-04-p0-a-host-report.md) і [спайку UI й
SSR](../specs/2026-11-08-t4-ux-spike-report.md) — лише еталон.

**Поділ і залежності.** Шість частин з власним «готово»: **D0** (Task 1) —
оракул окремим пакетом; **D1** (Task 2–7) — T5 і T6; **D2** (Task 8–12) —
каркас шаблону; **D3** (Task 13–14) — SSR, маршрути, `resume()`; **D4**
(Task 15–17) — оракул, бюджети, CI, документи; **D5** (Task 18) — маршрути
сигналів, **умовно** (Дх12). Передумови: B3-3, B3-4, B3-5, B3-6 і B5a спеки
П4-B у `main`; ПГ-2a, ПГ-2b і ПГ-3 спеки профілю `postgres` у `main` до D2.
D0 і D1 від ПГ не залежать і можуть іти раніше.

## Global Constraints

- Імпорти лише вниз за ярусами; T5 імпортує лише `react`, `simetra/model`,
  `simetra/data/react`, `@tanstack/react-virtual`, `@tanstack/react-form`;
  T6 — T5 і `@tanstack/react-router`; TanStack Start, `better-auth` і `pg` —
  лише в `packages/create-simetra-app/template` (пакет воркспейсу `create-simetra-app-template`).
- Хост T5 не імпортує роутера, Start, `better-auth` і `simetra/server`.
- `inProcess` — лише на прямому серверному виклику обробника під час SSR;
  HTTP-шлях — лише `dataFn` з фактами запиту (Дх7).
- `expectedOrigin` — з конфігу сервера (змінна середовища `SIMETRA_APP_ORIGIN`), ніколи з заголовка `Host`.
- Межа тіла — стала T0 межі тіла конверта (B1b-2, орієнтир 4 МБ); відмова — `command.invalid` з `reason: "payload-too-large"` до розбору JSON.
- HTML з даними — `Cache-Control: private, no-store` і `Vary: Cookie`; відповідь Server Function — `Cache-Control: no-store`.
- Better Auth: схема `better_auth`, `advanced.database.generateId: "uuid"`, вхід email і пароль, без `session.cookieCache`, без плагіна `anonymous`.
- Claims: `{ sub: user.id, is_anonymous: user.isAnonymous === true }`, `sub` — нижнім регістром.
- Dev-користувач — лише справжня сесія Better Auth; скрипт поза `src/`; випадковий пароль друкується один раз; production-збірка не містить скрипта, імені dev-користувача й паролів.
- Пул `simetra_runtime` і `pg` — лише `src/server/runtime.ts` шаблону й скрипти поза `src/`.
- Рантайм даних на сервері — на запит; анонімний запит його не створює.
- Колонки списку — не ліниві атрибути шапки в порядку каталогу без службових; підписи — логічні імена.
- ТЧ у картці — лише читання; редагування — атрибути шапки з `update: true`.
- Опції роутера: `defaultStaleReloadMode: 'blocking'`, `defaultPendingMs` великий, `defaultPendingMinMs: 0`, маршрути з даними — `ssr: true`.
- `residency`: `Country` — `full`, `Client` — `window`.
- Нових полів метаданих і клієнтського каталогу план не вводить.
- Коментарі — українською й про «чому»; публічні імена й JSDoc — англійською.
- Без `--` перед шаблоном vitest у `pnpm --filter`.
- DB- і e2e-прогони — лише через `pnpm db:pg:*`, з тегом прогону (`AGENTS.md`).

## Review Focus

1. **`inProcess` на HTTP-шляху.** Хтось «спрощує» `dataFn`, і та сама функція
   обслуговує SSR — тест Task 9 «`dataFn` завжди передає факти запиту» і
   негативний тест лінту Task 11 «`inProcess` поза `src/router.tsx`».
2. **Chunked-тіло без `Content-Length`.** Межа за заголовком пропускає
   потокове тіло — кейс Task 10 «chunked понад межу».
3. **Відмова збереження губить правки.** `failed` чи `conflict` скидає
   чернетку — тести Task 5 і сценарії 5–6 Task 15.
4. **Дані A після входу B у тій самій вкладці.** Тримач не замінює рантайм —
   кейс Task 12 і сценарій 7 Task 14.
5. **Dev-шлях у production.** `dev:user` чи пароль потрапили в `.output` —
   тест Task 12 «production-збірка без dev-шляху».
