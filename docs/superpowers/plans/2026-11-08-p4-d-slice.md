## Спільне

### Мета, архітектура, спека

**Мета.** Перший екран Simetra на справжній базі стеку `postgres`: шаблон
host-а на TanStack Start з однією Server Function даних над
`createDataHandler`, SSR і сесією Better Auth; список і картка довідника
`Client` з маршрутів в один рядок; правка атрибутів шапки через чернетку
форми й команду (`await`).

**Архітектура.** Хости T5 (`simetra/ui`) стоять на публічному API T4
(`simetra/data/react`) і інтерфейсі навігації T5; маршрути й адаптер
навігації на TanStack Router — T6 (`simetra/shell`). Шаблон — приватний
пакет `packages/create-simetra-app`: застосунок у `template/` (окремий пакет
воркспейсу) і e2e поза ним у `e2e/`. HTTP-шлях даних — лише `dataFn` з
фактами запиту; SSR-шлях — `ssrTransport` під `createServerOnlyFn` з
`{ inProcess: true }` (Дх7).

**Спека.** [П4-D](../specs/2026-11-08-p4-d-hosts-design.md) §1 («Тонкий
зріз у віхі М3»), §2–§9, §11; [П4-B](../specs/2026-11-05-p4-b-client-data-design.md)
§4.5, §6.1, §6.4–§6.6, §7.1, §13 (порядок ①–⑩); [профіль
`postgres`](../specs/2026-11-08-postgres-profile-design.md) §4.1, §4.2,
§4.4; [ADR-0091](../../adr/0091-m3-thin-slice-scale-later.md). Звіти
[П0 (а)](../specs/2026-11-04-p0-a-host-report.md) і [спайку UI й
SSR](../specs/2026-11-08-t4-ux-spike-report.md) — лише еталон.

### Глобальні обмеження

- Імпорти лише вниз за ярусами. T5 імпортує лише `react`, `simetra/model`,
  `simetra/data/react`, `@tanstack/react-virtual`, `@tanstack/react-form`;
  T6 — T5 і `@tanstack/react-router`. Правила лінту зони T5 дає c2 (B3-3c,
  задача 12); хости їх не обходять.
- TanStack Start, `better-auth` і `pg` — лише в `packages/create-simetra-app/template`
  і `packages/create-simetra-app/e2e`.
- `template/` не імпортує й не залежить від `test-host`,
  `simetra/data/testing`, `simetra/server/testing`.
- Форми T4 беруться з `main` після PR-передумови; план їх не вигадує. Де
  форма ще не в `main`, назва — з плану-джерела (таблиця «Інтерфейси»), а
  розбіжність на старті — звіт архітекторці, не тихе «як у коді».
- Нових полів метаданих і клієнтського каталогу план не вводить (Дх6).
- Коментарі — українською й про «чому»; публічні імена, JSDoc і тексти UI
  типової локалі — англійською.
- Без `--` перед шаблоном vitest; кожна нова команда фільтра чи новий рівень
  мають негативний контроль, що тести справді запущено.
- DB- і e2e-прогони — лише стеком `postgres` через `pnpm db:pg:*`, з тегом
  прогону; об'єкти чужих прогонів не чіпати (`AGENTS.md`).

### Задача 4 — `useCardDraft` і `CardHost` (T5; після ⑤)

`src/ui/card/`; `packages/simetra/package.json` — `@tanstack/react-form`
необов'язковий peer входу `./ui` з точним dev-піном (ліцензія — за
`CONTRIBUTING.md`) і група syncpack. `useCardDraft` реалізує контракт
чернетки B3-4-Л над TanStack Form: стани `idle`, `saving`, `failed`,
`conflict`, `unknown`, `purged`, `hidden`; `save` шле лише змінені атрибути з
`expectedVersion` = база. `CardHost` — шапка за §5.2 і ТЧ лише для читання
(`tabular-too-large` — причина). Готово: відповідь на ревізію A не
перезаписує правок ревізії B; успіх переносить базу на версію результату;
`conflict` лишає правки, дає серверний рядок, «Взяти серверне» й
«Перезаписати»; `failed` лишає правки; «Скасувати» — один рендер; `purged`
скидає чернетку; `unknown` — `dismiss`; `hidden` і `isStale` вимикають
«Зберегти»; поле редаговане лише за `update: true`, `editable` і без
`isStale`; `command.invalid` з `path` — біля поля; `dirty` кличе
`useBlockWhile(true)`. `run-tests unit --filter card`.

### Задача 5 — маршрути з одного рядка й адаптер навігації (T6; після задач 3–4)

`src/shell/` (`app`, `routes`, `navigation`, `context`, `index.ts`);
`@tanstack/react-router` — необов'язковий peer входу `./shell` з піном тесту
пакування. Loader бере тримач з `context.data` і кличе `preload` з тим самим
spec, що й хост; `openCard` шукає маршрут зі `staticData.simetraCard` = id
об'єкта; `useBlockWhile` — `useBlocker`. Готово (роутер у пам'яті): loader і
хост — один spec; `context.data = null` — `preload` не кличеться; невідомий
об'єкт — `TypeError`; `openCard` без маршруту картки — `Error`;
`useBlockWhile(true)` блокує перехід. `run-tests unit --filter routes`.
