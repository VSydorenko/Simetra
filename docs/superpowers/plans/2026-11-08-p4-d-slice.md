# П4-D. Тонкий зріз: шаблон host-а, список і картка довідника — план імплементації

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Мета:** перший екран Simetra на справжній базі — шаблон host-а на TanStack
Start з однією Server Function даних над `createDataHandler`, SSR і сесією
Better Auth профілю `postgres`; список і картка довідника `Client` з
маршрутів в один рядок; редагування атрибутів шапки через чернетку форми;
оракул заборонених кадрів і мережеві бюджети як гейт.

**Архітектура:** хости T5 (`simetra/ui`) стоять на публічному API T4
(`simetra/data/react`) і інтерфейсі навігації; маршрути з одного рядка й
адаптер навігації на TanStack Router — T6 (`simetra/shell`). Шаблон —
приватний пакет `packages/create-simetra-app` з працездатним застосунком у
`template/` (окремий пакет воркспейсу) і e2e поза застосунком у `e2e/`.
HTTP-шлях — лише `dataFn` з фактами запиту; SSR-шлях — `ssrTransport` на
`createServerOnlyFn` з `{ inProcess: true }` (Дх7). Серверний entry ставить
межу тіла й заголовки (Дх8). Оракул — вхід `test-host/oracle` (Дх9).

**Стек:** TypeScript, React 19, TanStack Start і Router (піни B3-6 і тесту
пакування), TanStack Virtual (пін B3-3), TanStack Form (новий точний пін),
Better Auth (пін плану ПГ-3), Playwright (пін B3-6), Vite, Vitest, Postgres
17 стеку `postgres`.

**Спека:** [П4-D](../specs/2026-11-08-p4-d-hosts-design.md) — усі розділи
зрізу; [П4-B](../specs/2026-11-05-p4-b-client-data-design.md) §4.5, §6.1,
§6.4–§6.6, §7.1, §12; [профіль
`postgres`](../specs/2026-11-08-postgres-profile-design.md) §4.1, §4.2, §4.4;
звіти [П0 (а)](../specs/2026-11-04-p0-a-host-report.md) і [спайку UI й
SSR](../specs/2026-11-08-t4-ux-spike-report.md) — лише еталон.

**Поділ і залежності.** П'ять частин з власним «готово»: **D1** (Task 1–6)
— T5 і T6; **D2** (Task 7–12) — каркас шаблону; **D3** (Task 13–14) — SSR,
маршрути, `resume()`; **D4** (Task 15–17) — оракул, бюджети, CI, документи;
**D5** (Task 18) — маршрути сигналів, **умовно** (Дх12). Передумови: B3-3,
B3-4, B3-5, B3-6 і B1d спеки П4-B у `main` до D1; ПГ-2a, ПГ-2b, ПГ-3 у
`main` до D2; B5a у `main` до D3; частина C плану ПГ-4/B2 у `main` до D4 — інакше D5
переходить в окремий план.

## Global Constraints

- Імпорти лише вниз за ярусами; T5 імпортує лише `react`, `simetra/model`,
  `simetra/data/react`, `@tanstack/react-virtual`, `@tanstack/react-form`;
  T6 — T5 і `@tanstack/react-router`.
- TanStack Start, `better-auth` і `pg` — лише в `packages/create-simetra-app/template` (пакет `create-simetra-app-template`) і `packages/create-simetra-app/e2e` (пакет `create-simetra-app`).
- `template/` не імпортує й не залежить від `test-host`, `simetra/data/testing`, `simetra/server/testing`.
- HTTP-шлях — лише `dataFn`; `inProcess` — лише в `src/server/ssr-transport.ts` під `createServerOnlyFn`.
- Походження перевіряє `checkRequestOrigin` першим кроком `dataFn`, до `verifySession`.
- `expectedOrigin` = `SIMETRA_APP_ORIGIN`, канонічне значення (`new URL(v).origin === v`), інакше відмова старту; ніколи з `Host` чи `X-Forwarded-*`.
- Межа тіла — стала T0 межі тіла конверта (B1b-2); кожне тіло не-`GET`/`HEAD`; `Content-Encoding` ≠ `identity` — відмова; відповідь — `command.invalid` з `reason: "payload-too-large"` (для кодування — `command.invalid`).
- Кожна неасетна відповідь — `Cache-Control: no-store`; HTML — `private, no-store` і `Vary: Cookie`.
- Better Auth — таблиця спеки П4-D §4.3: `baseURL` і `trustedOrigins` = `SIMETRA_APP_ORIGIN`, `disableSignUp: true`, плагін `anonymous`, без `session.cookieCache`, `rateLimit` у базі, cookie `HttpOnly`, `SameSite=Lax`, `Secure` для `https`.
- Claims: `{ sub: user.id, is_anonymous: user.isAnonymous === true }`, `sub` — нижнім регістром; анонімна сесія на маршрутах з даними — як відсутність сесії.
- Пули: `SIMETRA_RUNTIME_DATABASE_URL` читає лише `src/server/runtime.ts`; `SIMETRA_AUTH_DATABASE_URL` — лише `src/server/auth-db.ts`.
- Рантайм даних на сервері — на запит; `defer` бере `waitUntil` поточного запиту на кожен виклик.
- Колонки списку — не ліниві атрибути шапки в порядку каталогу без службових; підписи — логічні імена; тексти — ключі каталогу `en`/`uk`, типово `en`.
- ТЧ у картці — лише читання; редагування — атрибути шапки з `update: true`.
- Опції роутера: `defaultStaleReloadMode: 'blocking'`, `defaultPendingMs` великий, `defaultPendingMinMs: 0`, маршрути з даними — `ssr: true`.
- `residency`: `Country` — `full`, `Client` — `window`; `strict: true` лише в dev-збірці.
- Нових полів метаданих і клієнтського каталогу план не вводить.
- Коментарі — українською й про «чому»; публічні імена, JSDoc і тексти UI типової локалі — англійською.
- Без `--` перед шаблоном vitest у `pnpm --filter`; кожна нова команда фільтра має негативний контроль, що тести справді запущено.
- DB- і e2e-прогони — лише через `pnpm db:pg:*`, з тегом прогону (`AGENTS.md`); повний `pnpm test:db:pg` — раз на блок перед фінальною перевіркою.
