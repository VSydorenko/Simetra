# П4-B6 — кеш прав клієнта й сигнали прав: план-ескіз

> **Статус:** проєкт плану, 2026-11-09; приймає архітекторка `simetra-87`.
> Блок B6 спеки П4-B (§13). Ескіз: тут рішення, інтерфейси між блоками,
> інваріанти безпеки й «готово» задач. Тест-кейси, імена й дрібні кроки
> виконавець пише сам за кодом і спекою.
>
> **Залежності.** Після B5b частин A і B (знімок прав, приймач, порт з
> `refreshTokens`, `simetra/data/centrifugo`), ПГ-4/B2 частин B і C
> (`signal_outbox`, `signal_topic_allowed`, `signal_payload_allowed`, стенд,
> `authorizeChannels`), B3-3 (публічні хуки T5) і ПГ-2 (провайдер
> `postgres`). На `main` зараз немає жодного з них, крім ядра B3-2. Якорі на
> незмерджене позначено «після X».
> **Перед стартом кожної частини:** `.agents/skills/codebase-research/scripts/orient --plan <цей файл>`.
> Розійшлося ім'я — перейменуй у плані за кодом. Розійшлася поведінка —
> до архітекторки.
> **Спільні стеки.** Виконавець ніколи не виконує `pnpm db:stop`,
> `pnpm db:start`, `pnpm db:pg:stop`, `supabase stop`. DB-тести — лише
> `pnpm --filter … test:db*` під замками стеків.

**Goal:** клієнт знає свої права дій і рахує `can(action, object, { scope?, row? })`
за контрактом прав із клієнтського каталогу; зміна прав доходить до клієнта
сигналом за секунди, а не за інтервалом свіжості чи строком токена каналу.

**Architecture:**
- **T1/T0.** Компілятор кладе контракт прав об'єкта в клієнтський каталог.
  `rights_client_snapshot()` (B5b) дістає мої id учасника й значення вимірів.
  `signal_rights` і `signal_user_rights` пишуть рядок outbox від власника;
  `rights_bump` і тригери членства й призначень їх кличуть.
  `signal_topic_allowed` у режимі підписки відкриває канали прав.
- **T4.** Обчислювач `can` — загальний код над контрактом і знімком B5b.
  Знімок лишається одним сховищем (`CoreSession.rightsSnapshot()`).
  Звуження обсягу `read` на заміні знімка застосовує `can(read, row)` до
  кожного рядка сховища. Приймач B5b підписується на канали прав і
  реагує за §9.3.
- **T5.** `useCan` — хук над `can` і подією заміни знімка.

**Tech Stack:** TypeScript 7, Zod, Vitest 5 (фейкові таймери, jsdom),
fast-check, `pg` 8.23.1, Postgres 17, Centrifugo v6 (стенд ПГ-4/B2),
`centrifuge` 5.8.0.

**Spec:** [П4-B](../specs/2026-11-05-p4-b-client-data-design.md) §3, §6.2
правило 4, §6.5, §8.1–§8.4, §8.6, §9, §12 (рядки «unit T1», «unit T4 (кеш
прав)», «DB `simetra`», «стенд сигналу»), §13 рядок B6, §14.3; [спека
прав](../specs/2026-10-17-rights-design.md) Рх15, §5.2, §6.3; плани
[B5b](2026-11-08-p4-b5b-signal-receiver-rights-snapshot.md) і
[ПГ-4/B2](2026-11-08-pg-4-b2-signal-transport.md). Правила тестів — скіл
`writing-tests`.

## Global Constraints

- Коментарі — українською, пояснюють «чому»; JSDoc експортованого API —
  англійською. Коміти — Conventional Commits, опис українською, без
  трейлерів. Push і PR — архітекторка.
- 🔴 Без `--` перед шаблоном vitest у `pnpm --filter`.
- Кейс «на обох стеках» — спільне тіло в `*.support.ts` і два тонкі файли
  (`*.db.test.ts`, `*.supabase.db.test.ts`), як у B5b.
- Знімок прав у T4 — **одне** сховище (B5b Р1). Обчислювач, предикати
  підписки й звуження читають `scopeSets`, рядки прав, мої id учасника й
  значення вимірів лише через `CoreSession.rightsSnapshot()`.
- Обчислювач — не захист (§9.2). База — бар'єр. Помилка обчислювача дає
  зайву чи сховану кнопку; помилка звуження не сміє показати значення, яких
  база вже не дає.
- Запис у сховище — лише `core.commit(fn, token)`; старий токен нічого не
  пише.
- Без shims: речення «До B6…» у §6.2 правило 4 і булева `readAllowed` B5b
  замінюються в тій самій зміні.

## Рішення

| № | Рішення | Вплив на спеку |
| --- | --- | --- |
| Р1 | **Контракт прав у клієнтському каталозі** — поле `rights?` запису каталогу T0: `actions: { action, extents: ("any" \| "own" \| { dimension: uuid })[] }[]`; `ownership: { attribute, owner: "user" \| { membership: scopeKindId } }[]`; `access: { dimension, attribute, fresh: boolean }[]`; `binding?: { container: uuid, attribute }`; `readBoundary: "tenant" \| "users" \| "public" \| "none"`. Носій — **логічне ім'я атрибута** каталогу (компілятор мапить `CarrierContract.value`; носій поза атрибутами каталогу — помилка компілятора). `fresh` = зв'язок `values.relation`, чий об'єкт не `declared` у `KIND_REGISTRY`; функція виміру чи прийнята `CustomTable` — `false`. Граф вимог і `deny` уже розгорнуто в рядках знімка, у контракт не йдуть. `snapshotHash` змінюється, `kernelHash` — ні | §3, §9.2 (задача 0) |
| Р2 | **Розширення знімка B5b** (B6 розширює, не дублює): `members: { scopeKind, scope, member }[]` з `rights_my_scopes()` і `dimensionValues: { dimension, values: uuid[] }[]` з `rights_dimension_values()` на кожен вимір контрактів. Окремого поля `containers` немає: контейнерні права — рядки `rights` з `level = 'container'` і `container` (так рахує `rights_container`). `rightsVersion` B5b Р4 не змінюється; зміну `members` і `dimensionValues` ловить `rightsVersions` | §9.1 — поля знімка (задача 0) |
| Р3 | **Семантика `can` — дзеркало `rightsPredicates`** (`compiler/rights/predicates.ts`) для дії: обсяги дії × носії. Скоуплений об'єкт — грант із рядків `level = 'scope'` зі `scope` рядка (як `rights_any/own/dim`); глобальні й `everyUser` рядки скоупленого не відкривають. Нескоуплений — будь-який рівень, крім `container` (як `has_right`). Контейнер — рядок `level = 'container'` з `container` = значення носія прив'язки. `own` — носій = `userId` (`owner: "user"`) чи ∈ моїх `member` виду (`membership`). Вимір — носій ∈ `dimensionValues`. Плюс межа тенанта для скоупленого: скоуп ∈ `scopeSets` виду | §9.2 (задача 0) |
| Р4 | **Тризначність.** Кожна гілка дає `true`/`false`/`unknown`; результат — `true`, якщо хоч одна `true`, інакше `unknown`, якщо хоч одна `unknown`, інакше `false`. `unknown`: вимір з `fresh: false` (завжди, коли є грант на цей обсяг); носій відсутній у рядку; знімок без `versions` — гілки `own` через членство й межа тенанта; скоуп поза `scopeSets` виду з дослівною функцією множини (§14.3); `read` об'єкта з межею `users` — крім власного рядка (`key = userId`). `publicRead` — `read` = `true` для дійсного користувача поза `scopeSets` (§14.3). Без рядка — «чи маю грант дії хоч на якийсь обсяг у скоупі» за тими самими правилами без носіїв | §9.2, §14.3 (задача 0) |
| Р5 | **`readAllowed` B5b стає тризначною** (рішення архітекторки): скоуп поза `scopeSets` виду з дослівною функцією множини — `unknown`, а не `false`. На заміні знімка пара `false` — `purge` (як у B5b), пара `unknown` — ключі пари ховають значення й `revalidate` виглядів об'єкта | §6.2 правило 4 (задача 0) |
| Р6 | **Звуження обсягу `read`** замінює «`revalidate` усіх виглядів об'єкта» B5b Р5. На кожній заміні знімка, коли змінились рядки `read`, `members`, `dimensionValues` чи `scopeSets`, ядро в одному `commit` рахує `can(read, object, { scope, row })` для кожного ключа сховища (зокрема знімки показу вікна, цілі `include`, слоти `SectionStore` власників): `false` — `purge({ keys })` (стан `purged`, чернетка `card` скинута); `unknown` — нова операція `Writer.hide(object, keys)`: `stale.seen` з новою епохою (той самий механізм, що й горизонт B3-2: `visibleRow` ховає значення, знімає лише читання, почате після позначки) і `revalidate` усіх виглядів, що тримають ключ, зокрема невидимих і підмножин `include`. Збій перечитування лишає значення схованими. Без змін — 0 запитів | §6.2 правило 4 (задача 0) |
| Р7 | **`signal_rights(p_scope_kind uuid, p_scope uuid, p_version bigint)`** і **`signal_user_rights(p_user uuid, p_version bigint)`** — `SECURITY INVOKER SET search_path = ''`, `EXECUTE` нікому (`executeGrants(…, [])`). Власник обходить RLS outbox (таблиця без `FORCE`), тож політика `signal_payload_allowed` його не судить; **форму перевіряє сама функція** до `INSERT`: аргументи не `NULL`, версія > 0, вид і скоуп обидва нульові чи обидва ненульові; користувач ≠ `ZERO_UUID`. Інакше — `RAISE` з `22023`. Тіло будує канал з аргументів і `data` рівно `{ op: "rights", row_ver }`; `id` ставить штамп outbox. Режим злиття сигналів прав не гасить: їх мало, і вони про безпеку | §8.2 (задача 0) |
| Р8 | **Хто шле.** `rights_bump` — `RETURNING version`, потім `signal_rights` на ту саму пару (глобальна — нулі). Тригери членства — `signal_user_rights` кожному `userColumn` старих і нових рядків з версією скоупу після підвищення. Тригери призначень ролей: рівень скоупу — `subject` (id учасника) → користувач через довідник членства виду; глобальний — `subject` і є користувачем. Тригер «Користувачів» на зміні `invalid` чи `user_kind` — `signal_user_rights(id, глобальна версія)`. Дублікати пар у межах оператора — `DISTINCT`. Ролі й дельти шлють лише `signal_rights` скоупу (усі учасники підписані на канал прав скоупу). Прийняті джерела членства й призначень тригерів підвищення не мають — сигналу немає, свіжість за інтервалом (§8.6) | §8.2, спека прав Рх15 (задача 0) |
| Р9 | **Режим підписки `signal_topic_allowed`** для каналів прав: `simetra-rights:<вид>:<скоуп>` — вид є видом скоупу моделі й скоуп ∈ `scopeSetCall(вид)`; `simetra-rights:<нуль>:<нуль>` — дійсний користувач; змішані нулі — `false`; `simetra-user:<id>` — `id = current_user_id()`. Режим відправки для обох префіксів лишається `false`, `signal_payload_allowed` з `op: "rights"` — `false` (B2) | §8.3 (задача 0) |
| Р10 | **Підписки приймача на канали прав** — лише коли знімок має `versions` (є довідники прав): інакше сигналів прав не буває. Канали: `simetra-rights:` кожного `scopeSets`, глобальний і `simetra-user:<userId>`. Предикат `canSubscribeRights(snapshot, channel)` — дзеркало Р9; перерахунок дельтою разом із каналами змін (B5b Р7) | §8.4 (задача 0) |
| Р11 | **Реакція на сигнали прав** (§9.3): канал прав скоупу з `row_ver` > кешованої версії пари (порівняння `BigInt`; пари немає в `versions` — як більша) → `requestRights()`; ≤ — ігнор. Будь-який сигнал каналу користувача → `requestRights()` і `transport.refreshTokens()` в одній мікрозадачі. Нерозібране повідомлення каналу прав — `requestRights()`. Відмова `auth`: канал прав скоупу — `purge({ scope })` кожного об'єкта цього виду скоупу й `requestRights()`; глобальний чи канал користувача — `requestVersion()` (шлях сесії B5b Р13) | §8.4 (задача 0) |
| Р12 | `useCan(action, object, opts?) : boolean \| "unknown"` у T5 поруч із хуками B3-3: `useSyncExternalStore` над `onRightsChange` (B5b) і `runtime.can`. Хост показує `unknown` доступним (§9.2). Функціональних опцій хук не рахує (П4-E) | немає |

## Інваріанти безпеки й тести, що червоніють на дефекті

Кожен рядок — тест виконавця й навмисна мутація на закоміченому дереві
(мутацію відкочує після червоного прогону). Мутація без червоного тесту —
дефект плану, до архітекторки.

| Інваріант | Тест (рівень) | Мутація, що мусить червоніти |
| --- | --- | --- |
| І1. Підробити сигнал прав може лише власник | DB обох стеків: `signal_rights`/`signal_user_rights` від `simetra_command`, ролі `user`, `anonymous`, `simetra_signals` — `42501`; прямий `INSERT` від `simetra_command` у `simetra-rights:`/`simetra-user:` — `42501` | `GRANT EXECUTE … TO simetra_command`; режим відправки повертає `true` для каналу прав |
| І2. Форма рядка від власника — у функції | DB: кожен недійсний аргумент Р7 — `22023` і 0 рядків outbox; дійсний — `data` рівно `{ id, op, row_ver }` | прибрати кожну перевірку Р7 окремо |
| І3. Власник пише outbox без політики | DB: команда адміністрування прав під `simetra_command` (зміна ролі, членства, призначення, деактивація) дає рядок у правильний канал прав скоупу й користувача; `ROLLBACK` — 0 рядків | `rights_bump` без виклику `signal_rights`; тригер членства без `signal_user_rights` |

Канал прав відкривається лише своєму | DB обох стеків: режим підписки за Р9 — свій скоуп так, чужий ні, дослівна функція множини, що відсікає скоуп, ні, глобальний — лише дійсний користувач, канал користувача — лише свій, змішані нулі ні; `authorizeChannels` відсіює чужі | гілка каналу користувача без `= current_user_id()`; гілка скоупу без `scopeSetCall` |

| І6. Обчислювач ≡ ядро на фікстурах | DB обох стеків (§12 «DB `simetra`»): дії запису — `true`/`false` ≡ успіх/`no-right` ядра в транзакції з `ROLLBACK`; `read` — видимість `SELECT` під claims; без рядка — існування фікстурного рядка з успіхом. Втрата `read` ховає дані негайно | unit T4: звуження → `false` — `purge` ключа в усіх сховищах і чернетці `card`; `unknown` — значення сховано в тому самому `commit`, `revalidate` усіх виглядів ключа, збій перечитування лишає сховано, відповідь, почата до позначки, не відкриває | `unknown` без `Writer.hide`; `hide` знімає читання, почате до позначки |
| І8. Дослівна функція — `unknown`, не `false` | unit T4: заміна знімка, де скоуп виду з дослівною функцією зник зі `scopeSets`, — ключі сховано й `revalidate`, без `purge`; вид із членством — `purge` | `readAllowed` повертає `false` для дослівного виду |
| І9. Одне джерело знімка | unit T4: тест-інваріант над джерелами B5b розширено на `members`, `dimensionValues`; заміна знімка змінює відповідь `can` і `useCan` без іншого кешу | другий кеш у `can.ts` |

| І11. Сигнал після `dispose()`/`session-changed` чи старий знімок — 0 записів | unit T4 і модельний тест: сигнал прав і відповідь `rights` старого покоління нічого не пишуть | заміна знімка без перевірки токена |

## Review Focus

1. **Відкликане членство при живій підписці** — без сигналу межа 5 хв токена
   (§8.6), з сигналом — секунди. Тест — І10 на стенді, число в §8.6.
2. **Видалення учасника разом із призначеннями одним оператором** —
   користувач для призначення вже не знайдеться через членство; сигнал
   дає тригер членства. Тест — DB-кейс каскаду в задачі 3.
3. **Масове створення членства** (провізія тенанта, імпорт) — один сигнал на
   користувача й скоуп, без шторму перепідписок. Тест — DB-кейс з 1 000
   рядків одним оператором: ≤ 1 000 рядків outbox користувачів і 1 скоупу.
4. **Кількість каналів прав** = |`scopeSets`| + 2. Межа `authorizeChannels`
   (256 каналів на виклик, B2) — виконавець звіряє, що транспорт B5b ділить
   запит токенів; якщо ні — до архітекторки.
5. **Стара версія в сигналі прав скоупу** (повтор, відновлення історії) —
   ігнор без запиту (Р11).

## Готово — блок

- Контракт прав є в клієнтському каталозі; `can` еквівалентний ядру й базі
  на фікстурах обох стеків; `useCan` працює над ним.
- Знімок прав — одне сховище; звуження `read` ховає чи прибирає рядки за
  `can` негайно.
- Сигнали прав скоупу й користувача пише лише власник, з перевіркою форми у
  функції; канали прав відкриваються лише своєму; сигнал доходить на стенді
  й закриває втрачений канал без чекання строку токена.
