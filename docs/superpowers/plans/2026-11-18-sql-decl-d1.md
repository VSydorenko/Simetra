## Мета, архітектура, спека

**Мета.** Функція SQL застосунку отримує декларацію в
`<основа>.functions.json`; `EXECUTE` задекларованої функції, функції модуля
виду і функції значень виміру виводить генератор платформи; клас ремонту
дозволяє мутаціям `create`/`add` вести теку після зворотної генерації до
0 помилок. Готово, коли виконано рядок Д1 таблиці §3 спеки (кожна умова — тест
задачі нижче; кожне правило Д1 має тест, що червоніє без нього).

**Архітектура.** Стадія 1 (`stages/files.ts`) читає `.functions.json` як
супутній файл `.sql` (як `.module.ts`), схема — Zod T0. Новий модуль
компілятора `sql/declarations.ts` резолвить декларації в дослівні одиниці
(`declaredFunctions`) і знає форми платформи (`platformFormFunctions`); його
читають правила викликачів, `checkDefinerReads`, закрита оболонка й
генератор `EXECUTE`. `EXECUTE` будує один генератор
(`buildFunctionExecuteUnits` над `executeGrants`) для чотирьох джерел:
функції множини, обробники, функції значень виміру, задекларовані функції й
недекларовані функції модуля виду; тож `generatedGrantConflicts` і `fix`
працюють для нових цілей без нового коду. Клас ремонту — перелік кодів у
компіляторі з ключем `{ code, schema, name }`; режим `repair` — поле
`CompileOptions`, яке передають лише хвости `create`/`add` (і в Д4
`declare-function`).

**Спека.** §3 рядок Д1 (обсяг і done-when), §4 (інтерфейси, власник Д1),
§5.1 (файл, правила, `EXECUTE`, клас ремонту), §5.3, §5.4, §5.7 (коди Д1),
§6 «ACL»; ADR-0092. Д2 (§5.2), Д3 (§5.5), Д4 (§5.6), Д5 (§5.8) — лише шви.
Платформна спека §6.7 (гранти функцій).

## Глобальні обмеження

- Схема файлу — лише Zod у T0; типи — `z.infer`; JSON Schema генерується
  (`compiler/json-schema.ts`, `pnpm schemas:update`), не пишеться руками.
- Новий суфікс реєструється в обох читачах: `stages/files.ts` (компілятор) і
  `packages/designer/src/io/metadata-dir.ts` (`METADATA_SUFFIXES`); тест
  кожного читача.
- Повідомлення діагностик — англійською в `compiler/messages.ts`; код —
  у переліку `compiler/diagnostics.ts`. Тести перевіряють коди й параметри,
  не текст.
- Наявні тести лишаються зеленими без послаблення очікувань, зокрема
  `definer-reads.test.ts`, `function-execute.test.ts`,
  `provider-grants.test.ts` і DB-тести round-trip designer. Зміна
  очікування наявного тесту — рядок у тілі PR з причиною; послаблення
  оракула — розвилка до архітекторки.
- `compile()` без опцій поводиться як тепер: модель — лише з чистого прогону.

## Інтерфейси

Д1 дає (споживачі — Д2–Д5):

- T0: `sqlFunctionsFileSchema`, `SqlFunctionDeclaration` (з повною формою
  `check`: `action`, `object` — `MetadataRef`, `row?`, `scope?`),
  `FUNCTIONS_FILE_SUFFIX`, правило `declarations.not-canonical`; канонічний
  запис файлу в `model/format.ts`; JSON Schema `functions.schema.json`.
- Компілятор, `sql/declarations.ts`: `declaredFunctions(...)` → записи
  `{ declaration, file, pointer, unit, key }` (`unit` — дослівна одиниця
  `CREATE FUNCTION`, `key` — пара `{ schema, name }`, не зклеєний рядок); `platformFormFunctions(...)` →
  ідентичність функції → призначення форми. Д2 читає `declaration.check` і
  `unit`; Д3 пише файли канонічним записом; Д5 додає функції політик у
  `platformFormFunctions`.
- Клас ремонту: перелік `REPAIR_CLASS` і структурований ключ помилки `{ code, schema, name }` (Р7) у
  `compiler/diagnostics.ts`; Д2 і Д5 додають коди рядком.
- Операції: `CompileOptions.repair`, `compileInput(files, { repair })`,
  перевірка прийому «до/після» і хелпер переходу (Р12) — експортовані для
  `declare-function` (Д4); `OperationResult.written`.
- Шов Д2: причина `guardUnavailable` коду `sql.declaration-check-not-applied`
  (Р3) — єдине місце, яке Д2 замінює доказом `guardOf`; `check-form` Д1 не
  судить.
- Шов Д3: зворотна генерація пише декларації лише через схему й канонічний
  запис Д1; дослівних грантів `EXECUTE` задекларованим функціям вона не
  пише (§5.5 крок 3) — тест Д1 на `sql.generated-grant` це фіксує з боку
  компілятора.
- Шов Д4: `declare-function` = мутація з режимом `repair` + хелпер Р12;
  `fix` (а) id, (в) запобіжник, (г) видалення декларації форми — Д4.

Д1 бере: `sql.definer-caller-unchecked` і `isSecurityDefiner` (#173, на
`main`).

## Інваріанти безпеки

Кожен — тест, що червоніє на названій мутації.

1. **ACL задекларованої функції повний і лише з викликачів.** DB-тест
   (`postgres`): `callers: ["user"]` — `simetra_user` виконує,
   `simetra_anon` і роль без гранту — `42501`; `callers: []` — ніхто з ролей
   API. Мутація: прибрати `REVOKE … FROM PUBLIC` у генераторі для
   задекларованих — червоний.
2. **Функція значень виміру не має `EXECUTE` ролі запиту.** DB-тест: роль
   користувача отримує `42501` на прямому виклику. Мутація: призначення
   виміру `["user"]` — червоний.
3. **Недекларована функція модуля виду не має `EXECUTE` ролей API**, і на
   `supabase` теж (типові привілеї схеми дають `anon`/`authenticated`).
   `*.supabase.db.test.ts`: `anon` і `authenticated` — `42501`. Мутація:
   пропустити функції модуля в генераторі — червоний.
4. **Definer-функція з `user` чи `command` не компілюється без доведеної
   перевірки.** Без `check` — `sql.declaration-check-missing`; з `check` —
   `sql.declaration-check-not-applied` (`guardUnavailable`, Р3); з
   `anonymous` — `sql.declaration-anonymous-definer`. Мутації: вважати
   наявність `check` доказом; пропустити `command` у правилі — кожна
   червона. Недекларована definer-функція з дослівним грантом ролі
   команд і з `REVOKE … FROM PUBLIC` та ролей API — `sql.definer-caller-unchecked`
   (Р14); мутація: прибрати роль команд з ролей правила — червоний. Та
   сама функція з `REVOKE` без гранту ролі команд компілюється без цієї
   помилки; мутація: судити роль команд гілкою «не відкликано» —
   червоний (зокрема наявні випадки `rights-snapshot-sources.test.ts`
   з `REVOKE` без гранту ролі команд лишаються без нової діагностики).
5. **Модель з помилками класу не доходить до плану.** `compile()` без
   опції на теці з помилками лише класу ремонту — `ok: false`, без моделі;
   `promote` і `fix` на ній не пишуть нічого. Мутація: `repair` типово
   увімкнено — червоний.
6. **Мутація не додає помилки класу.** `add`, що прибирає одну помилку класу
   і додає іншу на іншій функції, відмовляє (кількість та сама). Мутація:
   порівнювати кількість замість множини ключів — червоний.
7. **Дослівний грант на ціль платформи — помилка.** `GRANT`/`REVOKE
   EXECUTE` на задекларовану функцію, функцію значень виміру й функцію
   модуля — `sql.generated-grant`; `fix` вирізає оператор лише з цілями
   платформи (наявний `ownsWholeGrant`). Мутація: не додавати
   задекларовані функції до генератора — червоний.
8. **Задекларована функція — у закритій оболонці в будь-якому файлі.**
   `SECURITY DEFINER` без `SET search_path = ''` — `sql.closed-shell`, не
   борг; окремий `ALTER FUNCTION` — `sql.function-settings-shell`. Мутація:
   не додавати задекларовані до `judgedFunctionIdentities` — червоний.
9. **Типові привілеї не віддають `EXECUTE` повз виведені гранти.** Дослівний
   `ALTER DEFAULT PRIVILEGES … GRANT EXECUTE ON FUNCTIONS` чи `ON ROUTINES`
   — `sql.default-privileges-execute` (Р15). Мутації: правило ігнорує
   `ON ROUTINES`; правило вимкнено — кожна червона.
