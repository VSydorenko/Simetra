# #276 Прийом з нуля: види скоупу й функції множини — план

**Статус:** аудит. Приймає архітекторка М4 (сесія `m4-simetra-milestone`); після приймання виконує автор (simetra-78).
**Якорі:** `main` fa065fb (#286 «платформне — за вмістом», Д1 декларацій, #297 план). Після #275 нічого з `compiler/sql/` план не бере.
**Заборони:** не змінювати `packages/simetra/src/compiler/sql/**` (там #275; потрібна зміна — розвилка архітекторці). Стек postgres спільний: лише таргетовані `run-tests`; повні рівні — CI на draft PR (`db`, `db-supabase`, `packaging`, `unit`). Стек `supabase` локально — лише `--filter` файлу Supabase, якщо задача його називає.

## Мета

Після прийому з нуля (`introspect` у порожню теку) база Simetra з функціями множини скоупу доходить до моделі одним шляхом: мутація `add` виду скоупу з `setFunction` у тій самій зміні призначає скоуп `CustomTable` і поглинає дослівні одиниці, які модель тепер генерує сама, — лише ті, що збігаються з генерованими за вмістом. Тест «adoption from scratch with named scope set functions» веде ланцюжок §9 до кінця: прийом → `add` видів → 0 помилок компіляції → план → звірка з тінню → застосування → наступний план порожній.

## Архітектура

Два шари, як у `promote`:

1. **T1, мутація (`compiler/operations/add.ts`).** Новий необов'язковий вхід `scopes` у `add` для колекції `scopeKinds` проєкту: `{ <ім'я CustomTable>: { scope: <вид> | "none", scopeColumn?: <логічне ім'я колонки> } }`. Мутація пише вид, поля `scope`/`scopeColumn` таблиць і прибирає з теки кандидатів поглинання — дослівні одиниці, чия ідентичність збігається з одиницею, яку генерує модель результату (інакше `sql.unit-duplicate`), разом з їхніми рядками в `sql-debt.json`. Перелік кандидатів повертається в результаті операції (`absorbed`). T1 вмісту не судить: каталожної форми він не бачить.
2. **Designer, суддя вмісту (`tools/mutations.ts`, `addTool`).** Порожній `absorbed` — запис як досі, без бази. Непорожній — суддя тим самим механізмом, що повторний `introspect` (#286): `extract` цілі, `folderReference` результату (одна тінь), `reverseGenerate(extract, { existing: результат, reference })`. Одиниця, що збігається за вмістом, упізнається як згенерована текою й не пишеться; розбіжна повертається дослівною й дає `sql.unit-duplicate` (або `sql.generated-grant` для гранту на функцію з виведеним `EXECUTE`) — мутація відмовляє, нічого не пише, діагностика називає одиницю. Успіх пише вихід `reverseGenerate` (він же переводить FK у межах тенанта у форму `scopedRef`, як повторний introspect над скоупленою текою).

Так «видаляти лише при точному збігу» тримає одна функція впізнавання (#286), а не другий порівнювач; T1 лишається чистим.

## Спека

- Декларації функцій (`docs/superpowers/specs/2026-11-18-sql-function-declarations-design.md`) §5.5, абзац «Форми платформи після прийому», пункт «форма платформи»: `add` виду скоупу несе `scopes` таблиць і поглинання за вмістом; розбіжна одиниця — відмова. §3 рядок Д4: частину «оголошення виду скоупу» в тесті «прийом з нуля» дає #276; Д4 лишаються `declare-function`, `fix`, MCP і решта фікстур.
- П2 (`docs/superpowers/specs/2026-09-28-p2-metamodel-compiler-design.md`) §8.6: вхід `scopes` мутації `add` і її доступ до бази лише при поглинанні.
- Промоція (`docs/superpowers/specs/2026-10-06-promotion-design.md`) §9.2, рядок «RLS і предикат скоупу»: одне речення — після прийому з нуля предикат скоупу повертає в модель `add` виду скоупу з поглинанням за вмістом, не промоція.

## Глобальні обмеження

- Без поступок сумісності (рішення власника 2026-11-18): старого шляху тесту (`refusedRoundTrip` для цього кейсу) не лишати.
- `simetra/model` — лише `zod`; новий вхід — Zod-схема в `compiler/operations/inputs.ts`, тип через `z.infer`.
- Повідомлення діагностик і опис інструмента — англійською; коментарі — українською, «чому».
- Ослаблення оракула чи очікування тесту — розвилка архітекторці.

Задача 0 перевіряє, що `simetra.current_user_id()` є в базі `postgres` без довідника «Користувачі» (установка платформи); ні — розвилка. | немає |
| Р7 | Прийнятий корінь зовнішнього виду (`user`, `auth.users`) не має таблиць у фікстурі: другий `add` поглинає лише гранти `user_ids`. Порядок викликів у тесті: `org` (з `scopes` для кожної таблиці), потім `user` (без `scopes`). | немає |

## Інтерфейси

- **Дає:** вхід `scopes` мутації `add` (схема в `inputs.ts`); поле `absorbed: string[]` (ідентичності одиниць) у результаті операції `add`; поведінка `addTool` з суддею. Споживачі — Д4 (`declare-function` повторює правило кандидатів, якщо його мутація теж зіткнеться з дублями), CLI/MCP.
- **Бере:** `folderReference`, `reverseGenerate` (`simetra/schema`, #286); `toPlatformForms` і режим `repair` (Д1); `sql.generated-grant` (Д1) як відмова для зайвого гранту.
