# План B1 М5c: доказ індексів таблиці перекладів під RLS

> **Статус:** план на приймання архітекторкою М5c. Блок — #402, спека — #410.
> Спільний ресурс — стенд `postgres` (один DB-слот М5c; перед прогоном рівня
> `db` — рядок архітекторкам `m4-sk-architect` і `tooling-architect`). Стенд не
> зупиняти й не перезапускати. Рівні `unit` і `db` CI запускає сам; локально —
> лише цільові форми нижче.

## 1. Мета, архітектура, спека

**Мета.** Довести на справжньому Postgres 17 стенду `postgres`, що спільні
індекси таблиці перекладів із провідною колонкою `language_id` є умовою індексу
(`Index Cond`) для префіксного пошуку й keyset-сторінки під формами політик, які
згенерує B3. Результат вирішує долю ADR-0112: `accepted` або запасний шлях.

**Архітектура.** Один DB-тест у `packages/simetra/test/db/` за зразком
`search-starts-with.db.test.ts`: компілює справжній домен прав (скоуплений
довідник із полем пошуку), розгортає його в транзакції, що відкочується
(`describeTransaction`), додає поруч рукописні таблицю мов і таблицю перекладів
тієї форми, яку дасть B3, засіває їх і читає `EXPLAIN (ANALYZE, FORMAT JSON)`
від ролі запиту через `queryAs` і `explain-plan.ts`. Компілятор, генератори й
код платформи блок не змінює.

**Спека.** [мультимовні дані](../specs/2026-11-24-multilingual-data-design.md)
§3 (рядок B1), §5.1, §5.3 («Таблиця перекладів», «Права»); ADR-0112
(фальсифікатор і запасний шлях); ADR-0097 (префіксна колонка, leakproof).

## 2. Глобальні обмеження

- Тест лишає стенд чистим: усе — в одній транзакції з відкатом; об'єкти, що не
  відкочуються (ролі, бази), не створюються.
- Наявні DB-тести лишаються зеленими; спільні допоміжні модулі
  (`connection.ts`, `explain-plan.ts`, `rights-seed.ts`, фікстури прав) лише
  використовуються, а якщо розширюються — без зміни поведінки для наявних
  викликачів.
- Засів — достатній, щоб планувальник обирав індекс за статистикою (порядок
  величини прецедентів: десятки тисяч рядків), і `ANALYZE` після засіву.

## 3. Рішення

| # | Рішення | Вплив на спеку |
| --- | --- | --- |
| Р-B1-1 | Таблиці мов і перекладів у тесті — рукописний SQL тієї форми, яку §5.2–§5.3 вимагають від B2/B3: «Мови» (`id`, `code`, `state`); переклади (`parent_id`, `language_id`, копія скоупу під тим самим ім'ям, що в шапці, мультимовна колонка, її префіксна колонка за ADR-0097, `source_hashes`), PK `(parent_id, language_id)`. | none |
| Р-B1-2 | Індекси — форма §5.1: keyset `(language_id, <скоуп>, <колонка>, parent_id)`, префікс `(language_id, <префікс> text_pattern_ops)`. Порядок колонок після `language_id` — той самий, що компілятор дає індексу `indexed` і пошуковому індексу шапки (`compiler/stages/model.ts`: скоуп першим, ключ рядка останнім). | none |
| Р-B1-3 | Чотири форми політики на таблиці перекладів, усі — з виразів, які компілятор уже згенерував для шапки того самого домену (`pg_policies` шапки), бо копії носіїв у перекладах мають ті самі імена колонок: **(а)** межа тенанта (`RESTRICTIVE`) + політика читання за правами — як у шапці; **(б)** та сама пара з політикою членства з підзапитом; **(в)** `<t>_public_read`: умова `publicRead` власника `AND language_id = ANY (ARRAY(SELECT id FROM <мови> WHERE state = 'published'))` для ролей гостя й користувача; **(г)** `OR` політик (в) і `<t>_edit_read` під роллю користувача. Для (г) предикат `<t>_edit_read` у B1 — вираз політики читання за правами шапки тієї самої форми (членство з підзапитом): B1 доводить форму плану, а не семантику права `update`, яку доводить B3. *На приймання архітекторки.* | none |
| Р-B1-4 | Якщо якась форма не дає `Index Cond` з `language_id`: виконавиця не латає тест і не змінює форму індексу сама — звітує архітекторці з планами `EXPLAIN`; архітекторка записує запасний шлях ADR-0112 у §5.1 і §5.3 спеки. | §5.1, §5.3 — лише за негативного результату |

## 4. Інтерфейси

Блок не дає інтерфейсів коду. Він дає факт для B3 (#404): форми індексів §5.1
підтверджено або замінено запасним шляхом ADR-0112.

## 5. Інваріанти безпеки

- Тест читає від справжніх ролей запиту (гість і користувач профілю
  `postgres`), а не від суперкористувача; кількість видимих рядків під кожною
  політикою дорівнює очікуваній за скоупом і станом мови. **Мутація:** політика
  (в) без фільтра мови — тест бачить рядки мови `draft` і червоніє.
- Перевірка умови індексу називає саме `language_id` і префікс чи межі keyset у
  `Index Cond` (не у `Filter`). **Мутація:** індекс без провідного `language_id`
  — перевірка червоніє.
